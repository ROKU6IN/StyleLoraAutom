# 0.59.0 本地功能收尾与综合验收

本轮完成了下列本地功能与本机验收（2026-10-29），不表示全部设计条目已完成。后续交叉审计确认仍有 F11/F14 本地尾项与标签索引/导出门禁待决问题，详见 [完成情况与范围审计](67-完成情况与范围审计.md)；此前“当前阶段全部完成”的结论据此更正。用户明确暂缓两项外部账户验收：NovelAI 真实生成与扣费、真实 LLM 供应商质量与费用。本轮没有调用真实生成或 LLM 服务，也没有初始化、提交或上传 Git。Launcher 直连替代路线沿用 0.52.0，不要求安装或修改 Aaalice。

## 产品默认配置

`GET/PATCH /api/config` 使用 schema_version=2，保留存储阈值，补齐默认费用策略、LLM 并发与超时、WD 默认选中状态、MCP 发现模式。界面入口为“界面设置 → 产品与界面设置”。PATCH 使用版本条件；草稿冲突保留输入，结果未知时先读取核对，不重复写入。

- `cost_policy` 默认 ask，只影响新建来源。选择 allow 需要 `confirm_allow=true`；已有来源保留其策略。CLI 创建草稿省略策略时读取并冻结产品默认值，默认 allow 仍须 `--confirm-allow`。
- `llm_limits.concurrency` 为 1–8，默认 2；`timeout_s` 为 5–600，默认 300。每次请求准入时读取限额，请求自己的更短超时继续有效。在途请求保持原限额，共用计数器，修改设置不替换正在使用的信号量。
- `wd_enabled` 默认 false，只决定新标注批次表单是否默认勾选 WD，不禁用显式 WD 任务。
- `mcp.discovery_mode` 默认 default；configured 只读取 `STYLELORA_LAUNCHER_APPDATA` 指定的绝对目录。未配置时明确报错；HTTP 不接收任意目录路径。

旧 schema_version=1 文件先校验原完整性封套，只在内存中迁移。GET 与无变化 PATCH 不重写旧文件；第一次实际修改原子保存 v2。

## 独立 CLI 写入与控制

新增前台 `stylelora session`，持有一个产品锁和自有 Runtime。它在同一进程中接受预览、人工确认、提交、查询和控制；复用原 CLI、ASGI 路由、幂等键、项目 lease 与后台执行器。

```powershell
./scripts/run.ps1 session --project "E:\datasets\example.slproj"
```

终端保持运行，逐行输入 JSON。每条 `argv` 是参数数组，不执行 shell。`$project_id` 是当前会话项目占位符：

```json
{"argv":["import","preview","E:\\inputs","--project-id","$project_id"],"save_plan":"E:\\plans\\import.json"}
```

核对返回的计划后，在**同一个会话**输入真实 confirmation_digest：

```json
{"argv":["import","run","--preview","E:\\plans\\import.json","--confirm-digest","替换为核对后的64位摘要"]}
{"argv":["source","list"]}
{"exit":true}
```

支持 source、job、import、export、prompt、storage 的既有命令及控制操作；prompt 不要求打开项目。`save_plan` 只用于 preview，独占创建文件，已有文件不覆盖。输出为 ready/command/closed NDJSON 事件，业务结果位于 result；进度写 stderr，不输出 Token。

EOF、退出命令或 Ctrl+C 排空并关闭自有工作；不保留后台服务、端口或控制管道，不接受 detach 或切换到其它实例。旧会话计划不能改绑新会话；重开后用持久任务/来源/导出编号查询，重新预览尚未提交的工作。这是 §9 独立容器的交互会话实现，没有承诺跨进程重用授权或新增通用持久请求账本。0.58.0 的单命令独立查询仍保留。

## 中断导出人工处置

导出页新增“中断导出恢复”，用户明确点击才扫描。API 为项目 exports/recovery/scan、actions、history。后台扫描与动作均持有项目文件操作锁。

完整复制导出只有在状态、报告、项目身份、数据库图片身份、所有产物大小和 SHA-256 一致且无额外文件时才可发布到原目标；目标已存在、文件变化或硬链接产物拒绝发布。不会补写缺少的报告、重建标注或重新生成图片。

证据不足可选择归档：先写完整性处置记录，再将整个目录移动至 `exports/.archived/<decision_id>`，保留所有文件，不删除。界面要求核对勾选和长按。动作绑定预览摘要及版本，重复同请求返回原动作；移动确认丢失时用目录身份读回。未知结果阻止新提交，需重新检查。处置记录在 `exports/.recovery/`，重开后可读取。

归档是保留现场的人工处置，不表示不完整导出自动续传成功；可从记录给出的归档位置取回文件，需要完整数据集时重新正常导出。损坏记录保留并返回明确错误。

## NSFW 精修模板与路由

新增固定摘要模板 R0-routing-v2、R1-nsfw；新任务冻结 composer-v2 与 R0-routing-v2/R1-sfw/R1-nsfw/R5。旧 composer-v1 任务仍使用原模板，重开不会更换合同。

R1-nsfw 沿用 R1 输出 schema、标签集合对账、排序、围栏、自然语言开关和图幅校验，只按提供内容精修，不凭空添加人物、年龄、行为或风格词。SFW 拒绝时允许在评级升级与围栏复查后切换一次 NSFW 角色；共用原修复预算。缺少角色明确跳过，上游再次拒绝则停止，不无限回退。三种协议使用模拟服务验证结构与路由；不据此宣称真实供应商输出质量通过。

`scripts/accept_local_scale.py` 显式创建临时夹具，使用生产 HTTP 应用完成导入、列表、缩略图、导出和存储扫描。数据为 10000 张不同的 512×384 JPEG 与同名 TXT，合计 54995941 字节；图像为合成素材。Windows 11、Python 3.12.14，本机实测：

| 项目 | 结果 |
| --- | ---: |
| 导入预览 | 27.5074 秒 |
| 全量导入 | 470.5083 秒，10000 张 |
| 列表每页 1000 张，10 页 P95 | 0.6190 秒 |
| 200 张冷缩略图 P95 | 36.55 毫秒 |

验收发现并修复了导入 sidecar 匹配重复遍历整个目录的问题：操作内目录索引按目录身份与修改时间刷新，逐文件路径校验和内容摘要仍执行；新增/删除/改写 sidecar 的回归覆盖保留。状态读取使用轻量 SQL，不反复解码整个导入清单。优化前同规模预览为 351.2769 秒，优化后约降低 92%。

这组数据用于容量和响应性验收，不能外推为任意分辨率/磁盘/机器的性能保证。报告 `.test-tmp/completion-scale.json`，日志 `.test-tmp/completion-scale.log`。脚本保留夹具供浏览器复验，不清理用户目录。
