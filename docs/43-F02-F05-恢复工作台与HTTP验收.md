# F02–F05 恢复工作台与 HTTP 验收

日期：2026-10-28；版本：0.36.0。本阶段继续本地开发，不提交或上传 Git。恢复闭环使用合成适配器验证，没有真实生成、扣费或 Launcher 设置写入。

## 实现范围

在 0.35.0 内部恢复核心之上，增加项目生成源范围的恢复证据查询、只读对账和显式设置恢复。页面位于“来源与导入”中已保存生成源的“生成恢复与对账”面板；Launcher 诊断页提示项目内入口。

生产 Runtime 仍不注册生成适配器，兼容清单仍为空。因此页面可以读取本地历史，但真实对账和恢复动作保持禁用。测试适配器仅存在于测试模块，并由专属浏览器测试进程显式开启。

## HTTP 合同

以 `P=/api/projects/{project_id}/sources/{source_id}` 表示当前项目生成源：

| 方法与路径 | 行为 |
|---|---|
| GET `P/recovery` | 本地条目分页，默认 50、上限 1000；可按 pending/sent/done/failed 筛选；返回 total、签名游标与逐项恢复状态 |
| GET `P/recovery/{item_id}` | 按编号查询该来源的条目，返回恢复版本与可执行动作 |
| POST `P/recovery` | item_id、action=reconcile/restore、confirm_restore；If-Match 使用该条目的恢复版本，必须有 Idempotency-Key；返回 202 Accepted、Location 与后台 Operation |

reconcile 不接受恢复确认；restore 要求严格布尔值 confirm_restore=true。GET 不连接后端，不创建、修复或清除文件。列出没有操作记录的普通条目，是为了区分“尚未提交”和“缺少可信证据”；不能把前者的界面描述当作远端未执行证明。

游标绑定项目句柄代次、来源和筛选条件，不能跨范围重用。分页固定 upper_id，但不同页不是整个目录的冻结快照；每项动作都重新检查最新证据。总数是当前筛选下的数据库条目数，不表示全项目待恢复项数。条目属于其他来源、失效项目句柄、非法分页、重复 status、额外请求字段与未知 action 均拒绝。

这三个来源接口细化早期 F11 A046/A047 的生成恢复部分；既有项目级 GET recovery 的打开时摘要保持兼容。没有把孤立文件清理、缺失文件修复或批量接管一起开放。

## 证据与动作门禁

恢复版本为会话 HMAC，绑定来源、条目、attempt、操作记录、设置日志、必要的费用凭据和适配器身份。原始提示词、路径、后端指纹、操作关联键、租约标识与设置原值/目标值不返回给浏览器。

只有操作记录与当前设置租约、来源、请求/配置摘要、后端实例/契约相符，才可考虑执行动作。缺少或损坏的记录、当前后端变化、另一个操作在途、来源仍 running 都会阻止恢复。sent 缺少操作记录不产生“强制继续”或“判定失败”入口。

未结清操作只允许 reconcile。已结清但设置尚未恢复时才允许 restore；若此前恢复写入响应丢失，日志为 restoring，必须先只读核查，不允许再次写入。外部设置修改仍由 F03 的原子条件写及冲突校验保护；页面没有覆盖冲突或删除恢复日志按钮。

仅有 F03 设置日志、没有对应条目操作记录的情况（例如 apply 阶段即中断）仍保持诊断状态，不猜测项目归属或创建关联。其专门恢复流程留待后续设计与真实适配验证。

## 后台生命周期与重放

恢复任务通过 Supervisor 执行，并占用 SerialDriver 的全局单执行槽位。接收请求后先保留恢复预约；任务真正开始时在同一控制锁下重新校验版本、项目状态和动作门禁，再取得执行槽位。排队期间的文件修改、来源变更、后端替换会使任务失败，远端调用尚未发生。

任务不在 HTTP 内等待完成。来源生成与恢复共用同一槽位；恢复预约也阻止重复恢复入队。项目引用保留到操作和最终通知结束，关闭项目只会取消尚未开始的任务，已经开始的核查/有条件恢复会排空后释放项目。面板关闭或请求断连不会取消已经受理的动作。

同会话同请求键返回原 Operation，不重复核查或写设置。进程重启后的旧请求键没有跨会话重放承诺，必须先重新读取证据。恢复本身不会 submit、增加 attempt、取得费用同意或自动继续来源。Operation 返回错误只包含脱敏原因码。

## 界面交互

面板每页 20 条，支持状态筛选、前后页与按条目编号查询；轮询只读取本地状态。没有条目、没有操作记录、需要对账、需要恢复、已结清和证据受阻分别显示。草稿未保存、离线或已有操作处理中时禁止提交新动作。

只读对账由明确点击触发。恢复设置须核对条目和尝试次数、勾选并长按一秒；弹窗持续读取当前证据，版本变化或读取失败时禁用确认。后台任务持续轮询，完成后使项目数据失效并重新读取；任务进度入口可查看既有操作。

提交结果未知时，面板保留错误并禁止继续提交，提示先核对任务记录，再重新打开面板读取证据。刷新本地证据不会自动重放未知请求。没有把实际恢复成功和“请求已受理”混为同一个结果。
