# F11 项目管理 CLI 验收

日期：2026-10-28；版本：0.43.0。只在本地开发，不初始化、提交或上传 Git，不调用真实生成服务。

## 本轮范围

接续 0.42.0 doctor 阶段，实现 F11 §9 的项目管理命令。附着模式通过当前用户 ACL 管道取得会话凭据，再调用现有项目 HTTP 服务；路径只提交到管道换取 grant，不把任意文件路径加入 HTTP。复用既有 ProjectService 生命周期、后台 Operation、版本与会话请求去重。

```powershell
# 终端一：持续运行本地服务
./scripts/run.ps1 serve --no-browser
# 终端二：创建后保持打开
./scripts/run.ps1 project init "E:\datasets\example.slproj" --name "样例" --trigger "example_style"
./scripts/run.ps1 project status --json
./scripts/run.ps1 project close
./scripts/run.ps1 project open "E:\datasets\example.slproj" --detach
./scripts/run.ps1 project status --operation-id <operation_id> --wait
# 无服务时：独立创建，退出前关闭
./scripts/run.ps1 project init "E:\datasets\offline.slproj" --name "离线项目" --standalone
```

新命令组不替换早期 init/info/import/edit/export 等兼容命令。只实现本轮项目管理范围，不声明全部 F11 CLI 完成。

## 命令语义

| 命令 | 行为 |
|---|---|
| project init PATH --name NAME --trigger WORD? | 授权 project_create，POST /api/projects。已存在目录不覆盖；服务已打开其它项目时任务失败，不自动关闭当前项目。成功后在服务中保持打开 |
| project open PATH | 授权 project_open，POST /api/projects/open。明确切换：旧项目按既有生命周期排空并关闭；打开同一路径保留句柄。返回新 project_id/metadata/version。后续打开失败时可能已关闭旧项目，不承诺跨项目切换原子性 |
| project close | 先 GET current 捕获 project_id/version，再携带 If-Match 提交关闭。可用 --project-id 限定目标。句柄或版本变化即冲突，不重新读取并强行关闭；后台排空完成后返回 closed=true |
| project status | 仅 GET current，返回 project 或 null，不扫描磁盘、不自动打开项目。关闭排空期间 current 为 null，只表示无可用当前句柄；是否关闭完成应查询对应 Operation |
| project status --operation-id ID | 只读项目 create/open/close Operation；非项目任务被拒绝。默认读取一次，--wait 轮询至终态。不存在/过期的任务沿用 session:expired |
| project init PATH ... --standalone | 显式持 CurrentUser 产品锁，复用与 HTTP create 相同的 F01 create_project/close_project 服务，内部持项目 OS 锁。创建后立即安全关闭，无服务、管道、HTTP、浏览器或最近项目记录写入。已有服务持产品锁则退出 4，不转为附着执行 |

附着模式不直接连接 SQLite，也不创建第二个 Runtime。无服务统一退出 3，由用户显式启动 serve；没有自动拉起后台进程或完整独立服务容器。独立创建不能 detach、不能复用会话 grant/instance/request key；不覆盖已有容器。成功必须创建和关闭均完成；创建后关闭失败返回 outcome=unknown 和 cli.created=true，提醒核对磁盘结果，不重复创建。

创建/打开/关闭默认 --wait，也可 --detach 在服务受理后返回 status=accepted 与任务编号。JSON stdout 始终是单个对象，--json 可省略；进度写 stderr。Ctrl+C 只结束客户端等待，退出 130；已经受理的附着任务仍归服务所有，不发送取消、暂停或关闭服务请求。独立创建是同步上下文，正常退出/异常栈展开会释放锁，不声称中断后的创建结果一定未发生。

## 响应丢失与会话边界

每次写入在发送前记录 `cli.request`：method、path、body、idempotency_key，关闭另含 if_match；同时记录 instance_id、grant_id 或 project_id。受理后记录 operation_id/status_url。输出不包含 Bearer token、管道秘密或绝对项目路径；项目名称/触发词作为请求内容和正常元数据可见。

网络超时、非 JSON/重定向响应、无效受理内容按未知写入处理，不自动重发 POST，不跟随 Location。轮询只读取固定本机 `/api/operations/{id}`，不信任任意返回 URL。轮询中断或失败保留已受理任务编号。

已得到任务编号时先查询：

```powershell
./scripts/run.ps1 project status --operation-id <operation_id> --instance-id <original_instance_id> --wait
```

若 POST 已发送但未得到任务编号，只能在同一个运行会话内使用原请求身份重放；名称、触发词等 body 内容必须与原请求完全相同。以下是手动核对后的重放方式，不是新的创建/关闭步骤：

```powershell
./scripts/run.ps1 project init --grant-id <original_grant_id> --name "原名称" --trigger "原触发词" --instance-id <original_instance_id> --idempotency-key <original_key>
./scripts/run.ps1 project open --grant-id <original_grant_id> --instance-id <original_instance_id> --idempotency-key <original_key>
./scripts/run.ps1 project close --project-id <original_project_id> --if-match <original_unquoted_version> --instance-id <original_instance_id> --idempotency-key <original_key>
```

grant 重放要求原 instance_id 与请求键；close 指定请求键时必须提供原项目、实例和版本，不会重新捕获当前项目。原 close 已成功且后来另一个项目已打开时，返回原 Operation，保持新项目打开。原 init 已成功而路径已存在、grant 已失效时，只要当前会话的请求收据仍可用，返回原 Operation；相同请求键配不同 body 返回冲突。收据或会话已过期时需人工核对当前状态，不能以新 key 当成安全重试。

`--instance-id` 在 hello 后、任何 HTTP/路径授权前比对；路径 grant 请求也携带该实例编号，管道在授权前再次校验，阻止 hello 与 grant 之间重启时跨会话授权。旧客户端可省略新增管道字段，保持兼容。服务重启后 old instance/grant/project/operation 都不能作为新会话重放凭据。

## 退出码

| 码 | 本轮含义 |
|---|---|
| 0 | 操作完成，或 --detach 已明确受理；当前状态查询成功，即使 project=null |
| 2 | 参数、路径或请求预检不合法，查询了非项目任务等 |
| 3 | 无运行实例、认证/授权被拒绝 |
| 4 | 项目/产品锁、版本/状态/会话冲突，原任务或句柄已过期 |
| 5 | 依赖、I/O、轮询失败或无效查询响应；可能保留已受理任务，需要继续核对 |
| 7 | 写入结果未知，或一次状态查询发现 pending/running/canceled/interrupted；不冒充完成 |
| 130 | 客户端中断，保留已知任务/请求身份 |
