# 最近项目与跨项目存储验收

日期：2026-10-28；版本：0.38.0。仅本地开发，无 Git 提交、上传或发布。测试使用临时项目和本机测试服务。

## 实现范围

接续 0.37.0，完成 F11 的 A039 最近项目列表、A041 已知项目重开、A118/A119 跨项目存储扫描，以及 F14 首页和存储页入口。项目数据库无 DDL 变化。

成功创建或打开项目后登记最近位置；查询列表本身不打开项目。正常启动时记录保存在产品配置目录的 `known-projects.json`，受产品进程单实例锁保护。测试可以注入独立配置目录或内存记录。最多 200 条、2 MiB；超出条数只淘汰最早记录，不删除项目或文件。

持久 `known_id` 与临时 `project_id` 分离：关掉重开会获得新句柄，持久编号保持；同一仍在打开的项目沿用原句柄。记录包含目录设备/文件编号和项目创建标记，按规范化绝对路径去重。元数据改名同步到历史但不改变打开顺序。HTTP、SSE 和页面仅返回名称、目录 basename 和状态，不公开绝对路径。

历史文件有版本和内容摘要，严格验证、原子替换，替换后响应丢失会只读核对。损坏文件保留，不静默覆盖；历史写失败不会把已成功打开的项目伪装成失败，返回 `recent_warning`，首页提示。历史文件不是防本机用户篡改的安全凭据；Windows 当前用户权限与进程单实例边界沿用原设计。

## 接口合同

| 接口 | 行为 |
|---|---|
| GET /api/projects | 分页最近项目，含 known_id、basename、last_opened_at、status/reason、当前 project_id（否则 null） |
| POST /api/projects/open | grant_id 与 known_id 必须且只能给一个；返回 202 Operation |
| POST /api/storage/scans | `{}` 扫描全部已知项目；或非空且不重复的 known_ids（最多 200）；202 Operation |
| GET /api/storage/scans/{scan_id} | scan_id 等于 Operation 编号；读取冻结统计，分页和排序 |

POST 沿用鉴权与 Idempotency-Key，不接受原始路径或额外字段。最近项目游标绑定记录版本，重开或更名后旧游标失效；扫描游标绑定 scan_id 和排序。错配沿用 `422 page:invalid_cursor`；结果过期返回 `410 session:expired`。排序支持 `-total_bytes,known_id` 与 `known_id`；不可访问项在大小排序末尾。

目录移走、被替换、包含符号链接/junction/reparse point、结构损坏、权限失败或锁被占用会给出原因。已知位置开启动作在受理和后台执行时复查；排队期间被替换会在关闭当前项目之前拒绝。更换了目录的项目须经原生选择器重新授权，登记新 known_id，旧编号失效。

## 跨项目扫描边界

- 只扫描提交时冻结的已知项目记录，不遍历磁盘发现项目。扫描单次至多一个；结果最多保留 3 次、15 分钟，重启即失效，最近项目记录仍持久。
- 当前项目持引用，关闭等待读取释放。未打开项目只读打开既有 `.project.lock` 并持共享锁；不创建锁文件、不调用第二个数据库 writer、不迁移、不恢复项目。Windows 锁冲突行为有真实文件锁测试。
- 与当前项目扫描共用文件盘点逻辑，跳过链接，单项目最多 50000 个目录项，目录遍历和每 256 项复查取消与根身份。扫描期间删除/变化可能产生 partial；统计是逐项观察结果，不承诺跨文件系统事务快照。
- `total_bytes=null` 表示不可访问，绝不伪造成零；`observed_total_bytes` 仅累计已读部分。返回 scanned_count、unavailable_count、partial、as_of 和每项目最多 20 条错误。逻辑长度按目录项累计，硬链接可能重复计数，不表示分配簇或可释放空间。
- 单项目提醒阈值固定 20 GiB，总量固定 100 GiB；达到提醒只显示提示，不触发删除或联网。界面允许全量或跨页勾选；提交后冻结选择，可取消，不发布截断成功结果。
- 扫描是产品级 Operation，不因切换项目丢失查询资格；退出程序仍遵循任务停止流程。GET 不自动触发扫描，未知 POST 结果不自动重发，页面引导核对任务记录。
