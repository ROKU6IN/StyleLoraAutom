## 本轮范围

接续 0.46.0 来源 CLI，实现 `import preview/run/status/summary`。CLI 使用当前用户 ACL 管道授权输入目录，通过已有 Import HTTP API 完成预览、审核提交、后台等待与持久汇总。扩展 `source pause/resume/cancel` 支持 import 来源，新增 `source import-root` 验证并绑定输入目录。

来源创建由 import run 的已有服务流程完成，仍不提供任意 import 配置直接写入 sources 的入口。该流程是对 F11 §9 原 import ROOT 的两阶段细化：先核查解析结果与阻断项，再以保存的计划和确认摘要提交。没有修改 HTTP 路由、导入状态机或项目 DDL；项目格式仍为 1。

## 命令和基本流程

先持续运行 `./scripts/run.ps1 serve --no-browser`，用 project open 打开目标项目，project status 获取当前 project_id。新导入命令仅附着已有实例，不自动拉起服务、切换项目或使用通用独立容器。

```powershell
./scripts/run.ps1 import --help
./scripts/run.ps1 project status
./scripts/run.ps1 api GET /api/projects/<project_id>/import-schemes
```

preview 可指定 --scheme 正整数编号；省略时使用项目默认导入方案。--options 接受严格 ImportOptionsInput JSON，支持 encoding、parser、recursive、max_image_bytes、max_pixels、max_sidecar_bytes、max_files；不接受秘密、根路径或未知字段。只传明确设置的字段，其余从方案继承。例如 options.json：

```json
{"encoding": "auto", "recursive": true}
```

auto 沿用已实现的严格 UTF-8 优先、失败后 GBK 策略；损坏 UTF-8 BOM 不会被当作 GBK 掩盖。使用 catalog-comma-v1 仍要求现有本地目录资料。完整格式、边界和冻结方式沿用已有方案服务。

```powershell
$lines = ./scripts/run.ps1 import preview .\input-images --project-id <project_id> --name "本地图片" --options .\options.json
$previewExit = $LASTEXITCODE
if ($previewExit -notin @(0, 6)) { throw '预览失败，请查看返回错误' }
$text = $lines -join [Environment]::NewLine
[IO.File]::WriteAllText((Join-Path (Get-Location) 'import-plan.json'), $text, [Text.UTF8Encoding]::new($false))
$preview = $text | ConvertFrom-Json
$preview.plan.preview | ConvertTo-Json -Depth 30
$preview.confirmation_digest
```

preview 默认等待后台扫描完成；不创建来源、不复制图片、不修改输入文件。检查 selected、manifest、diagnostics、options、blocking_errors、can_import、encoding_fallback_count 及 catalog_revision。can_import=false 时退出 6，保留诊断计划，run 不接受这份阻断计划。逐条诊断样本上限 100；服务仍验证完整清单。

```powershell
./scripts/run.ps1 import run --preview .\import-plan.json --confirm-digest <confirmation_digest> --detach
./scripts/run.ps1 import status <operation_id> --project-id <project_id> --wait
./scripts/run.ps1 import summary <source_id> --project-id <project_id>
./scripts/run.ps1 source status <source_id> --project-id <project_id>
./scripts/run.ps1 source items <source_id> --project-id <project_id> --limit 50
```

run 默认 --wait；--detach 返回 status=accepted 和 operation_id/status_url，表示受理。等待完成保留完整 operation 对象，导入报告在 result 中：source_id、status、selected、imported、skipped、failed、pending、unresolved、items 和 warnings。操作 status=done 不等于来源完整成功，CLI 还检查 result 中的来源状态与计数。存在失败项退出 6，仍有 pending/sent 或暂停时退出 7。

已有图片按原有哈希规则跳过，summary 返回持久来源内容和重复结果。它不重新扫描输入目录；重启后仍可读取编码证据、原始导入结果和条目状态。summary 可在部分失败时返回 6、尚未完成时返回 7，脚本应保留 JSON 并检查退出码。

## 附着、计划和请求恢复

目录绝对路径只通过当前用户管道发送，HTTP 使用 import_root grant_id。授权请求同时绑定当前 instance_id 和 project_id；CLI 验证 grant 的用途和项目身份，服务继续检查目录身份、路径安全、期限和租约。预览与运行不会将输入绝对路径写入请求收据；返回的文件清单是相对路径。

计划 schema_version=1 包含 instance_id、project_id、idempotency_key、ImportStart body（preview_id/digest/name）和完整 preview。SHA-256 confirmation_digest 覆盖计划。run 在附着前检查结构、请求与预览引用的一致性、确认摘要和严格输入类型；同一实例/项目的服务仍重新校验预览期限、方案摘要和输入清单。确认摘要是本地一致性检查，不是服务签名。

options 和计划文件要求严格 UTF-8（允许 BOM），上限 16 MiB；拒绝重复键、非有限数字及未知字段。成功预览的完整格式化输出也检查同一上限；超大返回 import:plan_too_large，不输出不可重读的成功计划。

提交前 cli.request 记录 method/path/body/idempotency_key，受理后记录 operation_id/status_url。超时、重定向、错误的受理身份或无效受理响应均按结果未知处理，退出 7，不自动重发。Ctrl+C 退出 130，仅停止等待，不隐式暂停/取消后台导入；使用记录的操作编号查询即可。

同一 run 计划明确重放会使用原请求键与请求体，服务返回原后台操作，不另建来源、不重新扫描或自动恢复。请求已因输入变化而失败时，重放仍返回原失败，调整文件后需要重新预览。服务会话收据不能跨实例当作持久创建凭证；CLI 拒绝重启后运行旧计划。

预览请求响应丢失或等待中断时，已取得的 grant 与请求键都保留。可明确恢复原预览操作，保持相同 --scheme/--options：

```powershell
./scripts/run.ps1 import preview --grant-id <original_grant_id> --instance-id <original_instance_id> --idempotency-key <original_key> --project-id <original_project_id> --name "本地图片"
```

提供 --grant-id 或请求键必须同时提供原实例与原键，并省略 ROOT，避免重放时重新授权而改变请求。--name 是 CLI 计划中审核的来源名称，不属于扫描请求；需要与计划一起审核。import status 可查看四类导入操作：import.preview、import.run、import.resume、import.verify_root；会校验项目、操作编号、类型及结果结构，不能用此命令查看任意产品/导出操作。

## 暂停、恢复与目录重新授权

```powershell
./scripts/run.ps1 source pause <source_id> --project-id <project_id>
./scripts/run.ps1 source resume <source_id> --project-id <project_id> --detach
./scripts/run.ps1 source cancel <source_id> --project-id <project_id>
./scripts/run.ps1 source import-root <source_id> .\input-images --project-id <project_id>
```

source 的控制先 GET 当前来源，使用捕获的 If-Match 提交。nai 继续使用原来源响应；import resume 返回后台操作并默认等待，--detach 明确返回受理状态。pause/cancel 沿用已有来源状态与在途处理语义；暂停成功不表示后台复制线程已退出，立即恢复可能返回 source:in_flight，应先查询原操作。已取消来源不能 resume。

导入恢复使用冻结的清单、方案和目录资料，不能用新的 options 替换内容。done 来源 resume 沿用服务的现有 no-op 报告语义，不重试 failed 条目；失败项专用重试仍未实现。

服务重启后，operation 和目录 grant 不保留，持久 source 与 summary 保留。重新打开原项目后，使用新的 project_id 查询 summary/source 状态；需要恢复时先明确 import-root。该命令后台核验全部冻结输入，成功后才以 CAS 绑定新 grant 并更新来源版本；不创建来源、不复制图片、不自动 resume。路径对应的图片/文本变化、目录资料缺失或版本变化会拒绝/失败，不能覆盖原绑定。导入目录必须仍能满足完整冻结清单，不能只提供未完成项。

import-root 支持 --wait（默认）/--detach；核验结果为 result.source_id 和 result.verified。响应未知时可用原 grant、实例、版本、请求键明确重放：

```powershell
./scripts/run.ps1 source import-root <source_id> --project-id <original_project_id> --grant-id <original_grant_id> --instance-id <original_instance_id> --if-match <original_version> --idempotency-key <original_key>
```

来源控制的显式重放也要求原 instance_id/if-match/idempotency-key，始终提交原版本，不用新 GET 覆盖。服务缓存的重放响应表示原请求结果；最新状态应另外读取。重新验证目录会改变来源版本，恢复时使用新的版本或默认读取当前版本。

## 兼容性与退出码

保留旧 `import PROJECT ROOT [旧选项]` 离线入口及原退出码，已有图片编辑/导出 CLI 回归继续运行。`import preview/run/status/summary` 和 `import --help` 进入新服务入口。旧相对项目目录若恰名为 preview/run/status/summary，请使用绝对路径或 `./preview` 等显式路径避免子命令歧义。服务入口与旧直接打开项目的入口不可同时占用同一项目锁。

以下仅为新入口的退出语义；stdout 一个 JSON，--json 可省略，进度写 stderr，不输出 Bearer token、原始异常或输入目录绝对路径：

| 码 | 含义 |
|---|---|
| 0 | 预览可提交；受理 --detach；导入完整结束；目录验证成功 |
| 2 | 参数、options、计划文件不合法/过大，或来源类型错误 |
| 3 | 无运行实例或认证不可用 |
| 4 | 实例/项目/版本/状态/预览冲突、会话或 grant 过期、阻断计划；后台已识别的版本/状态冲突 |
| 5 | 依赖/I/O/查询或后台操作失败；无效查询结果（保留已受理操作身份） |
| 6 | 预览含阻断项；来源 done 但有失败项 |
| 7 | 尚在运行、暂停/取消/中断、仍有未完成项、验证未完成或结果未知 |
| 130 | 客户端中断，后台工作继续 |

后台错误保留服务 error.code/outcome，不猜测不可得的 HTTP 状态；未单独识别的后台失败返回 5。读取失败不抹去已记录的操作身份；应查询原 operation/source，不能因为客户端读失败就新建任务。
