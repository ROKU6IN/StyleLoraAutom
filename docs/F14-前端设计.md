### 1.2 取舍说明

- 不选整套 UI 库（Ant Design、MUI 等）：它们自带视觉，与「`ui/` 层可整体替换外观」和「审图高密度」冲突。Radix 只提供行为与 ARIA，视觉全在本项目 `ui/` 层。
- 请求层自写薄封装 `api/client.ts`，不引 axios：注入 Bearer、解析错误信封、`If-Match`/ETag 往返、`AbortSignal` 透传、按 `retry_action` 统一分流。
- SSE：事件通道需要 Bearer，浏览器原生 `EventSource` 不能设请求头，所以用 `fetch` + `ReadableStream` 自解析（约百行，`events/sseClient.ts`），手动带 `Last-Event-ID`。见 Q31。
- 路由用 hash 模式：后端托管静态文件时无需 history fallback，token 与路径不混（见 Q30）。
- 虚拟化：网格是「按行虚拟化 + 每行 N 列」，N 由容器宽度与格宽计算；`@tanstack/react-virtual` 只管行，列在行内渲染。
- 图标：不绑定图标库。图标是 `ui/icons/svg/*.svg` 资源文件，`iconRegistry.ts` 用 `import.meta.glob(..., {query:'?url'})` 建名称→URL 注册表，`<Icon name>` 以 CSS `mask-image` + `currentColor` 渲染，组件内没有 SVG 字面量，也不用 `innerHTML`。限制：图标为单色；多色插画走 `<Illustration>` 槽位（`<img>`）。
- 安装核验：使用 TypeScript 5.9.3 解决 OpenAPI 生成器的 peer 冲突；其余本阶段使用的依赖按表固定，完整解析结果记录在 `web/package-lock.json`。未使用的 Radix 组件和 MSW 按后续功能需要引入。本机 npm 10.9.8 曾在依赖解析内部报错，使用项目缓存中的 npm 12.2.1 完成安装，未改全局 npm。

### 1.3 状态分层规则

| 类别 | 放哪 | 例 |
|---|---|---|
| 服务端数据（权威在后端） | react-query | 图片页、标注视图、源、任务、配置 |
| 实时事件 | `events/` 模块把 SSE 翻译成 `invalidateQueries` 或 `setQueryData`，不另存一份 | `image.updated` → 失效可见页 |

## 3. 数据清洗工作台（核心）

### 3.1 布局与密度

三栏可拖拽调宽，宽度与折叠状态存偏好：

```
┌ 工具条：筛选 chips ｜ 排序 ｜ 密度 ｜ 背景 ｜ 选择计数 ｜ 执行器 ▾ ｜ 批量规则 ┐
├ 图片网格（虚拟滚动）            ┬ 详情面板（选中图）                        ┤
│                                 │ 预览 / 标签层 / NL / 合并预览             │
├ 状态条：已加载/总数 ｜ 后台任务 ｜ 连接状态 ｜ 快捷键提示                    ┘
```

- 默认落点，进入即可审图，不经过概览页。
- 窄屏（<1100px）详情面板改为抽屉，网格优先。
- 三种布局密度（紧凑/标准/宽松）只改格宽与元信息显隐，由令牌 `--grid-cell-min` 驱动（§7），不改交互。

### 3.2 图片网格

**虚拟化**：按行虚拟化，行内 N 列。N = floor(容器宽 / (格宽 + 间距))，用 `ResizeObserver` 更新，只在 N 变化时重算行数。`overscan` 取 3 行；`rangeExtractor` 总是包含焦点图所在行，防止键盘移动时焦点节点被卸载。格高固定（由密度决定），不测量，避免滚动抖动。

**数据加载**：游标分页 `useInfiniteQuery`，页大小 200（API 允许 1..1000）。滚动到距末尾 3 屏时预取下一页。总数来自统计接口而不是页累加（API 说明 total 不是精确快照），状态条显示「已加载 N / 约 M」。跳到任意位置不做，上千张用滚动 + 筛选足够；v1 再评估基于 id 的跳转。

**格内容**（均为 `ImageCell` 的结构槽位，视觉在 `ui/`）：缩略图、选中框、review_status 角标（未审/保留/剔除）、rating 小标、标注状态点（WD/LLM 是否有结果、文件缺失）、焦点环。紧凑密度只留缩略图+角标。缩略图用 `loading="lazy"` + `decoding="async"`，URL 带版本参数以便失效；未加载时占位走 `<Skeleton>` 槽位。缩略图 404（file_missing）显示 `<ImageMissing>` 槽位，仍可选中和审图。

**筛选**（工具条 chips，同字段 OR、字段间 AND，写入 URL）：

| 维度 | 取值 | 说明 |
|---|---|---|
| 数据源 | 多选源 | 默认全部 |
| review_status | 未审 / 保留 / 剔除（多选） | 工作台默认**显示全部**，与导出默认「保留+未审」不同；chips 旁提示导出范围 |
| rating | general / sensitive / questionable / explicit / 未分级 | |
| 打标状态 | WD：无/有；LLM：无/有；文件缺失 | 与「执行未覆盖」的覆盖口径一致 |
| 文本 q | 标签名 | 仅名称/标签搜索，非正则；300ms 防抖 |

筛选变化时重置游标与滚动位置，选择集**保留**（不因筛选清空），状态条显示「已选 K（其中 J 在当前筛选外）」。

**排序**：`id` 升/降，其余仅在后端能力声明时出现（Q33）。

### 3.3 选择与焦点

- 两个概念分开：焦点图（键盘光标，唯一，驱动详情面板）和选择集（可多，驱动批量操作）。
- 选择集存 `Set<image_id>`（zustand），格组件用选择器订阅自身是否被选，选择变化只重渲染变化的格。
- 点击：设焦点；Ctrl/Cmd+点击：切换选中；Shift+点击：从锚点到当前的范围选（范围按网格顺序，跨未加载页时只选已加载部分并提示）；框选（拖拽矩形）v1。
- 「全选当前筛选」：不把浏览器已加载页当全集。选择集以**筛选条件**表示（`{kind:'filter', query}`）+ 例外集（取消勾选的 id），执行批量动作时交给后端按 Scope 物化。工具条显示「已选约 M（含筛选全集）」。选择集提供 `kind:'ids'` 与 `kind:'filter'` 两种形态，对齐 API 的 Scope 二选一。
- 批量动作前若选择为 filter 形态且数量大（>500），确认框显示数量与筛选摘要。

### 3.4 详情面板（焦点图）

数据来源：一次「标注视图」读取，包含五层 current、各层 current ref、original 是否存在、WD 与 original 的重合及置信度、合并结果。前端不自行实现合并算法，合并预览直接展示后端返回结果（避免两套 merge 语义漂移）。

面板分区（Tabs，键盘 `1-4` 切换）：

| 分区 | 内容 |
|---|---|
| 图像 | 大图预览（见 §3.5）、文件信息、来源、审图状态、rating |
| 标签 | 各层标签列表：original / WD / rule / manual。每个标签旁显示翻译（无翻译标 unknown，不自动入库）。WD 标签显示置信度条与「与 original 重合」徽标；无 original 时显示「无原始标签」。被 rule/manual 移除的标签以删除线显示在其层，可展开查看 |
| 自然语言 | original NL 原文、LLM 改进版、manual 版；标明当前生效的是哪一层（manual > llm > original，空 manual 回落 llm） |
| 合并预览 | 即导出 caption 预览：按当前导出方案配置组装的最终文本（触发词 + tags + 可选 NL），tag 逐个可点击；blocklist 命中高亮 |

**WD 与原始重合视图**：WD 标签按「重合 / 仅 WD / 仅 original」三组着色（用语义令牌，不靠颜色单独传达，加图标+文字），WD 置信度低于当前导出阈值的标签半透明显示「导出时会被排除」。阈值取自当前选中的导出方案，可在面板顶部切换方案。

**手动编辑**：在合并有效视图上操作。标签可删除（Delete 或点 ×）、可新增（输入框带自动补全，补全源为标签库）、可拖拽排序（v1）。NL 在 manual 分区用文本域编辑。编辑是草稿，显式「保存」（Ctrl+S）才提交；切图时有未保存草稿则弹出「保存/丢弃/取消」。保存携带读取时的各层 current ref 作为前置条件（CAS）。

### 3.5 大图预览与审图背景

- `Space` 打开/关闭大图预览（浮层，覆盖网格但保留工具条），`←/→` 在当前筛选内切换上一张/下一张，切换时预取前后各 2 张原图；`Esc` 关闭并把焦点还给网格里的该图。
- 预览支持：适应窗口 / 100% / 填满，滚轮缩放，拖拽平移，`0` 复位，`F` 切换适应/100%。
- 预览内也能审图：`K/X/U` 照常生效，操作后自动前进到下一张（可在偏好关闭「自动前进」）。
- 预览 URL 先显示已缓存缩略图作为占位，再无缝替换为原图，原图加载失败显示 `<ImageMissing>` 槽位。
- 缩放/平移状态不写入 react-query，只存在预览组件内部。

**背景切换**（工具条与预览内都有，`B` 循环）：棋盘 / 纯色（白、中灰、黑，可选自定义色）/ 深色（跟随主题表面）。用途：看透明通道和白底图的边缘。背景是 `ImageStage` 的一个属性，值来自令牌（`--stage-checker-a/b`、`--stage-solid-*`），棋盘用 CSS 渐变绘制，格大小也是令牌。设置存偏好，网格缩略图与预览共用同一设置，也可只对预览生效（Q36）。

### 3.6 review_status 与快捷键

review_status：未审（unreviewed）/ 保留（keep）/ 剔除（reject）。审图写入只改审图状态，不改标注。

| 键 | 动作 |
|---|---|
| `K` | 标为保留，作用于选择集；选择为空则作用于焦点图 |
| `X` | 标为剔除（同上） |
| `U` | 还原为未审 |
| `←→↑↓` | 移动焦点（上下按行） |
| `Shift+方向` | 扩展范围选择 |
| `Ctrl+A` | 全选当前筛选 |
| `Esc` | 清空选择 / 关闭浮层 |
| `Space` | 大图预览 |
| `Enter` | 聚焦详情面板 |
| `[` `]` | 上/下一个未审图（跳过已审） |
| `Ctrl+Z` | 撤销最近一次本地审图操作（见下） |
| `Ctrl+S` | 保存手动编辑草稿 |
| `B` | 循环切换背景 |
| `?` | 快捷键面板 |

快捷键由 `keymap.ts` 集中注册（动作名 → 默认键），组件只订阅动作，不写 `onKeyDown` 判断键值；在输入框/文本域聚焦时全局快捷键自动失效。快捷键面板与 §8 无障碍说明共用同一份注册表。自定义键位 v1。

**审图写入的响应速度**（高频操作，必须不卡）：采用乐观更新。按键后立即在缓存里改本页可见图的状态，请求在后台批量合并发送（同一批 150ms 内的按键合并为一次批量请求，每图携带其读到的审图版本作为前置条件）。失败的项回滚并在状态条给出一条汇总提示，冲突项见 §3.9。

**撤销**：本地维护最近 N 次审图操作栈（仅当前会话，N=50），`Ctrl+Z` 反向写回，同样走 CAS，版本已变的项跳过并提示。这不是后端的 undo，仅是审图状态的反向写入。

### 3.7 执行器面板（WD / LLM）

0.16.0 实现记录：工作台右侧非模态面板复用统一批次组件，覆盖详情栏、保留网格交互和草稿；关闭不停止任务，状态栏保留当前批次指示。三种范围均使用后端覆盖预览；“全选筛选结果”保持全选时的条件，后续修改筛选不改变该选择。失败重试先预览，原批次所有阶段终结后以原配置新建单阶段任务，强制重跑明确 failed 图片；跳过、成功、未执行项不包含在内。具体边界见 [工作台执行器验收](23-F14-工作台执行器与失败重试验收.md)。

工具条「执行器」按钮打开右侧浮动面板（Popover，非模态，不遮挡网格）。

- **执行器多选**：WD 打标、LLM 改进（NL）两个复选项，可同时勾选。WD 不可用（后端 capabilities 报设备/模型缺失或默认关闭）时该项禁用并显示原因与跳转 `#/settings/tagger` 的链接；LLM 角色未配置时同理跳转 `#/settings/llm`。
- **范围三选一**：执行选中 / 执行未覆盖 / 执行所有（当前筛选）。每个选项旁显示服务端计算的预计数量（调用预览，防抖）。
  - 「未覆盖」：口径由后端定义（该执行器在该图无 current 结果），前端只展示，不自行推导。
  - 「选中」随选择集形态走 `ids` 或 `filter`。
- **提交前确认**：列出「执行器 × 范围 × 数量」。数量>500，或 LLM 且数量>50 时需二次确认（LLM 可能产生费用与耗时）。「执行所有」使用长按确认（§6.4）。
- **提交后**：面板切为该批次的进度视图（总数/完成/失败/跳过，SSE 驱动），可暂停/取消；关闭面板不影响任务，状态条常驻一个任务指示，点击回到面板或 `#/p/:pid/jobs`。
- **逐图可见**：每完成一张图，对应格的标注状态点更新，若该图正是焦点图，详情面板自动刷新。刷新节流遵循 §6.2。
- **失败项**：失败计数可点击，展开失败图列表（reason_code 映射为中文提示），支持「仅重跑失败项」。
- 同类执行器在跑时，再次提交同范围给出提示，不静默排队。

### 3.8 批量规则替换

入口：工具条「批量规则」打开右侧抽屉（模态焦点陷阱，Esc 关闭）。流程固定三步，状态机在前端显式建模（`idle → editing → previewing → previewed → applying → applied → (undone)`），按钮可用性由状态机推导。

1. **规则**：从规则库选择一条（每次只应用一条），或临时编辑。规则表单为三组：条件 / 删除 / 写入，每组 `mode`（全部 all / 任一 any）+ 标签列表。标签输入沿用 `TagInput`（带补全）。空组显式为「无」。提交前由前端做形状校验（至少有删除或写入之一、组内去重），语义校验以后端为准。
2. **预览**：范围取当前选择集（`ids` 或 `filter` 二选一），预览冻结有序 id 列表，新增图片不自动纳入。展示命中数、变化数、增删标签示例（逐图 before/after diff 虚拟列表）、原因分布，以及「条件退化到 WD」或「无原始标签」提示。必须展示这些后，「执行」按钮才启用。预览有有效期（约 15 分钟）：过期后按钮禁用并提示重新预览，倒计时在抽屉底部。
3. **执行**：携带预览摘要执行，成功后显示受影响数量并刷新缓存（事件只给失效通知，不含内容）。读集失效（有图在预览后被改动）返回需重新预览，前端自动回到 `editing` 并保留规则表单内容。
4. **撤销最近一次**：抽屉头部与操作日志页都有「撤销最近一次」。只允许全局最近的一次已应用操作，且任一图有后续变更则整批拒绝，错误详情列出冲突的 image_id 与层，前端展示冲突清单并可跳转到该图。无重做，需重新预览。撤销按钮用长按确认。
5. **结果未知**：执行请求网络中断时（outcome=unknown），不重发，进入「核查」状态：查询操作日志，找到则显示结果，找不到则提示用户手动核查，禁止出现一键重试。

规则库的新增/编辑/导入（含 TagCleaner 规则迁移）在 `#/settings/rules`，抽屉内只做选择与临时编辑。

### 3.9 manual 编辑冲突处理（CAS）

所有写入（手动标签/NL、审图状态、rating）携带读取时的版本令牌。冲突统一为 409 版本冲突，前端按资源类型分流：

| 场景 | 处理 |
|---|---|
| 审图状态冲突（批量） | 乐观更新回滚冲突项，状态条汇总「N 张已被改动，已刷新」；其余项不受影响（逐图前置条件） |
| 手动编辑保存冲突 | 打开「冲突对比」对话框：左侧我的草稿，右侧最新服务端视图，顶部指出哪一层被谁改（WD/LLM 刚完成，或另一次编辑）。操作：**用最新重新编辑**（草稿的增删差异在最新视图上重放，能无歧义重放的直接保留）/ **覆盖**（以最新版本令牌重新提交我的草稿差异）/ **放弃草稿** |
| 批量手动编辑冲突 | 后端整批拒绝（任一读集失效即全拒），前端提示并列出冲突 image_id，可选「刷新后重试」，不做局部成功假设 |
| 规则执行冲突 | 回到预览，见 §3.8 |

草稿基于差异（增/删集合）而非整份快照，因此重放是确定的。WD/LLM 在后台完成会使焦点图的版本令牌变化：此时若有未保存草稿，详情面板顶部出现非阻塞横幅「此图标注已更新」，由用户决定是否合并，**不得**自动覆盖或自动丢弃草稿。

## 4. 数据源页

路由 `#/p/:pid/sources`（列表）与 `#/p/:pid/sources/:sid`（详情）。数据源之间地位平行（import、nai、其它接口源），共用列表与状态展示，差异只在「配置表单」和「运行控制」两块。

### 4.1 列表与状态

列表每行：名称、类型、状态（draft / running / paused / done / canceled / failed）、进度条（done/目标）、失败数、最近更新。状态到视觉的映射走语义令牌（§7），文字必须同时出现，不单靠颜色。启动后参数锁定：详情页表单整体只读并显示锁图标，想改参数只能「复制为新数据源」。

### 4.2 NAI 源配置表单（由 capabilities 动态渲染）

表单不在前端硬编码参数列表。后端返回 capabilities（可用模型、参数范围、枚举、默认值、接口形态），前端用一个 `SchemaForm` 渲染：

| 参数描述字段（前端消费） | 渲染 |
|---|---|
| 类型 enum | `Select`（项少于 5 用 `ToggleGroup`） |
| 数值 + 范围 + 步进 | `NumberField`，范围用 `Slider` 辅助；越界即时提示 |
| 布尔 | `Switch` |
| 文本 | `TextField` / `TextArea`（风格提示词、负面提示词） |
| 依赖/互斥（如某模型下不可用） | 字段禁用并显示原因，不隐藏 |
| 未知类型 | 退化为只读 JSON 展示并告警，不崩溃 |

要求：capabilities 切换模型时重新渲染并保留同名字段的值，丢弃的字段在表单底部列出「已移除的参数」。前端校验仅做范围/必填的即时提示，最终以后端校验（422，issues 数组带 field）为准，按 `field` 把错误回显到对应控件。

### 4.3 尺寸预设与 aspect

- 尺寸预设来自产品层，前端展示预设名与各 aspect（如方/竖/横）对应的像素值，选择后在表单里显示「启动时将物化为 W×H」。
- 启动后配置里保存的是实际像素值，与产品层预设脱钩：详情页展示像素值，并标注「来源预设：xxx（已脱钩）」。
- `aspect` 选项：留空表示用提示词条目自带的 aspect，否则取默认 aspect（推荐 square，Q32）。尺寸须为 64 的倍数，由后端校验，前端给范围提示。
- 内置预设只读；自定义预设在 `#/settings/presets` 维护。

### 4.4 费用策略 deny / ask / allow

- 三选一 `ToggleGroup`，每项附一句后果说明：deny（涉及费用时暂停，不提供同意动作）、ask（涉及费用时弹窗确认）、allow（直接执行，需额外一次确认才能设置）。
- 切到 allow 用长按确认，并说明「按 Anlas 计费」。修改策略会使已有的费用同意作废（后端行为），前端在切换时提示。
- **ask 弹窗**：由 `source.cost_confirmation_required` 事件触发。内容：预计 Anlas、涉及的条目、当前周期。按钮：**同意本周期** / **暂停**（默认焦点落在「暂停」）。同意动作必须携带事件里的 cycle_id；周期过期则后端拒绝，前端提示并刷新状态，不重试。
- 弹窗为全局队列：多个源同时触发时排队显示，一次一个，不叠层。页面不在源详情时，状态条出现红点徽标，点开才弹，避免打断审图。
- deny 暂停时不渲染同意按钮，只显示暂停原因与「改为 ask」入口。
- 不对付费请求做任何自动重发；网络中断后先读取状态再让用户决定。

### 4.5 运行 / 暂停 / 续跑与进度

- 控制按钮按状态机推导：draft→「启动」；running→「暂停」「取消」；paused→「续跑」「取消」；done/canceled 只读。每次控制携带版本令牌，同状态重复点击为 no-op，不当成额外一次运行。
- 进度区：计数（待发/已发/完成/失败/跳过）、当前条目与阶段、预计 Anlas（若有）、在途数。计数一律由事件**覆盖**本地值，不累加。
- 暂停原因（费用、失败、手动、重启中断）以文字呈现。重启后统一显示「中断暂停」，由用户决定续跑。
- 失败条目：可展开列表，按 reason_code 给出中文说明；重试失败项后源进入 paused，需再点「续跑」（与后端语义一致）。
- 产出实时可见：每完成一张图，源详情页下方「最近产出」缩略条追加，并提供「在工作台中查看」跳转到按此数据源筛选的工作台。

### 4.6 外部导入源

- 入口：数据源列表「新建 → 导入」。选择本地目录或文件（路径经后端文件选择能力，前端不接触任意路径，见 Q35），然后选择导入方案（如图片 + 同名 txt、元数据解析）。
- 流程：选择 → **预览**（展示识别到的图片数、可解析标签数、重复、问题清单 issues）→ 确认导入 → 进度（operation 类，SSE）→ 完成后跳转工作台并按该源筛选。
- 预览有有效期，过期需重新预览；导入不经过提示词生产层，也没有费用策略与尺寸预设区块（表单按源类型条件渲染）。
- 重复/问题：issues 按 severity 分组，error 阻止确认，warning 可确认；可导出问题清单为文本。

## 5. 提示词生产页

路由 `#/p/:pid/prompts`。提示词生产的数据（字典、任务）在产品层，项目只是入口；页面不向项目写任何东西，产出通过「冻结 seeds」交给数据源。页面自上而下三块：采样配置 → 覆盖预览 → 任务与结果。

### 5.1 采样配置

| 覆盖矩阵 | 开关 + 选择模板（默认模板由后端给），关闭时纯随机 |
| NSFW 围栏 | `Switch`，默认开，旁附阈值说明；关闭用长按确认（§6.4） |
| LLM 优化 | `Switch`；开时显示将使用的 prompt 角色（及 nsfw 角色）与「角色为空则跳过优化、保留原值」的提示；角色缺失时开关禁用并链接 `#/settings/llm` |
| 目标词典 | 可选：授权自动追加合格结果，或完成后手动追加 |

围栏与优化的说明文案来自后端返回的原因码映射（`skipped/role_empty`、`nsfw_contract_missing` 等），前端不自拟语义。围栏开时「保守排除」的条目要在预览里以「策略排除」计数，不能显示为失败。

### 5.2 覆盖矩阵预览

「预览覆盖」提交采样请求，得到覆盖报告（异步操作，SSE 驱动）。不调用精修 LLM，因此可反复点。

- **矩阵视图**：主维度 × 主维度的热力格，每格显示「目标 / 实际」，缺口格用语义令牌 `--color-warning` 加缺口数字，不靠颜色单独表达。维度超过两个时选两个做行列，其余做筛选。
- **汇总**：请求 N / 可用数、围栏排除数、重复数、不可分类数、状态（满足 / 无解 / 搜索耗尽）。无解与搜索耗尽文案不同：前者给修改建议，后者提示可调大搜索预算或缩小范围。
- 前端不自动放宽任何约束。修改参数后预览作废（标注「已过期」），必须重新预览。
- 键盘：矩阵格可聚焦，Enter 展开该格的条目列表。

### 5.3 任务与结果

- 「开始生产」创建任务（持久，产品层），页面进入任务视图：状态（pending / running / paused / done / failed / canceled）、进度（completed / total）、ready 标记、覆盖状态。计数由 SSE 覆盖，不累加。
- 控制：暂停 / 续跑 / 取消，携带版本令牌。终态任务只读，「重做」创建新任务并可引用旧快照。
- **ready 的含义**：done 不等于 ready。只有数量、内容、围栏、去重、覆盖全部通过才 ready。未 ready 时：显示缺口原因，「用于数据源」入口禁用，但允许导出部分结果。
- **结果列表**（虚拟滚动，分页拉取）：每条显示最终 tags、NL、aspect、rating、精修 outcome（ok / skipped 及原因 / failed）、是否使用了原值。支持按 outcome 筛选，单条可勾选。
- **写入词典**：勾选结果 →「追加到词典」→ 选择目标词典 → 得到追加报告（新增 / 重复 / 评级冲突）。评级冲突逐条列出，默认采纳高值，由用户确认，不静默覆盖。词典 revision 冲突时重新预览合并，不覆盖现有条目。追加失败不影响任务成果。
- **冻结 seeds**：任务 ready 后，数据源页创建 NAI 源时从「已就绪的任务」中选择。本页提供「去创建数据源」跳转，携带任务 id。
- 任务列表（历史）支持手动清理终态任务，使用长按确认。

### 5.4 字典库页（设置）的前端范围

`#/settings/dictionaries`：字典列表（按 kind 分 Tab）、条目分页浏览、导入预览（文件格式、有损字段提示、条目计数、问题清单）→ 确认、导出（json / csv / txt，txt 显示有损提示）、Launcher 词库只读导入（分组映射 → 预览 → 确认）。编辑条目 v1；MVP 只读浏览 + 整体导入导出。

## 6. 长任务进度、错误与离线、危险操作

### 6.1 事件管线

单一事件通道，`events/` 模块是唯一订阅点，业务组件不直接碰 SSE。

| 环节 | 规则 |
|---|---|
| 连接 | 登录会话后建立一条订阅，按当前项目与主题过滤；换项目换订阅，并先拉快照再消费事件 |
| 去重 | 事件 id 为 `epoch:sequence`；记录已处理的最大序号，重复事件丢弃。过滤后序号不连续是正常的，不据此判断丢失 |
| 分发 | 事件类型 → 处理器注册表（`eventHandlers.ts`）。处理器只做两件事：`setQueryData`（覆盖计数、状态）或 `invalidateQueries`（图片、标注、列表） |
| 计数 | 一律覆盖，不累加；事件迟到或重复不会让进度倒退（收到的计数小于本地且状态相同则忽略） |
| 缺口 | 收到 `stream.resync_required`，丢弃游标，对所有活跃查询做一次失效，并重新建立订阅 |
| 重连 | 指数退避 1/2/4…30 秒加抖动，带 `Last-Event-ID`；401 不重试旧凭据，转鉴权状态页 |
| 内容 | 事件不含标签、NL、图像。需要内容一律走 GET，这是前端对"失效通知"的唯一假设 |

### 6.2 刷新节流

高吞吐时（WD 批量、规则撤销）不能每个事件都刷新网格。

- `image.updated` / `annotations.changed`：按 image_id 收集到一个集合，每 300ms 刷一次，只失效**当前可见页**和**焦点图详情**；不可见页标记 stale，滚到时再拉。
- 事件带 `invalidate_scope=true` 时：整体失效图片列表查询（保留已渲染内容，后台拉取，不闪白）。
- 焦点图详情刷新且存在未保存草稿时，不覆盖草稿，走 §3.9 的横幅。
- 进度类事件由后端合并，前端不再二次防抖，仅用 `requestAnimationFrame` 合并同一帧内的多次写入。

### 6.3 进度 UX

统一的 `<TaskProgress>` 业务组件，视觉由 `ui/ProgressBar` 提供。三种形态：

| 形态 | 位置 | 内容 |
|---|---|---|
| 内联 | 数据源行、任务行 | 进度条 + done/total + 状态文字 + 失败数 |
| 状态条指示 | 工作台底部 | 活跃任务数；点击展开任务浮层，列出各任务简要进度与暂停/取消 |
| 详情 | 源详情、任务详情、执行器面板 | 分项计数、当前阶段、预计 Anlas、失败列表、控制按钮 |

约定：

- 未知总数用不确定进度条（`aria-busy`），不伪造百分比。
- 状态文字必须出现（"运行中 / 已暂停：费用确认 / 中断暂停"），暂停原因来自 reason_code 的映射表（`i18n/reasons.ts`），映射缺失时显示原码，不吞掉。
- 完成时不弹打断式提示：状态条出现一次性"已完成·在工作台查看"，8 秒后收起（时长走令牌）。失败与需要决策的事件（费用确认）才升级为模态或红点。
- 页面隐藏（`visibilitychange`）时不暂停订阅；回到前台时对活跃资源做一次 GET 校准。
- 刷新页面后任务状态从 GET 恢复，不依赖本地缓存的事件。

### 6.4 危险操作长按确认

沿用 TagCleaner 的长按确认交互：按住按钮到进度环填满才触发，松手即取消，防误点。以下为本文定义的细节，TagCleaner 原实现的具体参数我没有核对，列入 Q39。

- 组件：`ui/HoldToConfirm`，业务只传 `onConfirm`、`label`、`holdMs`（缺省取令牌 `--hold-confirm-duration`）。进度环用 CSS 动画驱动，时长来自动效令牌，不写死。
- 适用清单：执行器"执行所有"、撤销最近一次规则、切换 allow 费用策略、关闭 NSFW 围栏、清理任务/导出、删除字典/项目内数据、取消正在运行的数据源。
- 键盘：按住 `Space` 或 `Enter` 同样计时，松开取消；焦点环可见；`aria-describedby` 指向"按住 N 秒确认"说明。屏幕阅读器用 `aria-live="polite"` 播报"已确认"。
- 减弱动效：不播放填充动画，改为文字倒计时（"再按住 1 秒"），逻辑与时长不变。
- 可访问替代：不提供"点两次"等降级方案，避免绕过。需要无障碍替代时，由偏好里的"确认方式"切换为二次对话框（输入固定词，如 `CONFIRM`），默认关。
- 长按不替代预览：规则替换仍必须先预览。

### 6.5 错误体系

API 错误统一信封，前端 `api/errors.ts` 解析为 `AppError { code, status, message, details, retryAction }`，按 `retryAction` 分流：

| retryAction | 前端行为 |
|---|---|
| none | 展示错误，不提供重试 |
| read（安全读） | 自动重试读请求，最多 3 次退避 |
| reconcile（结果未知） | 不重发。进入"核查"：查询对应资源状态，让用户决定；写操作绝不自动重发 |
| reauth | 转鉴权状态页，不循环重试 |

展示层级：

1. 字段级：422 的 issues 回显到表单控件（`aria-invalid` + `aria-describedby`）。
2. 区域级：面板内的 `<InlineError>`（带重试按钮，仅 read 类）。
3. 全局：`Toast` 用于完成或非阻塞提示（可累计汇总，同类合并，不堆叠 5 条以上）；`ErrorBoundary` 兜住渲染异常，显示 `<ErrorState>` 槽位并提供"复制诊断信息"（仅含错误码、版本、相对路径，不含 token 与绝对路径）。

文案：`i18n/errors.ts` 维护 `code → 中文提示与建议动作`。未登记的错误码显示通用提示加原码。前端不显示后端原始 message（可能含内部细节）。

### 6.6 离线、会话与关闭

状态机 `connection`：`booting → online → degraded → offline → reauth → draining`，存 zustand，外壳顶栏常驻状态点（图标 + 文字）。

| 状态 | 触发 | UI |
|---|---|---|
| online | 会话 GET 成功、SSE 已连 | 正常 |
| degraded | SSE 断开但 REST 可用 | 顶栏黄点"实时更新已断开，重连中"；轮询活跃资源（间隔 5 秒，走令牌/配置）；不阻塞操作 |
| offline | REST 连续失败（网络错误） | 全局横幅"后端不可达"，写操作按钮禁用，读缓存只读显示（标注"数据可能过期"）；每 3 秒探测会话，恢复后自动校准全部活跃查询 |
| reauth | 401 | 全屏状态页，提示"会话已失效，请从启动器重新打开"；不无限重试 |
| draining | 收到 draining 事件或会话标记 | 横幅"后端正在关闭"，禁用新提交，保留查询直至断开 |

关键点：

- 后端重启后 `epoch` 变化：丢弃全部事件游标，全量失效，选择集若引用的 image_id 仍存在则保留，否则静默剔除并提示。
- 离线期间未发出的审图乐观更新：保留在待发队列（内存），恢复后逐项带原版本令牌重发；队列超过 200 项或离线超过 60 秒，改为提示用户"离线期间的 N 项审图未同步"，由用户选择重试或丢弃，避免静默覆盖。
- 写请求结果未知（超时/断线）：标记为"待核查"，恢复后先 GET 比对再决定，禁止自动重发创建类请求。
- 开发模式 HMR 导致内存 token 丢失：走 reauth，不把 token 写入 `localStorage`。

| 令牌组 | 内容 |
|---|---|
| 字号 `--font-size-*` | `2xs 10 / xs 11 / sm 12 / md 13 / lg 15 / xl 20 / 2xl 28 / display 48`（px 值，经 rem 输出）。工作台默认 `sm–md`，保证密度；`display` 仅用于总览与空状态 |
| 字重 / 行高 | `--font-weight-regular 400 / medium 500 / bold 700`；`--line-height-tight 1.15 / normal 1.4 / dense 1.25` |
| 标签字距 | `--tracking-label: 0.2em`（mono 大写小标签）、`--tracking-display: -0.02em`；`--type-label` 复合令牌 = mono + 2xs/xs + 全大写 + tracking-label + accent 色 |
| 间距 `--space-*` | 4 点网格：`0 / 1(2px) / 2(4) / 3(8) / 4(12) / 5(16) / 6(24) / 7(32) / 8(48)` |
| 密度 `--density-*` | `compact / comfortable` 两档（`data-density` 属性），影响 `--row-height`、`--control-height`、`--grid-gap`；工作台默认 compact |
| 圆角 / 阴影 | `--radius-0 / sm / md / lg / pill`，参考图风格默认 `0–2px`；`--shadow-0 / 1 / 2 / popover`，light 默认以细线代替阴影（阴影值可为 `none`） |
| 线宽 / 层级 | `--stroke-hairline: 1px`、`--stroke-focus: 2px`；`--z-grid / sticky / popover / modal / toast` |
| 动效 | 集中在 `tokens/motion.ts` + `motion.css`：`--motion-fast 90ms / base 160ms / slow 280ms`、`--ease-standard / enter / exit`；`@media (prefers-reduced-motion: reduce)` 把时长令牌置 `0.01ms`，进度环与骨架屏改为静态。审图翻页、选择高亮不使用动效 |

### 7.5 状态的非颜色区分与装饰槽位

| 对象 | 颜色之外的手段（必须同时出现） |
|---|---|
| review_status 未审 / 保留 / 剔除 | 图标槽位 `status.unreviewed`（空心圆）/ `status.keep`（对勾）/ `status.reject`（叉）+ 文字标签「未审 / 保留 / 剔除」；缩略图角标用图标，剔除图另加降亮度与斜线蒙层令牌 `--overlay-reject-pattern` |
| rating 四级 | 文字缩写 `G / S / Q / E`（mono）+ 图标槽位 `rating.*` + 形状（徽标描边样式随级别递增：无框 / 细框 / 粗框 / 实心）；颜色仅辅助 |
| 费用确认、失败、跳过 | 图标 + 文案，不只用红/琥珀边框 |
| 焦点 / 选中 / 当前 | 焦点 = 2px 环 + 偏移；选中 = accent-subtle 底 + 左上勾选图标；当前焦点图 = 外环。三者叠加时可同时辨认 |

装饰槽位（`ui/deco/`，均为可替换组件，默认实现读取 `--color-deco-*` 令牌，`aria-hidden="true"`，工作台默认不渲染，仅总览、空状态、项目选择页启用）：

| 槽位组件 | 作用 | 令牌依赖 |
|---|---|---|
| `PixelColumn` | 竖向方块列，顶浅底深渐变，可指定高亮格序号 | `--color-deco-pixel-1…5`、`-highlight`、`--deco-pixel-size`、`--deco-pixel-gap` |
| `HalftoneField` | 半调网点图形（CSS radial-gradient 或可替换为图片资源） | `--color-deco-halftone`、`--deco-halftone-dot`、`--deco-halftone-pitch` |
| `MonoLabel` | 宽字距大写小标签，如 `PROJECT ID`、`00000002` 风格编号 | `--type-label` |
| `Hairline` | 细线分隔 | `--color-border`、`--stroke-hairline` |

换肤只改令牌值或替换这四个组件的实现，业务组件不感知（Q43 覆盖字体与装饰默认值）。
## 8. 可访问性

目标是键盘全流程可用、状态不靠颜色、读屏可得到关键信息。完整 WCAG 合规需要辅助技术手测和专家评审，本文不宣称合规，只定义设计约束与可自动化的部分（FT 清单）。

### 8.1 键盘全流程与焦点管理

快捷键具体键位见 3.6，本节只定可访问性约束。

| 场景 | 约束 |
|---|---|
| 全局 | 每个功能有键盘路径；`?` 打开快捷键面板（可聚焦、可 Esc 关闭）；页首「跳到主内容 / 跳到网格」两个跳转链接，聚焦时才显示 |
| 网格 | 单个 tab stop（roving tabindex），方向键移动焦点，Tab 离开网格去详情面板；虚拟滚动时焦点图被回收则保留一个隐形焦点锚，滚回后恢复，不丢焦点 |
| 批量选择 | Space 切换、Shift+方向键扩选、Ctrl+A 全选；选择数量变化通过 `aria-live="polite"` 区域播报，节流 500ms |
| 审图快速连按 | 打标后自动前进到下一张，焦点随之移动；不对每次打标播报，只播报「第 N / 共 M，已保留」的当前图状态，避免读屏被刷屏 |
| 大图预览 | 打开时焦点进入预览并陷在其中（focus trap），Esc 关闭后焦点回到触发的缩略图；预览内左右键翻页，翻页后焦点不离开预览 |
| 对话框 / 弹层 | 打开聚焦首个可操作项（危险操作聚焦「取消」），关闭回到触发元素；背景 `inert`，不用手写 aria-hidden 全树 |
| 长按确认 | 同时提供键盘等价：按住 Enter/Space 满时长触发，松开取消；进度以 `role="progressbar"` 暴露，并有文字倒计时 |
| 输入框内 | 单字母快捷键在 input/textarea/contenteditable 内一律失效；`Esc` 先退出输入再回网格 |
| 快捷键冲突 | 不占用浏览器与读屏常用组合；单字母快捷键可在设置里整体关闭（WCAG 2.1.4 要求可关闭或重映射） |

### 8.2 ARIA、对比度与其它

| 项 | 要点 |
|---|---|
| 网格语义 | 容器 `role="grid"`，行 `role="row"`，缩略图格 `role="gridcell"`，`aria-selected`、`aria-rowcount/colcount`（虚拟滚动给总数）、`aria-rowindex`；单元的可访问名 = 「图 ID、审图状态、分级」，不读文件名路径 |
| 状态 | 审图状态、分级用文字加图标（图标 `aria-hidden`，文字或 `aria-label` 提供名称），不依赖颜色（7.5） |
| 进度 | `role="progressbar"` + `aria-valuenow/min/max`；状态变化（暂停、失败、需费用确认）用 `role="status"`，错误用 `role="alert"`，费用确认弹层为 `alertdialog` |
| 表单 | 每个控件有可见 label，错误文本用 `aria-describedby` 关联；后端返回的字段错误映射到对应控件 |
| 焦点环 | 统一 `:focus-visible`，2px `--color-focus-ring` 加 2px 偏移；`ui/` 基础组件内置，业务组件不得 `outline: none`。焦点环对相邻色 ≥3（accent/bg 9.61、dark 8.45） |
| 对比度 | 核验结果见 7.3：文本与控件边界全部达标；不达标的仅装饰线和装饰方块，且 `aria-hidden`。审图区背景（棋盘/纯色）下的叠加文字走带底色的徽标，不直接压在图上 |
| 动效 | 尊重 `prefers-reduced-motion`（7.4）；同时遵守 `forced-colors`：状态徽标保留边框，装饰层隐藏 |
| 缩放与密度 | 200% 缩放下工作台不出现横向滚动条的核心区；紧凑密度的点击目标最小 24×24 CSS px（WCAG 2.2 目标尺寸最低值），缩略图格本身远大于此 |
| 语言 | `<html lang>` 随界面语言；mono 的 tag 文本保留英文原文，设 `lang="en"` 以便读屏正确发音 |

以下仅是提案，未改动 F11 或其它文档。F11 自身的 C17–C23 与各 F 文档的 C 编号不在此重复，本文从 C30 起。

| 编号 | 建议 | 对应 | 不采纳时的退路 |
|---|---|---|---|
| C30 | `ImageView` 增加 `width`、`height`、`has_alpha`（只读，入库时已知），供占位尺寸与背景默认值 | AR07 | 前端加载后读 `naturalWidth`，网格布局有抖动；背景默认棋盘 |
| C31 | A059 的分页响应增加 `total`（当前筛选下的总数），并支持 `around_id` 或 `offset` 定位 | AR04 | 虚拟滚动只能估算总高度，无法精确跳转，`aria-rowcount` 用 -1（未知） |
| C32 | A062 的目标集合除 `ids` 外支持 `query` 范围（ImageQuery + `expected_total`），服务端在同一事务内展开并返回逐张旧状态，用于撤销 | AR10 | 前端先拉全部 id 再分批，超 5000 张被拆成多个事务，失去整批原子性，撤销也只能逐批 |
| C33 | 新增只读 `GET P/images/stats`：按 review_status、rating 分组计数，可带 ImageQuery | AR11 | 前端翻页累加，计数滞后且代价高 |
| C34 | A063/A064 明确 `ETag` + `Cache-Control: private, max-age`，支持 304；图片字节响应不得因 Bearer 被浏览器禁缓存 | AR06 | 每次切图重新下载原图，预览翻页变慢 |

### 12.2 待确认（接前文编号，只列影响实现的）

本文前 6 章引用了 Q30–Q39、Q42，其中 Q34、Q37 在已写章节中未被引用，以下显式标记空缺；Q40、Q41 此前未用，本次定义。推荐值不等于用户已裁决。

| 编号 | 问题 | 推荐 |
|---|---|---|
| Q30 | 路由用 hash 还是 history | hash，后端无需 fallback，token 引导码在片段里也不会和路径冲突 |
| Q31 | SSE 用原生 EventSource 还是 fetch 自解析 | fetch + ReadableStream，只有它能带 Bearer（约百行，见 FT09/FT10） |
| Q32 | 数据源默认 aspect | square，与 F02–F05 的推荐一致 |
| Q33 | 排序字段范围 | `id` 升/降（API为`id`/`-id`）；其余字段仅在后端能力声明时出现，与§3.2一致 |
| Q34 | 编号空缺（未使用） | — |
| Q35 | 本地路径如何选 | 一律经 A004 原生对话框，前端不接触绝对路径 |
| Q36 | 审图背景是否网格与预览共用 | 默认共用同一偏好，预览内可单独覆盖，覆盖不回写网格 |
| Q37 | 编号空缺（未使用） | — |
| Q38 | 混合来源占比 | 只展示实际占比，不暴露硬配额 |
| Q39 | 长按确认的时长与进度环参数 | 按§6.4由holdMs或默认令牌`--hold-confirm-duration`决定，进度环时长来自动效令牌；TagCleaner原值未核对，具体参数待确认，不预设危险/次级两档固定时长 |
| Q40 | 单字母快捷键默认开启还是关闭 | 默认开启（审图效率第一），设置里可整体关闭（8.1 的 WCAG 2.1.4 要求） |
| Q41 | 默认主题与密度 | 默认 `light`（参考图风格）+ compact；提供「跟随系统」选项但默认不开，避免首启颜色不符合预期 |
| Q42 | TypeScript 6 / Vite 8 / vitest 5 较新 | 首次安装出 peer 告警时按实际结果回改 1.1 选型表，而不是强行固定 |
| Q43 | 字体与装饰默认值（Inter/JetBrains Mono/Noto Sans SC 是否随包、像素方格与半调网点默认是否启用） | 随包 woff2 并附许可证；字体子集化 Noto Sans SC；装饰默认只在总览/空状态/项目选择页启用，工作台不渲染 |
| Q44 | 虚拟滚动自写还是用库（如 TanStack Virtual） | 用成熟库，只自写 roving 焦点与 `aria-*` 层；先做 1 万张的压力验证再定库 |
| Q45 | 暗色主题的 `-subtle` 底对比度与 mono 小标签（2xs/10px）的可读性 | 落地后由 FT21 自动核；10px 仅限装饰性标签，承载信息的最小用 11px |
| Q46 | 是否引入 Playwright 作为 FT24 | 先不进 MVP，仅在虚拟滚动与焦点出现 jsdom 无法覆盖的回归时再加 |
| Q47 | `<img>` 不能带 Bearer，图片怎么取 | fetch 带 Bearer 转 blob URL 并配合 C34 缓存与 LRU 回收；不用 URL query 带 token，以免进日志与 Referer |

以上不阻塞令牌文件、`ui/` 基础组件和 mock 数据下的工作台开发。C30–C34 的缺口会影响虚拟滚动精度、批量审图原子性和图片缓存，建议在 F11 下一次同步时一并处理。
