## 指纹算法与入库

`imaging/phash.py` 实现 `compute_phash`、`hamming`、`find_candidates` 及分行迭代接口。phash64-v1 的预处理固定为 Pillow 12.3.0：首帧、EXIF 方向归正、RGBA 白底合成、灰度、Lanczos 缩至 32×32。取二维未归一化 DCT-II 的左上 8×8，包含 DC，用 64 个系数中位数与严格大于比较，按行高位优先编码成 16 位小写十六进制。

为避免安装额外数值依赖，DCT 使用标准库 `math.cos` / `math.fsum` 的可分离计算，只算所需的八个频率。公式与 [SciPy 的 DCT-II 定义](https://docs.scipy.org/doc/scipy/reference/generated/scipy.fft.dct.html) 一致；v1 明确固定最终系数保留小数点后 8 位，再计算中位数，避免理论零值的浮点噪声影响指纹。预处理参照 [Pillow EXIF 转置](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html#PIL.ImageOps.exif_transpose)。本项目不是对任意第三方 pHash 库输出的兼容承诺。

Pillow 在 pyproject.toml 固定为 `==12.3.0`；运行时版本不匹配时不计算新指纹，返回明确 unavailable。golden fixture 固定黑图 `0000000000000000`、白图 `8000000000000000`、合成几何图 `ab1ac5c6d4e162ec`；另验证方向、透明通道、缩放和首帧。

导入仍先做 SHA-256 精确去重；文件复制和完整性检查后计算 pHash，经 `ImageArtifact.phash`、现有收据与 `complete_item` 原子登记。崩溃恢复复用收据里的指纹，不改变八张表或 schema v1。pHash 组件不可用时允许 NULL，并在导入报告的逐项 warnings 中给出 `phash:unavailable`；坏图片仍由既有完整性检查拒绝。不会改写原图、TXT、元数据或任何标注层。

按照 Q01 的首版范围，旧 NULL 不回填。已有 NULL 或坏 hash 会在扫描统计中明确跳过；即使距离为 0，也不跳过导入、不合并归属、不自动 reject 或删除图片。指纹函数支持动画首帧，但既有导入模块继续拒绝多帧图片，本轮不扩大导入格式能力。

## 扫描范围、排序和资源边界

- scope 必须且只能包含 selected_ids 或 filter。selected_ids 去重检查、校验存在性并按 ID 排序；筛选范围复用来源、审核、评级、缺失、标签查询。未明确指定审核状态的筛选排除 reject；显式选中可以包含 reject。
- 受理时用一个短数据库读快照提取最多 10,001 条轻量投影；超 10,000 图返回 413 `batch:too_large`，不创建扫描任务。此后释放连接再核查文件和比对，新增图片、标注或审核变化不改变已固定范围。
- 缺失文件/登记 missing、大小变化、NULL、非 16 位小写 hex 分别统计为 missing / size_changed / no_hash / invalid_hash。扫描本身不修改 file_missing；只检查路径、存在性和已登记大小，不重新读全图 SHA 或重新解码。用户随后查看图片时仍走既有媒体身份校验。
- 用户必须明确提供整数 threshold=0..64，不默认选择阈值。比较所有有效指纹对，保留 distance≤threshold 且 left_id<right_id 的唯一 pair，按 `(distance,left_id,right_id)` 稳定排序。A≈B、B≈C 不意味着 A≈C；界面按实际 pair 展示，不把连通分量当同图组。
- 分行全配对，O(n²) 时间；每行最多 9,999 个候选。每个距离一个二进制桶，两个 image_id 各用 8 字节；桶内按 left/right 自然有序。分页按桶计数定位并 seek，只读取本页，无需把所有 pair 放进内存或一次排序。
- 每次结果最多 **64 MiB**、同时最多 **3 次**会话结果、有效期 **15 分钟**。超结果上限整次 failed，原因 `duplicates:result_limit`，清理所有部分结果，不发布截断列表。运行中只返回进度与发现数量，items 为空；完成后才提供稳定分页游标。
- 取消在相邻行之间检查；DELETE 立即使查询失效，并等待工作线程在行边界清理。通过通用 operation 取消也会使扫描进入 canceled。关闭/切换项目取消相关任务并清理结果；退出服务同样收尾。过期在下一次扫描/查询时惰性回收，不后台删除图片。
- 临时目录用独立 `stylelora-duplicates-*` 名称，生产服务位于产品目录旁，测试位于 `.test-tmp` 内。临时结果只含 ID pair，不写项目数据库或图片目录。异常断电后的临时目录不承诺自动回收；不得据此恢复旧扫描或把临时文件当持久证据。

## HTTP 和工作台

项目接口前缀 `/api/projects/{project_id}`。沿用 Bearer、Origin、项目句柄、会话幂等键和有签名分页游标。

| 接口 | 行为 |
| --- | --- |
| `POST /duplicates/scans` | 严格 `{scope,threshold}`；UUID Idempotency-Key；202 返回 scan_id、task、status_url、operation_url。 |
| `GET /duplicates/scans` | 本轮增加的会话索引，最多 3 项；方便重新授权后找回或释放已有扫描，含明确容量限制。 |
| `GET /duplicates/scans/{id}?limit=&cursor=` | 默认 50 / 最大 1,000；返回 pair 页、状态、进度、跳过计数、threshold、version、到期时间；过期/释放后 410。 |
| `DELETE /duplicates/scans/{id}` | If-Match 必填；成功 204，过期版本 409；取消并释放结果，不删除图片。 |
| `GET /api/operations/{id}` | 复用 F11 后台任务查询和取消；任务种类 duplicates.scan；不创建 WD/LLM jobs 记录。 |

扫描版本绑定生命周期状态，进度变化不使取消版本每一行都失效；图片审核仍使用既有图片版本 CAS。未知/错误游标和跨扫描游标拒绝，不跨范围读结果。

侧栏“近似重复扫描”，路由 `#/p/:pid/duplicates`：

1. 选择项目中未剔除图片，或工作台选中的 ID/筛选范围。
2. 明确填写阈值；空值、非整数或超界不能提交。
3. 查看进度、有效指纹与跳过计数；完成后每页 10 对，显示距离和两张缩略图。
4. 点击“在工作台审核图片 N”，进入既有编辑审核流程。此次扫描保留固定结果，审核变化不会自动删除候选。
5. 可从会话下拉框或任务页找回结果；“释放扫描结果”只释放临时结果。没有“一键删除相似图”。

CLI 可用现有 `api POST ... --json-file <请求文件> --wait`，其中 status_url 为扫描资源；GET 同一路径继续分页。请求示例：

```json
{"scope":{"filter":{"review_statuses":["keep","unreviewed"]}},"threshold":6}
```

示例中的 6 只是显式调用示例，不是产品默认或推荐删除标准。

## 验证与容量检查

新增 `test_phash.py` 12 项与 `test_api_duplicates.py` 12 项，覆盖 golden、输入/版本拒绝、EXIF/白底/首帧、汉明极值、稳定排序与非传递、取消、入库/NULL 警告/收据恢复、范围与阈值、缺失/坏 hash 跳过、快照稳定、幂等/游标隔离、CAS 释放、会话上限/过期、项目关闭清理、结果容量与损坏。测试明确比较扫描前后的图片记录、jobs 数量、原图 SHA；近似距离 0 的不同字节图片仍各自入库。

`scripts/benchmark_duplicates.py` 是可复现合成容量检查。本机 10,000 个随机指纹、threshold=0 共 49,995,000 次比对，约 **2.075 秒**；10,000 个相同指纹、threshold=64 在累计 4,188,194 对后下一行超过 64 MiB，约 **12.466 秒**明确失败，临时结果已清理。日志 `.test-tmp/f08-capacity.log`，结构化结果 `f08-capacity.json`。

这些数字不是万张真实图的导入或图像解码吞吐：稀疏测试只测指纹比较，密集测试复用一个小文件路径测检查、写桶与上限清理。没有声称所有输入、硬盘或内存配置均相同性能。
