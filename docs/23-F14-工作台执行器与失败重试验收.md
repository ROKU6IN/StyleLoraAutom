# F14 工作台执行器与失败重试验收

版本 0.16.0，2026-10-26。依据 `F14-前端设计.md` §3.7、F08/F12 执行器与 F11/F14 API 合同，接续 0.15.0 组合批次阶段。本轮只在本地开发、构建和验证，没有初始化 Git、提交、推送或发布；没有使用真实供应商凭据、发送真实素材或执行付费 LLM 请求。

## 本阶段实现

| 入口/模块 | 行为 |
|---|---|
| 工作台“执行器批次” | 右侧非模态面板，复用统一批次的模型、范围、预览、确认及进度组件；网格仍可交互 |
| 工作台状态栏 | 关闭面板后保留本批次状态和计数，可再次打开；关闭不会暂停或取消后台任务 |
| 范围三选项 | 当前筛选未覆盖、当前筛选全部重跑、工作台选中；显示服务端候选数量，当前选项显示逐阶段缓存估算 |
| 完整筛选选择 | 来源、审核、评级、标签包含搜索、文件缺失；支持全选时保存的条件，不用浏览器已加载页冒充全集 |
| 任务失败列表 | 点击失败图片计数，服务端按 kind=failed 分页，可返回全部结果 |
| “仅重跑失败项” | 先预览失败数量、执行器和冻结模型，再确认创建新单阶段任务；保留原任务和结果 |

面板覆盖原详情栏，详情组件保留并设 inert，避免隐藏编辑器接收焦点；打开前沿用工作台草稿门禁，在面板内按 Escape 或点击关闭恢复入口焦点。网格快捷键仍可用，面板输入不触发审图快捷键。创建后切到批次进度，支持原有暂停/继续/取消。当前批次 ID 放在工作台 URL 的 executor_batch 参数中，不覆盖来源、搜索等筛选参数。

## 范围和兼容性

`JobFilter` / DAL `ImageFilter` 增加可选 rating、file_missing、q。标签搜索与工作台调用同一个 SQL 构造函数，搜索所有 current tags 层；不扩展为全文自然语言搜索。评级列表和已有来源/审核列表保持字段内 OR、字段间 AND，搜索使用参数绑定。q 最多 4096 字符，评级只接受既有四种枚举。

mode 与范围选择器分开：mode=selected/uncovered/all 决定缓存策略，scope 的 selected_ids/filter 决定候选成员。新增 selected+filter 支持“全选筛选结果”；all+selected_ids 支持对确定失败 ID 强制重跑。scope 仍恰好二选一，单次最多 5000 张。普通当前筛选缺少显式审核条件时默认排除 reject；用户已明确全选的筛选全集则忠实保留选择时包含的审核状态。其它筛选变化不改这份选择。

后台在创建事务中完整解析过滤条件、核对 scope_digest、冻结两阶段同一有序范围。预览后新增图片、修改评级或标签而导致成员变化时拒绝旧预览。冻结后的任务不随筛选变化扩大范围。缺失文件仍以 skipped/file_missing 记账，不做推理。旧筛选没有使用新增字段时，序列化省略其默认 null，旧任务 scope_json 和请求重放身份保持兼容。没有新增数据库表、SQL 列或迁移。

搜索输入的防抖尚未应用时，暂停“全选筛选结果”、打开执行器及启动新批次，避免刚输入条件却捕获旧筛选。已打开面板保留表单，条件应用后恢复预览和启动。空筛选结果时网格区域仍占据剩余宽度，详情栏及执行器面板贴齐右侧；浏览器测试核对面板不遮挡网格。

覆盖预览、暂停及整批接续沿用 0.15.0 合同：预览不推理、不调用 R5、不写评级；WD 待执行时视觉计数为等待 WD 决定；大批量、重叠范围和全部重跑保留原确认门禁。范围选项显示的是候选数，不能当成实际 LLM 计费调用次数。

## 失败重试合同

重试只读取 source job 的持久 outcome.kind=failed；不包含成功、跳过或尚未派发的图片。原组合批次必须所有阶段均终结，避免修改 WD 输入时与原 LLM 阶段继续运行。前序取消但后序仍 pending 时，需先取消剩余阶段。

只读预览返回 source_job_id、executor、image_count、model、mode=all、available/reason、preview_digest。模型、角色、模板、运行时等恢复依赖按原任务冻结配置核验，不静默改用当前新配置。客户端只能提交新 batch_id 和预览摘要，不能覆盖失败 ID、配置或模型。创建事务再次核对来源状态及摘要；冻结或写入失败整次回滚。

新任务是原执行器的单阶段 all job，明确 ID 范围、强制忽略旧缓存，params.retry_origin 记录来源 job 与预览摘要。原失败记录、计数、历史标注及其它阶段的任务记录保留；新结果按原规则追加版本并更新当前层。WD 重试完成后不会自动重跑之前完成的 LLM。LLM 继续执行成组 tags/nl 写入和评级/证据 CAS，可能再次产生费用。

未知提交可用相同 batch_id 查证/重放；相同来源和摘要返回已有 job，不重复创建。已经存在的重试任务可在依赖暂时移除后只读重放；新建仍要求冻结依赖可用。界面重复确认同一次未知结果使用同一 batch_id。进程崩溃前尚未提交的供应商结果仍不保证供应商侧不重复计费。

## API

| 方法与路径（P=`/api/projects/{pid}`） | 行为 |
|---|---|
| POST `P/jobs/preview`、`P/jobs/batches` | 接受扩展过滤条件和正交的 mode/scope，沿用范围摘要校验 |
| GET `P/jobs/{job_id}/outcomes?kind=failed` | 复用既有失败结果分页，界面新增可见入口 |
| GET `P/jobs/{job_id}/retry-preview` | 只读预览失败集合和原配置可用性，不创建任务 |
| POST `P/jobs/{job_id}/retry` | batch_id/preview_digest →202；返回 batch_url、items 和既有 task/status_url |

新增错误：job:retry_not_ready、job:no_failed_images、job:retry_stale；依赖错误复用原错误码。沿用鉴权、Origin 校验、幂等键、严格输入 schema。重试读的是已终结任务，摘要同时包含来源配置、失败 ID 和父批次状态；不通过前端分页收集结果决定服务端范围。
