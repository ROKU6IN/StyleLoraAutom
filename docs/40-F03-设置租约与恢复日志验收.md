# F03 设置租约与恢复日志验收

日期：2026-10-27；版本：0.33.0。依据 F02–F05 §4、T08–T10 与 Q03。本轮仅本地实现、测试和打包，未初始化、提交或上传 Git。

## 已实现范围

新增 `generation/settings.py`，由 Runtime 持有唯一 `SettingsLeases`。内部入口包括 acquire、verify_effective、mark_inflight、settle_inflight、reconcile、restore；底层 `SettingsAdapter` 是待真实契约审核后实现的注入协议。当前仅测试夹具实现此协议，生产 generation=false，未调用真实 Launcher，也未发送生成或付费请求。

同一 Launcher 的租约跨来源、项目和事件循环互斥；单次操作使用非阻塞线程锁，已持有租约或存在恢复记录时不能另开来源。依赖既有产品单实例进程锁，不把本文件的进程内锁宣称为跨进程文件锁。生产生成源预检读取屏障，但尚未把租约、费用、prepare、派发和 finally 恢复串成真实 runner。

每周期重新读取当前设置，冻结 original/desired、项目/来源/周期、租约标识及后端身份。身份含适配器提供的实例指纹、契约摘要及可写字段集合；仅 PID、重新连接成功或版本字符串相同不足以沿用。身份变化拒绝恢复，不能向新的实例回放旧设置。

可写键限于 model、effort、sampler、steps、scale、cfg_rescale、noise_schedule、quality_toggle、uc_preset、smea、smea_dyn、variety_plus、decrisp，具体集合由已审核适配器声明。只保留简单 JSON 值；页面 prompt、token、角色、只读派生字段不入快照。请求的 quality_toggle 只能为 false、uc_preset 只能为 null；未来完整 profile/适配器必须保证固定项都包含并满足，核心不补造缺少的后端参数。one-shot 提示词与尺寸仍不写回页面。

## 持久化与操作时序

默认日志为 `%LOCALAPPDATA%/StyleLoraAutom/recovery/launcher/settings-lease.json`。显式独立产品目录的服务使用其 `private/recovery/launcher/`；直接注入 Runtime 的测试可指定独立目录或使用内存。该日志属于产品私有恢复证据，不放入项目 config_json 或 SQLite，不增加表/列。不要手工删除或编辑恢复日志。

日志带 schema_version=1、revision 和规范 JSON SHA-256，最多 64 KiB，严格拒绝重复键、非法形状、非有限数值、路径重解析点及损坏摘要。摘要用于检测损坏，不证明远端归属。写入前核对旧版本，同目录原子替换；替换后报错会回读验证已保存版本，无法确认则保持未知结果。解除租约写 record=null 的新修订，不删除文件。当前进程仍持有租约时，文件丢失或被替换不能解除屏障；跨进程恢复依赖持久记录，无法从被人为删除的文件重建证据。

| 阶段 | 含义与下一步 |
|---|---|
| applying | 已持久保存原值、目标值和写入操作号；应用结果未确认，不重发 |
| applied | 应用完成且可继续验证；prepare 有效回显必须完整、值和类型匹配，包括显式 null |
| restoring | 已持久保存恢复写意图；结果未知时只允许核查 |
| needs_restore | 已知写操作结清，仍有本次改动待恢复 |
| conflict | 外部改动、回显漂移或原子前置条件失败；保留记录和阻塞 |
| idle / invalid | 无待处理记录 / 无法可靠读取记录；invalid 阻止新来源但允许查看项目 |

apply 和 restore 均先落盘再调用适配器。写入丢失回包、超时、取消或执行结果异常，保留已落盘意图；不会因没有返回 lease_id 丢失恢复信息。读取操作失败不会触发任何补写，取消同样不能让下一来源绕过记录。

未知写的 reconciliation 先要求 `settings_write_settled(operation_id) is True`，证明精确对应操作已经结清、不会迟到生效，再读取当前值。读取到 original 也不构成写入尚未执行且永不执行的证据；recent 缺条目、取消通知成功和普通 timeout 均不能替代。探测异常或真值但非 bool True 不解除屏障。reconcile 对远端只读，绝不重放 update。

派发前需先持久标记精确 attempt 的操作摘要；在途结果未决时拒绝 restore/reconcile。只有 `generation_settled(operation_key) is True` 才能清标记，再按正常流程恢复。重建管理器后保留该限制。完整 runner 尚未连接此入口，不声称停止按钮现在已经完成真实设置恢复。

## 外部修改保护

只处理 original 与 desired 不同的可写键。当前值已是 original 就跳过；仍是 desired 才列入恢复补丁；出现第三种值则整次恢复报 conflict，不部分覆盖。未改过的字段即使被外部修改也保留。值比较严格区分 bool、int、float，不能把 true 当作 1。成功写入后再次读取验证，未证实恢复成功就保留记录。

单纯“先读再写”仍存在竞争窗口。内部更新协议因此要求 `update_settings(values, operation_id, expected=...)` 在实际修改边界原子比较待改键的预期值：期间发生变化必须整批拒绝，且没有写入副作用；适配器仅在能够证明这一点时抛 `SettingsWriteConflict`。一般异常保持 unknown，不能归类为确定拒绝。本地互斥锁只协调本产品调用，不能代替外部页面的原子保护。

该协议不是已验证的 Launcher MCP 入参，也未向真实工具添加 expected 字段。后续必须审核真实 Launcher 是否提供等效机制及权威结清证据；若缺少，继续禁用真实设置写入，不能降级成先 GET 后无条件 update。effort 锁定规则、prepare 响应及实例身份也须由真实 fixture 验证，核心不臆造有效值或修改冻结 profile 迎合漂移。

## HTTP 与页面

新增 `GET /api/backends/nai_launcher/settings-lease`，无查询参数、不要求打开项目、沿用会话认证及 Host/Origin 约束。仅返回 blocked、phase、reason、inflight、revision、version、source_id、changed_keys、recovery_adapter_available；不返回快照值、后端指纹、完整操作号、路径或凭据。日志缺失时读取不创建目录/文件，损坏时保留原字节并返回 blocked=true。读取不调用任何适配器。

“Launcher / MCP”页面展示中文原因、来源号和本次改动字段。三秒轮询与 backend.changed 事件只刷新查询，页面重开仍从服务读取记录；请求失败时不继续展示旧的正常状态。没有恢复、删除日志或强制解锁按钮；recovery_adapter_available 固定 false。已有项目查看、标注与导出不被设置日志损坏阻断。
