# F11 提示词任务 CLI 验收

日期：2026-10-28；版本：0.45.0。只在本地开发，不初始化、提交或上传 Git，不调用真实生成服务。

## 本轮范围

接续 0.44.0 标注任务 CLI，实现 F11 §9 的 prompt preview/run/list/status/pause/resume/cancel/outcomes/seeds。通过已有产品级 PromptProduction HTTP 服务执行覆盖采样或精修，输出已就绪任务的内容 seeds。不要求打开项目；不写项目 SQLite、来源引用、图片或标注，不直接调用 LLM。

preview 接受 SamplingRequest JSON，run 的 --spec 接受保存的预览计划，并要求确认摘要。这是对原 --spec FILE 入口的分阶段细化：服务预览固定随机种子、词典/策略/角色等快照摘要，CLI 再固定 task_id 和请求键；提交前配置变化、响应丢失或重复执行都能明确处理。

## 使用流程

先在一个终端持续运行 `./scripts/run.ps1 serve --no-browser`。在工作台维护词典；词典编号也可通过 `./scripts/run.ps1 api GET /api/prompt-production/dictionaries` 查询。命令不创建词典、不配置密钥或自动拉起服务。

下面是纯本地词典抽样的 `sampling.json`。替换为实际的 prompts 词典编号；该示例关闭覆盖矩阵和 LLM 精修，要求至少 10 条满足既有内容围栏的可用候选：

```json
{
  "prompt_dictionary_ids": ["<existing_prompt_dictionary_uuid>"],
  "coverage_enabled": false,
  "optimize": false,
  "plan": {"target_count": 10, "random_seed": 42}
}
```

特征词典使用 feature_dictionary_ids。覆盖矩阵、配额、排除条件、source_weights、options、fence、optimize 和 append_target_id 沿用既有 SamplingRequest；未知字段或密钥字段拒绝。optimize / use_rating_model 运行时可能调用配置的 LLM；append_target_id 可启用既有自动追加行为，因此应审核预览中的 refinement 和目标词典信息。CLI 不扩大这些服务能力或绕过内容围栏。

保存预览并查看，保留原始 JSON 文本，避免重新序列化大整数随机种子：

```powershell
$previewLines = ./scripts/run.ps1 prompt preview --spec .\sampling.json
$previewExit = $LASTEXITCODE
if ($previewExit -notin @(0, 6)) { throw '预览失败，请查看返回错误' }
$previewText = $previewLines -join [Environment]::NewLine
$planFile = Join-Path (Get-Location) 'prompt-plan.json'
[IO.File]::WriteAllText($planFile, $previewText, [Text.UTF8Encoding]::new($false))
$preview = $previewText | ConvertFrom-Json
$preview.plan.preview | ConvertTo-Json -Depth 30
$preview.confirmation_digest
```

预览退出 6 表示当前 ready=false，仍保留可审核计划；可以先调整输入再预览，也可以明确运行以获得部分结果/诊断。审核后使用显示的确认摘要：

```powershell
./scripts/run.ps1 prompt run --spec .\prompt-plan.json --confirm-digest <confirmation_digest> --detach
./scripts/run.ps1 prompt list --limit 20
./scripts/run.ps1 prompt status <task_id> --wait
./scripts/run.ps1 prompt outcomes <task_id> --limit 50
./scripts/run.ps1 prompt pause <task_id>
./scripts/run.ps1 prompt resume <task_id>
./scripts/run.ps1 prompt cancel <task_id>
# 先审核 status 返回的 ready 和 revision，再导出内容
./scripts/run.ps1 prompt seeds <task_id> --expected-revision <revision>
```

run/resume 默认等待完成；--detach 返回已受理/恢复状态。run 输出 status=accepted 和服务当时的 task_status，不把 202 冒充完成。status 默认读取一次，--wait 等到终态或暂停/带诊断的 pending。Ctrl+C 退出 130，仅停止客户端等待，服务中已受理的任务继续。

## 计划和产品边界

所有命令通过当前用户 ACL 管道附着服务，使用回环 Bearer HTTP、关闭环境代理与重定向。没有 --project/--project-id、路径 grant、独立执行或自动安装参数，不改变当前项目。status/list 发出 GET；服务内部仍沿用已有的中断/待提交结果处理，不把这些 GET 宣称为严格磁盘只读诊断。

preview 调用 coverage/preview，不创建持久任务、不发 LLM 请求；服务可能保留可过期的覆盖明细预览。输入 random_seed 为空时，使用服务返回的确定种子，不能在 run 时再随机一次。CLI 计划包含 schema_version=1、instance_id、idempotency_key、body（TaskCreate）和完整 preview；SHA-256 confirmation_digest 覆盖整个计划。计划内容变化、配置与预览不一致、请求对象未知字段或错误摘要在附着前拒绝。

原始 spec 与保存的计划均采用严格 UTF-8（允许 BOM），上限 16 MiB；拒绝重复键、非有限数字及错误类型。成功预览的完整格式化输出也检查同一上限，过大返回 prompt:plan_too_large，避免输出不能由 run 读取的计划。Launcher 的 live_features/launcher_selection 当前未实现，在发送 HTTP 前拒绝，不将开放字典字段中的内容回显为请求收据。

确认摘要是客户端计划一致性检查，不是服务签名或费用担保。服务创建时重新计算既有快照摘要：词典、目录资料、策略或依赖变化可能返回 prompt:preview_stale，CLI 不自动刷新并继续。预览中可能显示的精修调用上界并不保证实际质量或费用。

## 状态、控制与未知结果

任务使用持久 task_id，控制使用 JSON 中的 expected_revision，沿用现有 Prompt API，未新增 If-Match 合同。pause/resume/cancel 默认先读取当前修订号，再提交一次控制；冲突立即返回，不捕获新修订号强行重试。服务已有“当前状态已是目标状态则无变化返回”的语义保留，不把该幂等 no-op 宣称为修改成功或新增修订。

控制成功不表示所有在途线程已经退出；继续和取消的在途结果处理保持现有冻结、generation 和 LLM 未知结果合同。终态任务不能通过 resume 重跑，需要新计划。控制未知时先读 status，再决定是否使用原 task_id、action、expected_revision 和请求键明确重放：

```powershell
./scripts/run.ps1 prompt pause <task_id> --expected-revision <original_revision> --instance-id <original_instance_id> --idempotency-key <original_key>
```

指定控制请求键时必须同时指定原实例和修订号，重放阶段不重新读版本。创建 run 在发 POST 前记录 cli.task_id/status_url/request；超时、重定向、无效受理内容或中断均保留身份，不自动重试。重复使用同一计划保留 task_id 和请求键；服务返回原任务，不自动恢复已暂停/取消任务，也不会从已清理任务的墓碑重新创建。

当前 CLI 拒绝跨服务实例执行旧 run 计划，即使服务本身保留了持久创建收据。重启后应使用原 task_id 只读查询产品任务；需要继续暂停任务时，根据新状态明确 resume。列表和 outcomes 使用既有版本绑定游标，内容变化可能返回 page:stale；CLI 不自动翻页、重启分页或合并不同时点结果。

stdout 默认为单个 JSON，--json 可省略；进度和中断提示写 stderr。除 seeds 成功输出外，结果附 cli 诊断和请求身份，不含 Bearer token、密钥正文或文件绝对路径。任务正常内容、标签和元数据仍会返回。

## seeds 内容投影

seeds 必须传入已审核的 expected_revision；服务拒绝修订变化或 ready=false，不返回半套 seeds。CLI 校验数量、连续 seq、内容字段和摘要后才输出成功结果：

```json
{
  "digest": "<sha256_of_items>",
  "count": 1,
  "items": [{"seq": 1, "prompt": "no humans, forest", "aspect": "landscape"}]
}
```

每个 item 只含 seq、prompt、aspect（可为 null）。成功 stdout 不附 cli、task_id、dictionary_id、project_id 或 source_id；没有自动创建项目/来源或写回引用，也没有直接启动生成。失败输出仍为错误 JSON，保存输出时应先检查退出码，不能把错误对象作为 seeds 使用。具体项目接入继续使用既有内容交接流程。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 查询/导出成功；任务已 done 且 ready 且无所列部分失败；--detach 已受理；控制已达到目标状态 |
| 2 | 参数、文件、计划、配置或内容格式不合法/过大 |
| 3 | 无运行实例或认证不可用 |
| 4 | 实例、修订、状态或预览冲突；任务删除；seeds 未就绪；分页过期 |
| 5 | 依赖/I/O/查询失败、无效响应或任务级失败 |
| 6 | preview ready=false；或 done 但未 ready、存在 failed/review_required 候选、自动追加失败。保留覆盖、进度和原因，不冒充完整成功 |
| 7 | 未完成的一次查询、暂停、取消、待处理诊断或请求结果未知 |
| 130 | 客户端中断，未隐式取消后台工作 |

list/outcomes 的 0 仅表示该页读取成功。pause/cancel 的 0 表示该控制目标已经达到；status 看到 paused/canceled 则返回 7。ready seeds 与任务候选诊断是不同范围：任务已 ready 但某些被补位候选失败时，run/status 可返回 6，seeds 仍可按修订号导出完整已选择内容。
