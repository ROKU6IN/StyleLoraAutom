# F02 直连未知请求人工处置验收

版本：0.57.0；日期：2026-10-29。

## 范围与用户操作

实现 F02 的“无法证明上游结果时保留现场，提示人工处理”下一步：用户可以决定结束此来源并留下持久记录，避免把暂停误认为已经结清。仅用于 NovelAI 直连来源；不连接 Launcher 或 NovelAI，不读取 Token，不调用模型。

在“来源与导入”选择已有直连来源，进入“生成恢复与对账 → 未知请求人工处置”。核对来源、未知请求与未提交数量，点击“核对并结束此来源”；同时确认停止来源和未知扣费后长按一秒。来源变为 canceled，不能继续，未提交项保留 pending。未知项仍为 sent，attempts 不变，没有自动或手动重发。既有图片、费用、响应/intent 和未认领文件全部保留。

这份决定不证明上游未执行、已完成、已退款或收费为零。没有可信上游结果查询时不能核销 unknown；本阶段不实现人工认领图片、外部结清凭据导入、复制剩余 seeds、强制 failed 或购买新 attempt。真实账户生成与账单验收仍待完成。

## HTTP 与证据约束

`GET /api/projects/{project_id}/sources/{source_id}/unknown-disposition` 只读取本地状态。返回 source_status、unknown_count（当前 sent 数）、pending_count、最多 100 条未知尝试摘要、items_truncated、busy、reason、can_stop、decision、upstream_outcome 与 version。不输出提示词、Token、绝对路径或完整费用凭据。来源最多核对 10000 项，超出明确拒绝。

同路径 POST 要求现有鉴权、有效项目句柄、Idempotency-Key 与 If-Match，正文严格为：

```json
{"confirm_stop_source": true, "acknowledge_unknown_charge": true}
```

必须有 sent，所有 sent 都具有绑定到当前 source/item/attempt 的 intent 与费用凭据；有完整 response 时应先走既有条目核查入库，缺失/损坏/错配凭据拒绝决定。来源须 paused 或 canceled，直连 runner 与恢复任务必须空闲，项目不能关闭或排空。新请求使用当前摘要版本；旧版本、额外字段和非严格 true 确认均被拒绝。

POST 返回当前摘要（200），同步写入本地记录，不新建后台生成任务。结束仅复用 F01 的来源状态迁移，不修改数据库结构、条目、attempts 或费用。不同并发请求串行审核，同一 Idempotency-Key 可重放原结果；已完成记录在当前版本下重复确认也不会创建第二份决定。

## 持久记录与中断恢复

路径为项目相对的 `images/.nai-direct/reviews/<source_id>.json`。记录包含 schema_version、source_id、随机 decision_id、固定 action=stop_source_preserve_unknown、phase、依据摘要、两项数量与 UTC 时间；外层包含内容摘要。8 KiB 上限、严格字段/类型/摘要检查，沿用项目路径保护与原子文件写入；摘要用于完整性与绑定，不是外部签名或上游证明。

依据摘要绑定来源创建时间、锁定配置、全部条目投影及未知请求的 intent/费用凭据。生成协调锁内审核版本并保存 prepared；写队列事务内再次核对数据库与文件依据，通过后取消来源并终止运行费用周期；最后保存 completed。持久化异常按 outcome=unknown 报告，不据异常推断某一步未发生。

| 中断位置 | 重新读取的状态 | 明确后续操作 |
| --- | --- | --- |
| prepared 保存前失败 | 原来源与无决定 | 核对新摘要后重新确认 |
| prepared 保存后 | 原来源、prepared | GET 不推进；明确确认完成原 decision_id |
| 来源已 canceled，completed 未写 | canceled、prepared | 明确确认补完同一记录，不重发生成 |
| completed 已保存但响应丢失 | canceled、completed | 显示既有决定，不要求重复结束 |
| 记录损坏或依据变化 | 保留文件与来源现场，阻止操作 | 不自动修复或覆盖记录 |

浏览器定期只读刷新证据，确认对话框绑定打开时版本，证据变化立即阻止长按提交。写结果未知后保持禁止重复提交；自动轮询不会解除该状态，需点击“重新读取处置记录”成功后再明确核对。重开项目/页面仍可读取同一决定。prepared 和 completed 均不是“上游结清”。
