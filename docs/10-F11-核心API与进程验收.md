# F11 核心 API、进程管理与后台任务

日期：2026-10-25；包版本 0.3.0，项目数据库保持 schema v1、原有八张表。按本轮要求只在本地开发，没有初始化、提交或上传 Git。

本轮依据《05-项目结构与数据模型》和《F11-F14-API与进程设计》实现支持现有数据集闭环的核心子集。会话能力标识为 `api_scope=f11-core-v1`；不将设计文档的全部 142 个接口视为已完成。

## 启动与使用

依赖已配置在项目 .venv，PowerShell 脚本优先使用它。实际验证环境：Windows、Python 3.12.14、SQLite 3.53.1、Pillow 12.3.0、FastAPI 0.162.0、Uvicorn 0.54.0、httpx 0.28.1。

```powershell
# 窗口一：前台运行服务，退出前会等待已接受的工作
./scripts/run.ps1 serve --no-browser

# 也可以启动时打开已有项目；同一实例只打开一个可写项目
./scripts/run.ps1 serve --project ./existing.slproj --no-browser

# 窗口二：读取会话与当前项目
./scripts/run.ps1 api GET /api/session
./scripts/run.ps1 api GET /api/projects/current
```

默认只绑定 `127.0.0.1:0`，由操作系统分配端口；同一个已绑定 socket 直接交给 Uvicorn。`--port` 可指定端口；占用时明确失败。只能一个 worker，不允许 reload 或监听公网。再次运行 serve 会附着已运行实例；要切换该实例的项目，应使用 `/api/projects/open`。

默认定位文件是 `%LOCALAPPDATA%/StyleLoraAutom/runtime/instance.json`，只含 PID、实例 UUID、端口、协议版本和管道名。测试使用 `--runtime-dir` 指向仓库临时目录。定位文件不是认证依据，CLI 连接当前用户的命名管道取得本次服务凭据。

### 可直接运行的完整示例

先启动一个没有打开项目的服务，然后执行：

```powershell
./scripts/http-demo.ps1 -Output .
```

脚本在指定的已有父目录中新建唯一的 `http-demo-<时间>-<随机后缀>` 目录，生成两张合成 PNG 和同名 txt，通过本地管道授权项目目标及素材目录，随后所有业务操作经 HTTP 完成：创建 → 导入预览 → 后台导入 → 读取完整标注读集 → 编辑标签/描述 → keep 审核 → 导出预览 → 后台导出 → 核对 txt 内容。完成后输出项目与导出目录、图片数量、export_id；项目保持打开，演示文件保留供检查。已有打开项目时明确停止，不替用户关闭或切换项目。

对应源码为 `scripts/http_demo.py`；真实进程测试实际运行该脚本并核对导出结果。

### 手工提交业务请求

`grant` 接受用户在本机明确输入的路径，只返回不含绝对路径的短期授权。

```powershell
# 父目录须存在，目标项目目录须不存在
./scripts/run.ps1 grant project_create ./new.slproj

# 将上一步 grant_id 写入 create.json，例如：
# {"grant_id":"返回的 UUID","name":"本地项目","trigger_word":"my_style"}
./scripts/run.ps1 api POST /api/projects --json-file ./create.json --wait

# 使用创建结果中的 project_id 授权外部素材目录
./scripts/run.ps1 grant import_root ./input --project-id <project_id>
```

然后按示例脚本的请求顺序调用。`api` 自动为 POST/PUT/PATCH 生成 UUID 请求键，也可用 `--idempotency-key` 指定；不会自动重发写请求。更新或控制操作用 `--if-match <version>`。`--wait` 轮询 202 的 status_url；Ctrl+C 只中断客户端等待，不自动取消服务任务。取消使用对应 operation/source/export 的明确控制接口。

退出服务：

```powershell
$session = ./scripts/run.ps1 api GET /api/session | ConvertFrom-Json
./scripts/run.ps1 api POST /api/session/shutdown --if-match $session.version
```

shutdown 返回退出意图后服务结束，不使用 `--wait` 等待一个已经退出的 HTTP 端点。旧离线 CLI 保留；除只读 info/check 外，在服务运行时拒绝启动第二个可写项目进程，并提示使用 api。

新运行时 CLI 的退出码：0 成功；2 输入不合法；3 连接/认证不可用；4 冲突；5 整体操作或 I/O 失败；6 部分失败；7 取消、中断或仍有待处理项；130 客户端中断。旧离线命令仍保留原来的退出码。

## 已实现的 HTTP 范围

以 `P=/api/projects/{project_id}` 表示当前项目。以下分组包含 41 个方法/路径，其中原生目录选择器明确返回 501；以受保护的 `GET /api/openapi.json` 及源码为实际请求合同。

| 分组 | 方法与路径 | 说明 |
|---|---|---|
| 会话 | GET /api/session；POST /api/session/bootstrap、/shutdown | 能力、一次性引导和退出意图 |
| 文件授权 | POST /api/filesystem/grants；DELETE /api/filesystem/grants/{grant_id} | 原生选择器暂不可用；CLI 管道授权，HTTP 可撤销 |
| 后台任务 | GET /api/operations/{operation_id}；POST 同路径 /cancel | 登记后返回 202，轮询结果与取消 |
| 事件 | GET /api/events | 唯一 SSE 通道，按主题、项目、资源筛选 |
| 项目 | GET /api/projects/current；POST /api/projects、/api/projects/open；GET/PATCH P；POST P/close；GET P/recovery | 单项目生命周期、元数据 CAS、恢复摘要 |
| 图片 | GET P/images、P/images/{image_id}、同路径 /content、/thumbnail；POST P/images/review | 筛选/游标/定位、媒体、批量审核 |
| 标注 | GET P/annotations/{image_id}；PUT 同路径 /manual；POST P/annotations/manual/bulk | 完整读集、单张标签＋描述、批量增删 |
| 导入源 | GET P/sources、P/sources/{source_id}、同路径 /items；POST 同路径 /control、/import-root；GET P/imports/{source_id}/summary | 暂停、继续、取消及重启后的根目录重授权 |
| 方案与能力 | GET P/import-schemes、P/export-schemes、/api/exchange/capabilities | 默认方案读取与已支持能力 |
| 导入 | POST P/imports/preview、P/imports | 冻结清单与后台导入 |
| 导出 | POST P/exports/preview、P/exports；GET P/exports、P/exports/{export_id}、同路径 /report；POST 同路径 /cancel | 冻结快照、后台导出、报告和中断记录 |
| 接口定义 | GET /api/openapi.json | 仅包含当前实现；声明 Bearer 鉴权 |

读/更新返回 200；长任务在登记后返回 202、Location、Retry-After。更新使用 ETag/If-Match，缺少必要版本返回 428，过期返回 409。所有 JSON 错误使用统一 error 信封，未知提交结果指示先核查而非重试；不返回 SQL、堆栈、外部绝对目录或凭据。

图片列表默认 50、最大 1,000；支持 source_id、review_status、rating、file_missing、标签 q、id/-id 排序和 around_id。游标签名绑定项目、筛选、排序及本次上界，不提供 offset。批量编辑/审核最多 5,000 张，通过逐图 expected_versions；人工编辑还必须提交完整 read_set，包括不存在的标注层引用。审核版本包含会话递增计数，A→B→A 不会复用旧版本。编辑响应取自本次写事务，避免把其它并发编辑的新版本误当成自己的结果。

## 运行与恢复保证

- Windows 当前 SID 专属互斥锁保证单实例；命名管道使用仅当前 SID 的受保护 DACL，并核对对端进程用户身份。会话 token 随启动轮换，仅在内存/可信管道/HTTP 请求头中使用，不进入定位文件、命令行参数或服务日志。
- 浏览器引导链接的 code 放 URL fragment，兑换前立即从地址栏移除；60 秒有效、单次、绑定精确 Origin。接口、原图、缩略图和 SSE 全部要求 Bearer，Host 和 Origin 严格校验。开发只允许一个显式 `http://127.0.0.1:<port>` Origin。静态会话壳不含业务数据。
- HTTP 只接项目/图片/方案 ID 和授权句柄。项目创建、项目打开、导入根三类授权区分用途，绑定项目代次和 15 分钟有效期；活动任务持租约，使用中撤销返回 409。失效/撤销阻止后续使用，已接受的文件操作安全收尾。
- Supervisor 维护两条文件执行线程、一条生命周期控制线程、最多 32 个未完成任务；HTTP 适配工作有独立有界入口。扫描、复制、图片编码、预览和导出不占事件循环，不把这些辅助任务写入 F01 jobs 表，也不使用 FastAPI BackgroundTasks 承载长任务。
- 客户端断开不会撤销已经接受的工作；项目关闭/切换停止新派发并等待租约、请求和文件线程，随后排空 F01 写队列、checkpoint 并释放项目锁。shutdown 默认 HTTP 宽限 30 秒，允许请求更短宽限；文件工作未退出时仍等待，不能因超时释放正在使用的项目锁。
- 项目每次重新打开得到新 UUID。旧句柄、预览、游标、项目授权和绑定任务查询失效；切换新项目失败保持无打开项目。恢复不会自动调用生成服务，也不会自动继续导入。
- 导入预览冻结 manifest；应用时重新扫描并比对，素材变化拒绝创建源。暂停允许已接受的单图登记，后续图片保持 pending；恢复时重新授权素材目录、核对冻结清单，然后显式 resume。
- 导出预览冻结方案/元数据/选图/标注摘要，正式导出拒绝过期快照。copy 模式成对生成图片/txt，整个版本目录发布后才视为 finished。正式报告持久保存 export_id；`.partial-*` 收据在重开/重启后显示 interrupted，不自动续写或冒充成品。
- SSE 仅发送已提交结果的摘要。事件有 epoch/sequence，内存环最多 10,000 条、8 MiB、10 分钟；单订阅最多 256 条/1 MiB、最多四个订阅。支持回放、过期重同步、慢消费者断开和 15 秒心跳。GET 是状态依据，通知失败不回滚已提交的数据。
- 原图读取核对存在、大小、哈希；缩略图按 EXIF 方向、白底和 WebP 256/512 编码，原子写缓存。媒体先鉴权及核对身份，再处理 If-None-Match；304 保留 ETag/私有缓存头，缺图不能被缓存命中掩盖。未实现图片清理，当前使用项目租约保护媒体读取与关闭之间的关系。

幂等键只承诺当前服务会话内相同方法/路径/正文的去重；同键不同正文返回 409。重启不恢复内存 operation、预览、授权或去重缓存。导入源、已登记图片、标注和导出报告从磁盘恢复，客户端应先查询这些证据，再决定是否重新发起操作。

## 本轮边界与下一步

以下为 0.3.0 当时的范围记录。0.4.0 已继续实现浏览器工作台、Windows 目录选择、图片统计、查询范围审核和任务列表，参见 [F14 工作台实现与验收](11-F14-工作台实现与验收.md)。

当前浏览器页面仅用于建立会话和显示连接状态，未实现 F14 素材库、标注编辑器、任务面板。原生目录选择器、产品配置/DPAPI 凭据、最近项目、清理、规则、模型 jobs、NAI、prompt tasks、全部 142 条 API 和完整前端字段合同也不在本轮范围。未实现的业务路由不伪造成功。

HTTP 导入目前支持 literal-tags-v1；完整词库适配、方案编辑、失败项单独重试接口和查询范围批量编辑留待后续。已有离线 CLI 的词库及 --retry-failed 能力保留，须先停止服务。HTTP 恢复只继续 pending 项，不自动把 failed 项变成新 attempt。

完整 CLI 产品命令仍需后续统一成自动附着的语义命令；本轮提供通用 `api`、`grant`、`serve`、`ui` 入口和旧命令互斥保护。下一步可基于本轮 HTTP 合同实现 F14 的项目页、图片列表、标注编辑、审核与导出任务面板，再逐项扩充 F11 的其余产品接口。
