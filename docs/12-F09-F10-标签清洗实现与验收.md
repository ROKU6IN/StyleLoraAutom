## 数据与执行语义

产品资料放在 `%APPDATA%/StyleLoraAutom/tagging/tagging-library.json`。`serve --product-dir <目录>` 可使用独立资料目录；指定测试 runtime-dir 时默认隔离到其 product 子目录。库默认空，不自动下载外部词库。项目 schema 仍为 v1、八张表。

实现采用一个版本化产品信封原子替换，同时保存标签、别名、翻译、规则和请求去重凭据，保证别名与翻译不会跨文件半提交。文件写入先 flush/fsync，再 os.replace；格式损坏时拒绝加载，保留原文件。运行时使用锁和版本前置条件串行更新。资料只应通过服务修改；不支持服务运行期间从外部直接编辑该文件。

标签仍按 F01 的 trim/lower/下划线转空格规范化，不折叠内部空白、不做 NFKC。更换词库不会重新解释已有 annotations。中文只作显示辅助。词库只有局部覆盖时，未命中不等于非法；文件声明完整库时明确标为“导入文件声明”，不冒充外部核验。

条件只读 original/tags：该行即使为空也不退到 WD；缺少该行才读 WD，仍无 WD 则有条件规则不满足。删除读有效全层视图、不套导出阈值；删除成功才判断写入。write/all 要求删除后的集合完全没有写入列表，失败只跳过写入，已成功删除仍保留；write/any 补所有缺失。删除再加回同一标签且无语义变化时不写新快照/日志。未修改标签的来源和模型置信度沿用 F01 证据元数据。

`selected_ids` 与 `filter` 互斥。查询规则默认排除 reject，显式选中或指定 reject 过滤可包含它。浏览器“全选筛选结果”保存过滤条件，预览时物化全量 IDs；新增图片不会加入已生成的预览。每个候选冻结八个 current/缺失引用（五个 tags 层和三个 NL 层），包括未命中规则的图片。预览最多 5000 张、计划 16 MiB，15 分钟有效。示例只显示前 100 张，提交使用完整计划。

批量人工编辑和规则应用分别通过一个 F01 writer 事务完成；任一候选版本过期整批拒绝。规则原子写完整 rule/tags 和一条 operation_log；零变化无日志。相同预览同进程重交复用结果。重启后项目预览失效，需要重新预览。规则撤销检查最新操作、当前/前一规则快照和后续人工/模型标注；冲突整批不撤销。审核变化不构成标注撤销冲突。修复了既有撤销冲突分支中未耗尽查询游标导致 Windows 数据库关闭失败的问题。

产品写入需要 If-Match 与 UUID Idempotency-Key，凭据与库版本一起持久保存；相同请求键/内容可在重启后复用结果，不重复迁入旧规则。凭据上限 4096，达到后明确拒绝写入而非静默丢弃去重证据。上传单文件 10 MiB，multipart 请求 11 MiB，产品库总文件 32 MiB；不使用上传文件名构造磁盘路径。前端不自动重试写请求；同一批确认按钮重试保留请求键，结果未知先查日志和数据。

## 使用与文件示例

运行 `./scripts/run.ps1 serve`。先从侧栏“本地标签库”导入资料，再到工作台选图、编辑或批量预览。未多选时，批量操作使用当前聚焦图片；全选查询的规则预览可能因默认排除剔除项而少于选择数量，确认窗口显示实际范围。批量人工编辑不进入规则撤销历史。

规范标签 JSON（整体替换）：

```json
{"schema_version":1,"kind":"tag_catalog","complete":false,"tags":[
  {"tag":"blue_hair","category":"general","aliases":["azure_hair"]},
  {"tag":"smile","category":"general","aliases":[]}
]}
```

翻译 JSON（合并）：

```json
{"blue_hair":"蓝发","smile":"微笑"}
```

也支持 `{schema_version:1,kind:"translations",entries:{...}}`，或每行两列、制表符分隔的 TSV。UTF-8 BOM 可用。JSON 重复键、别名多指向、合并后不同翻译冲突均报错。

标准规则库 JSON（整体替换）：

```json
{"schema_version":1,"kind":"replacement_rules","rules":[
  {"id":"ec135d8e-9410-43f9-b6db-416c24a98424","name":"换背景",
   "rule":{"schema_version":1,"condition":{"mode":"any","tags":["blue hair"]},
           "delete":{"mode":"any","tags":["indoors"]},
           "write":{"mode":"all","tags":["outdoors"]}}}
]}
```

TagCleaner 导入格式选择“TagCleaner 规则 JSON”：对象数组的 condition/delete/write 可为逗号串或数组，各 Mode 缺省 any。迁移只保存规则，不会直接修改图片。

## HTTP 与代码位置

`api/cleaning.py` 接入标签库、翻译、规则与日志接口；请求体声明在 `api/contracts.py`，前端规则请求类型来自生成的 OpenAPI。multipart 请求也提供 OpenAPI schema，响应 DTO 仍显式维护。

新增查询范围批量接口：`POST /api/projects/{pid}/annotations/manual/bulk/preview`、`.../apply`，保留旧 bulk 接口兼容性。新增统计：`POST /api/projects/{pid}/annotations/stats`，请求 `{scope:...}`，属于只读查询。产品更新发送 `catalog.changed`，项目标注更新发送 `annotations.changed`；前端据此刷新标签库、规则库、统计和日志。

`rules/engine.py` 只做纯计算；`services/cleaning.py` 冻结范围、协调 F01 应用和撤销；`tagging/library.py` 管理产品库与原子文件；前端在 `web/src/features/cleaning`。数据库事务仍由 F01 统一负责。
