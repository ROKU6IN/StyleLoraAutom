# 当前项目存储扫描与安全清理验收

日期：2026-10-28；版本：0.37.0。仅本地开发，无 Git 提交、上传或发布。测试使用临时项目，不清理用户实际项目或调用真实生成服务。

## 本轮范围

实现 docs/05 §3.5 与 F11 §7.3 的当前项目部分：只读占用扫描、最近一次扫描摘要、缩略图/已完成导出/剔除图片文件的预览与确认清理。侧栏入口为“存储占用与清理”（`#/settings/storage`）；未打开项目时不可操作。

跨项目扫描依赖最近项目登记，本轮不注册 A118/A119。产品阈值配置、存储专用 CLI、文件恢复入口和跨项目提醒仍待后续。本轮项目提醒阈值固定为 20 GiB，界面明确二进制单位；不把旧文档 GB 字样当成相同值。

## HTTP 与扫描

| 路由（P=/api/projects/{project_id}） | 行为 |
|---|---|
| POST P/storage/scans | 空对象；202 Operation，完整扫描结果通过 operation 查询 |
| GET P/storage/summary | 最近扫描、as_of、stale；未扫描为 null；不触发扫描或联网 |
| POST P/storage/cleanup/preview | 严格 kind 枚举；202 Operation → CleanupPreview |
| POST P/storage/cleanup | preview_id、digest、严格布尔 confirm=true；202 Operation → CleanupReport |

POST 均使用会话 Idempotency-Key，拒绝额外路径字段和未知查询参数。预览绑定项目句柄代次、类型、完整候选列表、文件身份、目录身份与展示统计，15 分钟有效。相同预览即使用另一请求键也返回原 Operation，不重复删除；关闭项目会使预览失效。没有跨进程自动重放承诺。

扫描分类互斥：已登记图片、其它 images 文件、images/.pending、images/.checks/.costs/.operations 与 .cleanup 证据、cache、exports（含报告）、DB/WAL/SHM、迁移备份、其它项目文件。图片另按审核状态和来源统计，拆分值不重复加入总数。file_missing 记录数与未观察到文件的记录数分开，扫描不更新数据库缺失位。

统计为文件逻辑长度之和，不是分配簇占用或可释放磁盘量；硬链接按目录项计，显示硬链接文件数量。符号链接、junction、reparse point 不遍历。遇权限/非法路径/超限时返回 partial、error_count、最多 200 个错误和已观察字节，不把不可访问文件冒充零。最多扫描 50000 个目录项；结果是逐项观察的快照，非跨文件系统事务。读取摘要始终说明可能过期，清理后需重新扫描。

## 删除边界与恢复

- thumbnails 只选择 cache/thumbnails 下工具生成的 64 位十六进制 `.webp` 文件；其它缓存、未知文件和临时文件保留。
- exports 只选择 `.export-state.json` 与 export_report.json 均证明 complete、目录和 export_id 一致的正式目录。`.partial-*`、缺失/损坏凭据与松散文件跳过。显示完整候选，每页 50 个，单次超过 5000 个则整体拒绝预览。删除载荷后才删除完成凭据；某个文件失败后该导出的剩余文件保留，其他导出可以继续。
- rejected_files 只选择已登记、review=reject 且未标记 missing 的图片。提交前再次验证整个计划，逐文件删除时在同一 writer 回调中复查审图、身份并写 missing。存在 pending/running/paused 标注任务时拒绝该图片的删除。删除图片保留 images、annotations、来源和审核历史；missing 图片不能恢复为 keep/unreviewed。
- import/export 已有项目文件锁；媒体原图读取与缩略图生成现也持同一锁。清理非阻塞取得排他锁，否则 storage:leased。当前实现按项目串行，未实现更细的并行图级读租约。导出报告读取也受保护。
- Windows 使用允许读取但拒绝并发写/删除的文件句柄，核对最终句柄路径、设备/文件编号、大小、mtime、birthtime；删除剔除原图还核对登记 SHA-256。删除操作落在已验证句柄上，不按未经复核的路径重新查找目标。Python 3.12 Windows stat/fstat 的 legacy ctime 含义不一致，统一取 birthtime；DirEntry.stat 的 inode/硬链接计数不完整，显式使用 Path.stat。
- `.cleanup/<preview_id>.json` 在删除前原子写入完整候选，逐文件保存结果；文件系统删除不伪装成跨文件事务。删除后在 missing 提交前进程中断，既有 F01 打开时扫描会补记 missing。清理不会自动继续删除剩余文件，也不自动解除 missing。
- `.cleanup/exports/<摘要>.json` 在删除导出前标记清理开始；失败/中断时导出状态为 cleanup_partial，报告入口关闭，重开后仍保留该状态。完成为 cleaned；完整文件已清空的目录在重开后不再从磁盘恢复为可用导出记录。空目录保留。
- 清理任务不能通过普通取消请求回滚已删文件。关闭项目停止后续删除，保留逐项结果，并排空当前文件操作后释放句柄。未知 HTTP 响应不在界面自动重发，提示核对任务记录。

界面先展示候选和后果，再要求勾选并长按一秒。关闭预览不删除；空预览/过期预览/离线/已有任务运行时禁止确认。部分失败显示文件及原因，不声称全部成功。API 最终校验为准。
