# F12 第二阶段：WD 推理与持久任务实现与验收

版本 0.10.0，2026-10-25。承接 [模型管理阶段](16-F12-模型管理实现与验收.md)，实现《F08–F12 视觉与执行器设计》§5、§8 中的本地 ONNX 路径以及统一 API A079–A083。本轮只在本地开发；没有初始化 Git、提交、推送或发布安装包。

本文保留 0.10.0 历史记录。后续用户已明确确认 CSV 官方 Git 摘要核验方案；0.11.0 已接入真实模型，见 [F12 第三阶段验收](18-F12-真实模型接入与CPU验收.md)。

## 已实现的闭环

图片导入 → 选择已校验模型、阈值和范围 → 创建持久 WD job → 逐图推理或复用当前缓存 → 写入 `wd/tags` → 工作台人工编辑/审核 → 既有导出流程。CPU 推理使用真实 ONNX Runtime，模型为固定 154 字节合成 ReduceMean 图；测试清单仅注入测试进程，没有加入生产清单。

工作台新增“WD 标注任务”，支持显式选择模型和两个 [0,1] 阈值、CPU/自动策略、全项目未覆盖/全量重跑/工作台选中范围、包含已剔除图片选项、创建、暂停、恢复、取消，以及分页任务记录和逐图结果。可以跳转图片继续审核，任务页也能返回标注记录。表单不自动选择阈值、不自动开始推理；无可用模型时仍能查看已有记录。提交结果未知时保留本次 batch_id，手动重试不重复建任务。

## 推理和数据约束

- `tagging/predictor.py` 读取受管原图并核对字节数与 SHA-256；限制每图 100 MiB，正方形填充后的画布最多一亿像素，拒绝极长窄图造成的超大分配。处理 EXIF 方向、透明白底、居中等比填充、Pillow bicubic、RGB/BGR、NHWC/NCHW 和 manifest 指定归一化；不用 LLM 图片副本。
- 加载前对 ONNX、CSV、ready manifest 做完整校验，检查张量名称、float32、输入尺寸、batch 和输出数量；前后检查文件元信息，变化时暂停。每图提交前再次核对原图哈希，writer 内短事务复核图像元数据、文件状态及当前 WD 版本。
- 分别对 general/character 应用 `conf >= threshold`；F01 规范化为小写、下划线换空格、去首尾空白。同键保留首次位置、取最高置信度，params 保存原始模型名、类别与映射证据。rating 类只保留为诊断分数，不生成普通 tag、不修改项目评级。未知标签保留；这一阶段不做词库别名映射，缓存明确记录无索引版本。
- 默认一个本地 worker、CPU、batch=1。自动策略有显存余量时尝试 CUDA，会话 provider 初始化失败或后续显存不足则回退同模型 CPU；batch=1 的 CUDA OOM 只在 CPU 重试一次。仍失败记录图级失败。没有实测显存档案，因此动态 batch 模型也逐图执行，未实现大 batch 调度/减半性能验收。
- 缓存包含原图 SHA、实际模型及固定 revision、manifest/CSV/预处理/归一版本、Pillow/ORT 版本、阈值、实际 provider、无 Skill/索引标记。不包含瞬时显存、重试、任务 ID 或 batch 大小。CPU 请求只复用 CPU；自动策略允许既有 CPU/CUDA 当前结果。只检查当前 `wd/tags`，不复活历史版本；`all` 始终推理并追加版本。

## 持久任务与恢复

`services/jobs.py` 只经 F01 公开 DAL 和 command 操作项目，无服务层 SQL、无 schema 变更。新增带 executor 筛选的只读 repository 方法，保留已有签名。

创建时在同一个 writer 事务解析范围、创建 batch、冻结配置和有序 image_ids，最多 5000 张。selected 去重排序、允许明确选中的 reject；筛选默认排除 reject，可显式纳入。缺失原图记 skipped/file_missing，不调用模型；不存在的 selected ID 整批 422。冻结后导入新图或改变审核状态不改变范围。

相同 batch_id 与相同请求返回原任务，跨重新打开项目仍有效，不隐式恢复；不同请求 409。恢复严格沿用 manifest、模型、阈值、管线和 ORT 版本，缺失或变化时保持暂停。任务启动不下载模型。

每张图片的标注、outcome 和计数经 F01 原子提交。暂停停止派发，允许在途图提交；最后一张完成可自然 paused→done。取消先持久化 canceled，再停止派发，推理返回后丢弃尚未提交结果。原始、人工、规则层不被 WD 写入覆盖；并发 WD 版本或原图变化记失败并保留现有层。

库忙最多重试三次提交；同进程保留已准备结果，恢复不重新推理。COMMIT 结果未知时按实际提交的 outcome 摘要核对账本，确认成功则继续，否则暂停；不盲目重发模型。关闭项目/服务会取消运行尝试并等待在途调用返回，持久 job 保持暂停，重新打开不会自动执行。进程在提交前崩溃时内存结果仍可能丢失，未有 outcome 的图片恢复后可能再次推理，这是既有 F01 边界。

本次运行尝试也出现在普通 operation 列表，但其完成只表示 worker 已退出。任务最终状态以持久 `/jobs/{id}` 为准，界面提供直达链接；禁止通过通用 operation 取消接口绕过 job 状态机。

## API

所有接口沿用本地会话鉴权、Origin/Host、严格 DTO、统一错误、项目租约和 If-Match。POST 要求幂等键；浏览器只提交 manifest_id，不接受模型路径或 URL。

| 方法 | 路径（P = `/api/projects/{project_id}`） | 行为 |
|---|---|---|
| POST | `P/jobs/batches` | 显式 `executors:["wd"]`、稳定 UUID batch_id、mode、scope、config；202 返回持久 TaskRef、状态/事件 URL |
| GET | `P/jobs` | status/batch_id/executor 筛选，limit/cursor 分页 |
| GET | `P/jobs/{id}` | 状态、冻结配置、计数、version；不返回整份内部 progress_json |
| GET | `P/jobs/{id}/outcomes` | kind 筛选，逐图原因、标注 ID 和缓存键，limit/cursor 分页 |
| POST | `P/jobs/{id}/control` | `{action:"pause"|"resume"|"cancel"}` + If-Match |

配置示例：`{"manifest_id":"<可信清单摘要>","general_threshold":0.35,"character_threshold":0.85,"batch_size":1,"provider":"cpu","backend":"onnx"}`。数值仅示例，程序要求用户明确填写。scope 为 `{"filter":{}}` 或 selected 模式的 `{"selected_ids":[1,2]}`。当前只能创建 WD 单执行器；LLM 记录可读，执行/联动尚未实现。

SSE 支持 `topics=job`，发布 job.started/image_completed/paused/done/canceled/failed，附 job/image ID、计数、原因和 outcome kind；账本仍以 GET 为准。`topics=tagger` 可订阅模型事件。前端结合事件失效刷新与轮询恢复状态。

能力字段：`session.capabilities.wd_jobs=true` 表示任务接口已实现；`wd` 与 `/tagger/capabilities.available` 取决于可信清单、可选运行时和当前已校验模型。模型文件存在但未在本进程校验时，UI 要求手动校验；HTTP runner 加载前也会完整校验，损坏时暂停而不推理。

## 真实模型与未完成项

生产 `REVIEWED_MANIFESTS=()` 保持为空，正常启动的工作台仍不能执行真实 WD。研究了发布者 [wd-eva02-large-tagger-v3 文件树](https://huggingface.co/SmilingWolf/wd-eva02-large-tagger-v3/tree/b25b82a03f7282e41aa2f257a52c7583b710bd1c)、[ONNX 文件](https://huggingface.co/SmilingWolf/wd-eva02-large-tagger-v3/blob/b25b82a03f7282e41aa2f257a52c7583b710bd1c/model.onnx) 和 [标签 CSV](https://huggingface.co/SmilingWolf/wd-eva02-large-tagger-v3/blob/b25b82a03f7282e41aa2f257a52c7583b710bd1c/selected_tags.csv)：权重有发布者 SHA-256，但尚未取得标签表独立发布的可信 SHA-256 证据。没有将首次下载计算值伪装为预期摘要，也没有下载真实权重。发布者 [演示代码](https://huggingface.co/spaces/SmilingWolf/wd-tagger/blob/main/app.py) 作为白底、方形填充和 BGR 预处理的交叉参照；产品仍以审核清单为准。会话实现参照 [ORT 官方 Python API](https://onnxruntime.ai/docs/api/python/api_summary.html)。

下一阶段应补齐真实模型可信清单和固定 golden fixture，完成真实 WD CPU 精度/性能验收，再做真实 CUDA/显存档案与批调度。Launcher interrogate 仍无核验合同，不会自动切换；F15 VLM、全局 LLM、WD→LLM 多执行器依赖调度、生成/费用与导出处理链仍未实现。本阶段不宣称真实 WD 质量或 GPU 性能已验证。
