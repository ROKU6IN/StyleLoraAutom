日期：2026-10-28；版本：0.49.0。接续 [服务化导出 CLI](55-F11-服务化导出CLI验收.md)，实现 [F11 设计](F11-F14-API与进程设计.md) A057/A058、§9 source retry-item，以及来源草稿编辑 CLI。本机仍未发现 Launcher 发现文件，生产兼容清单仍为空；本阶段仅本地开发，不初始化、提交或上传 Git。

## 已实现

- `source update SOURCE_ID --spec FILE --if-match VERSION --project-id PROJECT_ID`：使用既有完整 Draft PUT，编辑未锁定、未启动的 nai 来源。严格 UTF-8 JSON（支持 BOM），最多 16 MiB；未知键、重复键、非有限数值及配置错误在连接前拒绝。目标数量、三组尺寸、参数、画风和负面词等一起验证保存，不支持把局部字段文件当补丁。完整结构见 [生成来源 CLI](53-F11-生成来源CLI验收.md)。
- 编辑必须提供用户原来读取的版本，不临时读取最新版本覆盖旧修改。费用策略为 allow 时必须额外 `--confirm-allow`；其它策略不允许带该开关。已锁定的生成来源和导入来源拒绝 Draft 更新；费用策略仍可通过专用命令调整。
- `source item ITEM_ID --project-id PROJECT_ID`：读取持久条目、attempts、状态、错误、图像编号和当前版本，与分页 items 的条目版本一致。一次查询成功即退出 0，failed 表示条目状态而非查询失败。
- `source retry-item ITEM_ID --project-id PROJECT_ID --expected-attempt N [--if-match VERSION]`：显式授权这一个失败 attempt 的下一次尝试，同时支持 nai/import。未提供版本时只读取该条目当前版本；expected-attempt 始终必填，不从最新状态自动替换。复用 F01 `retry_failed_item`，清空错误、转 pending、attempts 仅加一次；原提示词、序号、来源和冻结配置保持不变。
- 新增 `GET P/source-items/{item_id}`、`POST P/source-items/{item_id}/retry`，P 为 `/api/projects/{project_id}`。POST 严格接受 `expected_attempt` 正整数，要求 If-Match 和 Idempotency-Key。版本检查和重试在同一写事务；并发请求不会重复累加。错误码区分 `item:not_failed`、`item:attempt_conflict`、`source:canceled` 和版本冲突。
- done 来源重试时在同一事务转 paused、清 finished_at、刷新费用周期；running/paused 来源保持原生命周期。CLI 与 HTTP 不主动 dispatch 或 resume；若来源本来正在运行，既有 runner 可以处理用户新授权的 pending 条目。sent/done/skipped 条目不能重试，canceled 来源不能重试，也不新增生成自动重试策略。
- 同一失败 attempt 已转为 pending 且 attempts=N+1 时，按 F01 可只读确认该转变，不再增加次数。必须提供当前有效版本；若该条目已进入 sent 或新一次 failed，旧 expected-attempt 不能授权下一轮。
- 发生提交后的通知/回执错误时，草稿更新与条目重试明确返回 outcome=unknown。事务前失败按原领域错误返回，避免把已提交操作误报为已拒绝。

## 使用与恢复

```powershell
./scripts/run.ps1 serve
# 从 status 取得原草稿 version，编辑完整 draft.json 后保存：
./scripts/run.ps1 source status 1 --project-id <project_id>
./scripts/run.ps1 source update 1 --project-id <project_id> --spec .\draft.json --if-match <original_version>

# 查询失败项，再授权该次重试：
./scripts/run.ps1 source item 7 --project-id <project_id>
./scripts/run.ps1 source retry-item 7 --project-id <project_id> --expected-attempt 1 --if-match <item_version>
./scripts/run.ps1 source status 1 --project-id <project_id>
# 如需继续暂停的来源，另行显式执行：
./scripts/run.ps1 source resume 1 --project-id <project_id>
```

stdout 为单个 JSON，`--json` 可省略。回执 `cli` 保留实例、项目、资源编号、状态 URL，以及写请求的 method/path/body/if_match/idempotency_key。无自动重发，原请求结果未知时先查询 source status 或 source item；查询和回执均不输出 Bearer token、外部配置路径或原始内部错误。

同一实例内，完整 Draft PUT 携带键时按原 body+If-Match 去重，HTTP 兼容既有不带键的 PUT。retry 同样绑定 expected_attempt+If-Match。同键不同内容或版本返回 `idempotency:key_conflict`。CLI 重放必须显式提供原 `--instance-id --idempotency-key --if-match` 和原文件/attempt。重放成功结果是原请求回执；要了解 runner 后续变化需重新查询 item/status。

服务重启后旧实例请求不允许重放。重新打开原项目后，使用新 project_id 查询持久内容与次数。若同一次授权仍是 pending/N+1，可用新请求键、当前条目版本和原 expected-attempt 核对，不增加次数。若真实状态未能证明结果，不自动提交新的尝试。导入恢复仍需要已授权且通过验证的原输入目录；真实生成仍受适配器与费用门禁保护。

退出码沿用来源 CLI：0 为编辑/查询/重试受理成功；2 参数或文件不合法；3 本地服务不可用；4 版本、实例或状态冲突；5 读取/依赖错误；7 写结果未知；130 客户端中断。重试退出 0 只表示条目进入下一次尝试或重复请求已核对，不表示重新生成/导入成功。
