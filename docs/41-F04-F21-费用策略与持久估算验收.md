# F04 / F21 费用策略与持久估算验收

日期：2026-10-27；版本：0.34.0。依据 F02–F05 §5、T11–T12、F01 费用周期合同、F14 §4.4 及已采纳的 C06。本轮仅本地开发、测试与打包，未初始化、提交或上传 Git，未调用真实 Launcher 或收费模型。

## 已实现范围

新增 `generation/costs.py`，复用 F01 的 evaluate_cost、confirm_cost_and_resume、set_cost_policy 和 mark_sent。Runtime 持有 CostService，与已有 SourceService 共用控制锁，使策略修改、费用确认与派发关口串行。F01 费用确认新增可选事务内校验回调，HTTP 的 If-Match 在实际写事务中再次校验；旧调用保持兼容。

这一阶段完成费用控制核心、内部派发前授权边界、C06 持久估算、HTTP 查询/控制及前端确认界面。生产 driver 仍为空，generation=false。内部 reserve_dispatch/observe 不开放 HTTP 写入口，不伪造真实 prepare、提交或审批结果。

## 周期费用控制

| 条件 | 行为 |
|---|---|
| 估算是严格整数 0 | 放行费用检查，但不声称免费 |
| 非零 + deny | 暂停，不增加 attempts，不提供周期同意操作 |
| 非零 + ask、无本周期同意 | 暂停并记录当前会话中的 item、估算和周期，等待用户确认 |
| 非零 + ask、已有本周期同意 | 当前周期可继续，后续每张仍经过检查 |
| 非零 + allow | 放行本产品费用检查；Launcher 自身审批仍可能发生 |
| 缺失、负数、bool、浮点数或超过 JS 安全整数上限 | cost:invalid_estimate，暂停，不能取得派发授权 |

周期 token 沿用 F01 的 32 位十六进制不透明标识。确认要求 paused、ask、当前 pending_cost、相同周期和来源版本，并检查 driver、在途任务及 F03 恢复屏障。同意后进入新运行周期，由已有 driver.dispatch 入口排队；不是复用旧 preparation。成功重复 HTTP 请求使用同一 Idempotency-Key 返回已有结果，不重复派发。普通继续不带费用同意；暂停、停止、完成、改策略和进程重启均不能沿用旧 ack。

策略独立于锁定的生成配置，可以修改已锁来源。实际策略改变时清除原 ack/pending；运行中的来源获得无同意的新周期，已 sent 的请求不撤回。策略修改与提交检查之间发生竞争时，以最后一次写事务中的策略/周期为准；旧检查结果不能授权新周期。没有把 pause_reason、ack 或 cycle 写入项目数据库。

## C06 持久凭据与派发边界

新增项目相对文件 `images/.costs/<item_id>/<attempt>.json`，不加表、列或数据库版本。文件随项目搬迁保留，不能当缓存清理。单份最大 8 KiB，schema_version=1、严格 JSON 和规范 SHA-256 信封；拒绝重复键、非法类型、超限和不安全路径。摘要防损坏，不单独证明外部请求归属。

记录仅含来源/item/attempt、周期、唯一 operation_key、请求/配置摘要、实例/契约摘要、单张 estimated_anlas、当时策略、outcome 和证据摘要。没有完整 prompt、端点、绝对路径、token 或实际扣费数据。GET 不创建目录或文件。

未来 runner 在真实 prepare 成功且取得可信估算后调用 reserve_dispatch：

1. 检查来源 running、条目 pending、周期匹配、该源没有其它 sent 条目；调用 F01 费用门禁。
2. 只有放行才以原子写入保存 intent 凭据，并 flush/fsync；保存无法确认就暂停，不能 mark_sent。
3. 在单写事务中重新核对来源策略、周期/ack、条目 attempt、冻结请求/配置及刚保存的凭据，再 mark_sent。
4. 只有该次事务明确成功才返回一次派发授权。同 attempt 再次调用不会得到授权。提交异常即使后来看到 sent，也保持 unknown、暂停并要求核查，不能重发。

intent + sent 表示“可能已发送，结果未知”，不证明已经扣费。崩溃可能发生在 sent 提交后、远端发送前；这种保守归类避免把不确定请求误当未发送。intent + pending 不纳入累计；确认数据库仍是同一 pending attempt 且原凭据身份匹配时，下一次显式新 prepare 可以替换未派发 intent，生成新的 operation_key。不同来源/请求的凭据、损坏凭据不覆盖。

已审核适配器可通过内部 CostEvidence 提交精确 operation_key、实例/契约与证据摘要，把 unknown 更新为 submitted 或 rejected。submitted 仅确认派发，不等于实际扣费；rejected 必须证明该 attempt 没有生成/扣费，普通超时、recent 缺条目或取消通知不足以证明。明确拒绝会从有效估算中排除，但保留原估算与记录；相同证据可重复，矛盾证据拒绝，已完成当前图片不能再记拒绝。费用证据本身不改变 item 状态，未来 runner 仍须利用同一权威证据执行 fail_item、暂停等生命周期操作。

未知发送、preparation 取消、实际提交和审批契约尚未接入。此核心不代替 F03 设置租约、逐源完整调度和外部归属验证，也不具备供应商幂等保证。

## 本地累计与完整性

汇总以数据库中的实际 attempt 范围为准，按 item/attempt 去重；retry 分配但尚未 sent 的最新 attempt 不计，旧 attempt 保留。不读取 PNG 元数据做账。跨重启与项目搬迁可以读取相同记录，费用同意不会恢复。

返回 source=local_estimate、estimate_scope=persisted_attempts，余额/订阅/体力/actual_charged_anlas 均为 null。estimated_anlas 为 submitted + unknown 的本地估算，unknown 与 rejected 的次数、金额分别展示。未知结果不会被算成明确成功或明确拒绝。

旧项目没有凭据、文件损坏/丢失、来源/请求摘要不符时，estimate_complete=false，estimated_anlas=null，另给已读部分和缺失/损坏计数，不默认为零。每次最多扫描 100000 份预期凭据，超出计入 unscanned 并明确不完整；金额累计超过安全整数范围返回 null，不通过浮点 JSON 四舍五入。estimate_complete 只表示预期 attempt 的估算记录齐全，不表示实际账单已知。

## HTTP 与界面

| 接口 | 当前合同 |
|---|---|
| GET `/api/projects/{pid}/sources/{sid}/cost-state` | 当前策略、来源版本、周期、ack、暂停估算与能否确认；只读取，不派发 |
| PATCH `/api/projects/{pid}/sources/{sid}` | 仅 cost_policy/confirm_allow；If-Match + Idempotency-Key；allow 必须 confirm_allow=true |
| POST `/api/projects/{pid}/sources/{sid}/confirm-cost` | cycle_id + 来源 If-Match + Idempotency-Key；成功返回 200 SourceView，driver 只排队，不在 HTTP 中执行生成 |
| GET `/api/backends/nai_launcher/account-status?project_id=…&source_id=…` | 项目范围的持久本地估算；不请求 Launcher 账号数据 |

未指定项目/来源时 account-status 保持 null，不拼接跨项目总额；错误后端、导入源、鉴权失败及多余参数仍拒绝。费用凭据写入、上报结果和强制清零没有 HTTP 入口。以上细化覆盖早期 A055 的 202 草案；本阶段沿用来源控制的同步 200 回执，费用执行核心没有新增 Operation 或 jobs。

在“来源与导入”打开已保存生成源，可查看“生成费用与估算”、单独修改运行策略。编辑中的来源草稿须先保存或处理，避免策略保存覆盖草稿。选择 allow 要核对说明、勾选并长按一秒；草稿表单中的 allow 同样要求确认。ask 的周期确认明确表示整个运行周期、不是单张授权或费用上限，绑定弹窗打开时的来源版本和周期；变化后禁止确认。deny 无同意按钮，真实适配不可用或设置恢复未结清时禁止继续。

查询通过 source.changed 失效更新并周期刷新。界面区分累计估算、未知结果和明确拒绝；凭据缺失时显示“不完整，不能给出总额”。普通浏览不连接外部后端，不触发真实费用。
