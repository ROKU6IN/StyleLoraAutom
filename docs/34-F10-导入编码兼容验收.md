# F10 导入编码兼容实现与验收

日期：2026-10-26；版本：0.27.0。仅本地开发与验收，不初始化、提交或上传 Git。

## 本阶段范围

实现 F09–F10 设计 §9、T17 与 C14 的可选严格 UTF-8→GBK 回退，同步 05 §10.5。默认 `utf-8-sig` 保持；`auto` 通过方案、HTTP 临时覆盖、浏览器和 CLI `--encoding auto` 显式选择，不作为统计编码检测。

| 输入与选择 | 行为 |
|---|---|
| UTF-8 BOM（所有已支持选择） | 按 utf-8-sig 严格解码；损坏不尝试 GBK |
| auto，无 BOM | 先严格 UTF-8；仅解码失败后尝试严格 GBK |
| auto，ASCII 或空文件 | UTF-8 优先，无回退提示 |
| 显式 gbk，无 BOM | 直接严格 GBK，不先试 UTF-8，不标为自动回退 |
| 两种解码均失败 | `encoding:invalid`；HTTP 预览禁止确认导入，底层逐图导入记录失败 |
| NUL、非法分段或标签语法 | 原有校验继续生效，不用替换字符修复，不改变 tokenizer 规则 |

CRLF/CR 仍统一为 LF，标签和描述按既有空行规则解析。UTF-8/GBK 可解码不意味着语义一定正确；页面明确要求核对回退后的中文。原始图片和 txt 字节不修改。

## 持久记录与恢复

原始 tags/nl 的 params_json 增加 `encoding_requested`、`encoding_fallback` 与 `warnings`，继续保留实际 `encoding` 和 sidecar SHA-256。GBK 自动回退产生 `encoding:gbk_fallback`；词库解析的未知片段提示可同时存在。无 txt 不生成编码记录，空 txt 仍生成空 tags 及其解码记录。

来源配置冻结 `encoding=auto`，修改或删除产品方案不改变已开始导入。收据携带原始输入及解码证据，恢复后随同标注一次性提交；不会重复生成标注。

导入任务返回及 `GET /api/projects/{id}/imports/{source_id}/summary` 从已提交原始标注恢复逐项编码和提示，不重新读取外部素材。查询仅提取这三个小字段，不把完整 tokenizer 分段证据全部载入报告内存。重开项目、外部根已移动时仍可查询。旧项目没有新增证据的条目保持空值，不猜测或补造回退记录；跳过/失败且未登记图片的条目也不伪造历史编码。无数据库迁移。

## API 与页面

- capabilities 的 encodings 新增 auto，并返回 `auto_encoding_policy=utf8_then_gbk`；默认方案编码不变。
- auto 方案保存后 executable=true；临时 options 覆盖不改写保存方案。
- 预览 diagnostics 增加 encoding、encoding_fallback；`encoding_fallback_count` 统计全部验证通过的条目，覆盖未展示的第 101 项及以后。
- “导入导出方案”与“来源与导入”提供明确的回退选项；更改选择使旧预览失效，需重新扫描。
- 预览展示实际编码和中文回退提示；来源明细从 summary 读取持久证据。预览仍最多 100 项，明细仍最多展示 500 项，完整报告可通过 API 查询。
- 原有清单哈希、方案版本、预览摘要校验保留；损坏 BOM 或源文件变化不创建成功来源/图片。
