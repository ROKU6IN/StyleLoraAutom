## 实现范围

- `tagging/manifests.py` 定义冻结、严格且带内容摘要的清单；包含 HF repo、40 位固定 commit、两个文件的预期长度/SHA-256、完整输入/输出与预处理约定、CSV 列与类别。拒绝可变 revision、路径、Windows 保留名、额外字段、重复 JSON 键和坏摘要。当前仅支持单文件 ONNX + CSV，单个权重最多 2 GiB、标签表 16 MiB、清单 32 KiB。
- `tagging/models.py` 只在明确安装动作后下载，初始 URL 由清单生成；限制到 HTTPS Hugging Face/CDN 主机，禁代理环境继承、不携带服务凭据、不透传响应正文或签名 URL。最多 5 次重定向，连接 10 秒、读取 5 秒、每个文件总预算 30 分钟；逐网络块检查取消、总时限与长度。
- 下载在同一模型目录的随机 `.partial` 子目录中进行。逐文件核对摘要，然后检查 CSV 表头、行宽、数量、重复模型名和类别，再通过 CPU ONNX Runtime 加载、核对张量名称/类型/布局/尺寸/batch/输出数量。仅支持清单声明的 `float32`；外部权重文件不受支持，模型以 bytes 加载，不能解析外部文件路径。
- 全部校验完成后 fsync 文件，写 ready manifest，原子重命名整个版本目录。取消与发布共用任务锁划定提交点。失败或取消清理本次暂存；旧 ready、其他 revision 和旧进程残留 `.partial` 都不会被覆盖或删除。
- `services/tagger.py` 同模型同版本正在安装时合并为同一 operation；幂等键重放不会重新下载安装。安装目录已存在时只重新校验，不联网、不自动覆盖损坏文件。列表通过文件 size/mtime/inode 与本次校验记录比较；重启后只有 `unverified`，显式全量重验后才能重新 ready。列表的文件元信息检查不替代未来每次推理加载前的完整校验。
- `tagging/device.py` 先 NVML、失败再有 3 秒超时的固定路径 nvidia-smi。未知数值保留 null；保留预算 max(1 GiB, 总量 20%)。无模型显存实测档案时批大小恒为 1。此阶段 provider 始终 CPU，显存检测只作信息展示，CUDA 模型会话没有验证。
- `tagging/model_runtime.py` 按可选依赖加载 ONNX Runtime，缺失/加载失败/CPU 与 GPU 发行包同时存在均明确不可用。基础编辑器无需 ORT；`wd-cpu` extra 固定 `onnxruntime==1.31.0`。
- 设置页“WD 模型管理”展示环境、版本、大小、SHA、安装阶段和取消；分页 20 项。可从任务页回到模型管理，重新进入会恢复本进程安装状态。安装成功不会开启 WD executor，也不改项目数据库。

## API 与存储

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/tagger/capabilities` | 管理能力、可选运行时、设备快照、执行器禁用原因 |
| GET | `/api/tagger/models` | 固定清单与本机状态；limit/cursor 分页 |
| POST | `/api/tagger/models/install` | `{manifest_id}` + 幂等键，202 返回 installation_id/TaskRef/状态 URL |
| GET | `/api/tagger/installations/{id}` | OperationView + 阶段、下载字节、校验结果、版本 |
| DELETE | `/api/tagger/installations/{id}` | If-Match，204 请求停止本次安装；完成后的文件保留 |

沿用本地鉴权、Origin/Host 门禁、统一错误与 `/api/events`，未知安装会话 410；会话操作保留至进程退出。产品操作不写入 `jobs`、annotations 或图片，关闭/切换项目不应中断产品安装；服务退出会请求取消并等待已进入的本机验证返回。ORT 阻塞加载无法中途安全强杀，取消在加载返回后、发布之前生效。

默认存储 `%LOCALAPPDATA%/StyleLoraAutom/models/wd/<model_id>/<revision>`，与 `%APPDATA%` 的标签资料分开。测试服务通过独立 runtime 目录隔离模型路径。所有层级拒绝符号链接、junction 和 reparse point。

## 可信清单与当前限制

Q02 仍未裁决：`REVIEWED_MANIFESTS=()`，没有把候选模型名称或首次下载摘要当作已审核清单。生产 UI 因此显示没有可安装模型。此阶段交付的是模型管理机制及闭环验收，不宣称真实 WD 已能标注。HTTP 没有注册清单、任意 URL 下载、模型路径授权或删除已安装版本的接口。

加入真实模型仍需独立核对发布者固定 commit、两份预期摘要、tensor/CSV 合同与预处理证据，再作为审核过的内置清单发布。当前清单摘要只证明内容一致，可信性来自开发审核；它不是发布者数字签名。

设备读取在首次能力查询时执行并在内存缓存 30 秒；启动不扫描显卡、不联网，未来推理前的设备重新检查由 runner 阶段接入。GPU provider 初始化、实测显存档案、OOM 减半与 CPU 回退均未实现。没有接受外部权重分片，损坏版本需恢复原始文件后手动重验；崩溃遗留暂存不自动清理，以免误删另一安装持有的文件。

## 验证

新增 `test_tagger_models.py` 17 项和 `test_api_tagger.py` 11 项，覆盖清单信任边界、原子发布/重用、截断/超长/坏摘要、CSV、取消、磁盘异常、链接拒绝、损坏 ready 与遗留暂存、重定向/慢速流总时限/错误脱敏、设备回退、可选依赖冲突、鉴权/严格 DTO、并发合并、幂等、CAS、排队取消、状态恢复、项目关闭不取消产品安装和项目数据不变。

真实 ONNX 测试使用仓库中的 154 字节合成 ReduceMean 图（固定 base64 fixture，绝非 WD 模型）：通过 ORT CPU 加载及一次实际执行，同时核验错误输入名称、布局、batch 和输出维度被拒绝。普通 API 测试注入可控下载与验证边界；真实 ORT 测试及浏览器测试使用生产 tensor validator。若没有 wd-cpu，可选真实 ORT 单测明确 skip；本机验收已安装依赖并执行该项，浏览器模型验收也要求 wd-cpu。
