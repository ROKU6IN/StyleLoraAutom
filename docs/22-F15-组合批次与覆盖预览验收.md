## 顺序、冻结与恢复合同

一次创建请求在同一 writer 事务中建 WD、LLM 两个单值 job；即使请求顺序相反也规范为 WD 在先。两阶段共享本次物化的图片范围，各自冻结配置、模型/角色/模板和词表摘要。WD 转 running，LLM 保持 pending。任何阶段的冻结失败会回滚整个建批事务。

这细化了设计中“首次启动冻结”的时点：组合批次在建批时冻结两阶段，LLM 的 started_at 仍等实际启动才写入；后续图片导入、审核变化不会改变其范围。LLM 输入证据则在执行时读取，因此可使用本批次已提交的 WD 结果。原始或 WD 证据在推理过程中变化仍受既有 CAS 保护。

只有前序状态 done 才能启动后序，done 可包含逐图失败。WD failed/canceled 时后序保持 pending、批次显示 blocked，禁止跳过依赖；可取消剩余阶段并按需要另建批次。空范围可直接完成两阶段，不产生模型请求。

整批暂停在一个事务中暂停运行阶段，并持久化 pending 阶段的等待原因 `job:batch_paused`。暂停允许已经接受的推理返回；即使这是 WD 的最后一张，LLM 仍不会自动启动。继续批次先核验冻结依赖，再清除暂停等待原因、恢复最早未结束阶段。整批取消在同一事务中取消全部未结束阶段，丢弃未提交及迟到结果，保留已完成阶段和已提交标注。单 job 控制继续只作用于该阶段，跨阶段暂停使用整批接口。

关闭项目会抑制接续；重开后的中断任务 paused，后一阶段仍 pending，必须显式继续。角色、模板、模型或运行时不匹配时保持等待并返回诊断，恢复原配置后可继续。批次聚合状态仅用于 HTTP/UI，不增加数据库状态枚举。进程崩溃前未提交的模型结果仍可能在恢复后重新调用，沿用上一阶段的计费边界。

批次控制使用整个批次版本的 If-Match，并在 writer 内再次核验，拒绝陈旧状态。创建与整批控制发生提交结果未知时，读取持久状态核对，不盲目重复建批。相同 batch_id/请求重放返回原任务；不同执行器、配置或范围冲突。已存在批次的只读重放不要求当前模型依赖仍可用。

## 覆盖预览与界面

预览只检查元数据、文件是否存在和当前标注缓存，不调用视觉/R5、不修改评级、不解码图片或重算 SHA-256。实际执行仍重新核验文件及输入。WD 按当前 CPU/自动配置的缓存合同统计；视觉阶段只接受同组双层 current 缓存。可能需要 WD 更新的图片记为 `waiting_for_wd`，未来视觉调用数只能在 WD 完成后确定。

每阶段返回 total、cache_hit、needs_execution、file_missing、waiting_for_wd、role_empty、rating_unresolved。rating_unresolved 是待执行项的附加说明，不另加总。预览还返回与同执行器未结束 job 重叠的记录；不自动并入或排队到旧批次。

预览范围摘要包含项目、模式、scope 和有序 IDs。客户端创建时提交 `preview_scope_digest`，服务在建批事务中再次解析并比对；图片成员变化返回 409 `job:preview_stale`，界面刷新预览，等待用户重新提交。摘要不保证未来缓存状态，也不是强制所有旧客户端采用的新权限机制；旧单阶段请求可不传。

界面默认未覆盖、排除 reject，最多 5000 张，支持工作台显式选中。候选超过 500、视觉待执行加 waiting_for_wd 超过 50、或出现任务重叠时打开确认；全部重跑无论数量均需长按。CPU 固定一图，自动设备支持既有 1/2/4 上限。确认内容、scope_digest 或表单发生变化时不能沿用旧确认。未知提交重试保持 batch_id，不因按钮再次点击创建重复批次。

批次总进度按阶段图片项统计，两阶段各自记一次；界面同时显示图片数、阶段数与分阶段进度。任务列表也聚合已有单阶段任务，详情保留逐图结果和工作台跳转。

## HTTP 合同

| 方法与路径（P=`/api/projects/{pid}`） | 用途 |
|---|---|
| POST `P/jobs/preview` | executors/mode/scope/config → 本地估算和 scope_digest；无模型调用或 job 写入 |
| POST `P/jobs/batches` | 支持单阶段或 WD+LLM；新增可选 preview_scope_digest；返回 items、batch_id、batch_url 和既有 task/status_url |
| GET `P/jobs/batches` | 按最早 job ID 分页的批次聚合；稳定上界游标 |
| GET `P/jobs/batches/{batch_id}` | 批次状态、版本、总进度和各阶段 JobView |
| POST `P/jobs/batches/{batch_id}/control` | pause/resume/cancel；If-Match 和幂等键 |
| GET `/api/executors/capabilities` | llm_vision.combined_batch=true；可用性仍取决于本机配置 |

单阶段 config 保持原结构。组合请求 config 必须为 `{ "wd": { ...TaggerConfig }, "llm_vision": { ...VisionConfig } }`；重复执行器或不匹配结构拒绝。UUID、严格 schema、回环鉴权及源校验均沿用原 API 门禁。SSE 的 job 事件增加 batch_id 和 executor，仍可通过 HTTP 重查真实状态。
