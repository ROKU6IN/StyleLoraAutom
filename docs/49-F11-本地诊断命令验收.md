## 本轮范围

接续 0.41.0 原图恢复核验，实现 F11 §9 / T42 的 doctor 离线诊断阶段。诊断可在没有运行服务时使用，也可在服务运行时观察锁状态。不会创建 Runtime、请求管道凭据、附着 HTTP、打开浏览器、改变当前项目、自动启动服务或创建缺失产品目录。

```powershell
./scripts/run.ps1 doctor --json
./scripts/run.ps1 doctor --project "E:\datasets\example.slproj" --json
```

使用自定义 serve 目录时，传入同样的 `--runtime-dir` 和/或 `--product-dir`。serve 与 doctor 共用 `runtime/paths.py`：默认配置位于 APPDATA，私有资料与模型位于 LOCALAPPDATA；自定义目录沿用既有 serve 布局。参数选择的是要检查的磁盘位置；发现产品锁占用不表示已认证或已连接到那个服务，也不能据此认定活动服务使用所选路径。

`--json` 可省略，stdout 始终为一个 JSON 对象；错误参数和中断说明写 stderr。没有 token、secret、repair、install 或 `--probe-network` 参数；未知参数退出 2，不执行检查。网络诊断为后续范围。

## 检查内容与边界

报告包含 schema_version、产品 version、as_of、scope=offline_metadata、status、exit_code、network_probed=false、repairs_performed=false 及 checks。每项包括固定 id、code、status、exit_code 和最小 details。逐项失败不阻止其余检查，不返回异常原文、绝对路径、端点 URL、配置正文、项目名称、提示词或密钥。结果是各项读取时的观察，既不是跨文件原子快照，也不是持续健康监控。

| 检查 | 实际行为 |
|---|---|
| SQLite | 仅连接内存库，验证 SQLite ≥3.38、JSON 函数及 STRICT 表支持；不连接项目 DB |
| 产品锁 | 使用现有 CurrentUser OS mutex 做即时观察；空闲时立即释放，无服务时不创建定位文件。占用返回 instance:running，不获取凭据或释放他人所有权 |
| 目录访问 | Windows 对已有目录或最近已有祖先请求创建文件/子目录权限后立即关闭句柄，不创建试写文件；报告目标是否存在和检查方式。这不保证后续任意文件替换或磁盘容量充足。非 Windows os.access 仅为建议性结果 |
| DPAPI | 对 32 字节随机探针进行 CurrentUser 内存加解密往返；不读取已有密钥值，不持久化探针或密文 |
| 配置 | 复用现有只读校验器，分别检查产品阈值、LLM 配置、加密密钥容器结构、当前视觉词表、尺寸预设、最近项目记录、标签/规则库。缺失文件采用内存默认值，不写回；不遍历最近项目列表中的目录 |
| Launcher 恢复日志 | 校验既有摘要和 schema，只返回阶段及 blocked。未结清返回需处理，损坏返回错误；不读取外部 Launcher 设置、不对账或恢复，不披露原值/目标值 |
| WD 模型 | 只遍历内置已审核清单对应位置，校验 ready.json 与内置清单完全一致及两文件大小；未安装为正常可选状态。明确 content_verified=false、inference_run=false，不计算权重哈希、不载入 ONNX/CPU/GPU，不下载安装 |
| 可选项目 | 校验 .slproj 目录和现有只读项目锁，读取有界 project.json 及 DB 前 100 字节；仅检查元数据版本和 SQLite 文件头。检测迁移标记、rollback journal、非空 images/.pending，报告 WAL 是否存在。占用时返回冲突，不绕过锁 |

当前项目检查不会调用普通 open/recover；也不调用 SQLite 只读连接，避免创建或改变 WAL/SHM。项目 DB 文件头中的版本可能落后于 WAL，因此不拿它冒充当前 schema，也不执行 integrity_check、foreign_key_check、内容计数或收据恢复。输出明确 database_check=header_only、integrity_checked=false、opened=false。迁移标记或 pending 内容只作为需检查的线索，不自动认定数据损坏。没有扫描全部图片哈希、导出目录、任务文件、词典/模板及配置历史版本。

读取拒绝 symlink/junction 等重解析路径；配置文件按现有上限验证，诊断用原图核验已有的 Windows 只读句柄辅助固定文件，并检查普通文件类型。缺失可选文件不会被创建。目录句柄、文件句柄和观察到的锁在退出时释放。诊断不保证之后的外部修改不会发生。

## 状态与退出码

| 码 | 含义 |
|---|---|
| 0 | 本轮所列检查通过；可选模型未安装、配置使用默认值、服务正在运行本身不算故障；不代表 DB 内容、模型哈希、网络或生成能力已验收 |
| 2 | 参数错误，不执行诊断 |
| 4 | 指定项目占用，未读取受锁保护的容器内容 |
| 5 | 至少一项依赖、路径、配置或 I/O 检查失败；保留其它项结果 |
| 6 | 诊断部分不可用，例如非 Windows 产品单实例检查不受支持 |
| 7 | 发现需人工处理/核对的恢复记录、迁移线索或不支持的项目版本，没有执行恢复 |
| 130 | 用户中断检查，不输出完整成功报告 |

多项问题同时存在时，汇总优先级为 5、4、7、6、0；每项的原始 code/exit_code 均保留。失败只返回安全错误码，可能需要结合既有专用页面或日志进一步定位，doctor 不回显文件中的敏感值。
