## 模板与评级合同

R2、R5 的可读源文件为 `skills/vision-captioner/SKILL.md`、`skills/rating-classifier/SKILL.md`；包内 `llm/data/r2.md`、`r5.md` 与源文件逐字一致，清单固定提示词及 JSON Schema 的 SHA-256。R0 同样固定摘要。R2 缺少原始 TagCleaner 模板，因此本版按设计合同新写，不宣称已完成原文迁移。R1 NSFW、R3、R4 的缺失状态不因本次改变。

R2 只接收压缩图片、原始标签优先合并 WD 的标签、style 模式和评级策略；原始自然语言仅传 R5。R5 可以绑定文本模型，文本模型不附图。两者均通过全局协议服务调用，沿用超时、取消、令牌轮换、严格 JSON 和本地检查。

R2 成功必须同时返回 `vision_tags: list[str]` 和 `vision_description: str`，允许显式双空；拒答只能返回 `status=refused_nsfw` 与 reason。标签不允许权重或提示词语法，写入 conf=null。R5 返回四级评级或 uncertain。reason 不写入项目。

评级顺序为：可靠缓存 → 本地关键词精确匹配取最高级 → 显式启用的 R5 → 用户选择的兜底。detector 保持预留，不虚构检测结果。默认 D1 为空、R5 关闭、普通兜底不写可靠评级。导入只运行本地关键词，无网络调用。

general/sensitive 使用普通视觉角色；questionable/explicit 使用 NSFW 角色。普通角色拒答后 CAS 写入 questionable/refusal/verified=true，再重路由一次；NSFW 角色缺失记 skipped/role_empty，再拒答记 skipped/refusal_repeated。nsfwfallback 写 questionable/fallback/verified=false。严格保留 R0 对所有未验证请求的原规则，没有采用 C10 的放宽建议。

关键词和输出禁用词保存在产品目录 `vision-policy/current.json` 与 `<hash>.json`。默认服务路径为 `%APPDATA%/StyleLoraAutom/vision-policy`；测试和显式独立产品目录按运行参数隔离。已冻结任务使用原词表摘要，后续编辑不改变其语义。

## 写入、缓存与恢复

- 项目快照只含安全角色投影、模型/协议、参数、模板和词表摘要，不保存 URL、token、binding ID、完整提示词或图片字节。恢复重新解析角色并核对投影，不静默换模型或模板。
- 发送前读取并核验原图 SHA-256；提交时再次检查文件、评级四列、输入及 LLM 输出层 refs。用户在 R2 之前改评级可本地重新求值一次，不重复调用 R5；R2 已发送后发生冲突则丢弃结果。
- 标签和描述使用一个 outcome、同一事务记账；中间故障整组回滚。新响应使用内部 paired_job 追加策略，即使旧标签单层缓存匹配也不会拼接到新描述上；cache_hit 必须是同一次旧 outcome 的两层 current、同一模型与 params。
- 缓存包含证据内容、图像指纹、评级路由、模型/协议、实际图像档位、模板/词表与模式参数；不含 rated_at、任务 ID 或证据 annotation_id。人工编辑不是模型输入。历史版本不能作为 current 缓存复活。
- uncovered/selected 可以复用完整当前缓存；all 始终追加新结果。无效 JSON、风格禁用词、待语义复核表达、图片变化或冲突不会清空旧层。
- 暂停停止后续派发，已接受的最多两张可以结束；取消先持久化再丢弃迟到结果，并释放待写内存。关闭/重开项目后中断任务保持 paused，不自动继续付费调用。
- Busy 和提交未知先重试/查证，进程内恢复复用已收到的 R5/视觉结果。若进程在结果提交前崩溃，恢复未完成图片可能再次调用供应商；不保证供应商侧幂等或不重复计费。
- 两条视觉路由共用 JSON 修复预算和已降档的实际图像档位，避免 NSFW 重路由回升到原始大图。

## HTTP 合同

| 方法与路径 | 用途 |
|---|---|
| GET `/api/executors/capabilities` | WD 和 llm_vision 能力，标明 combined_batch=false、style 模式及字面检查边界 |
| GET/PUT `/api/llm/vision-policy` | 读写全局分级关键词/输出禁用词；写入要求 If-Match |
| POST `/api/projects/{pid}/jobs/batches` | executors=["llm_vision"]，冻结 scope/mode/config；202 与持久 job 地址 |
| GET 项目 `/jobs`、`/jobs/{id}`、`/jobs/{id}/outcomes` | 任务及结果分页；支持 executor=llm_vision |
| POST 项目 `/jobs/{id}/control` | pause/resume/cancel，If-Match；沿用 SSE 和幂等键 |
| PATCH 项目 `/images/{id}` | 人工 rating；If-Match |
| POST 项目 `/ratings/reclassify` | scope/config → 202 operation；不创建虚构的 rating executor job |

视觉 config 只接受 dataset_mode_policy=style、use_rating_model、fallback、max_tokens、timeout_s、transport_retry_limit。页面显式说明发送的数据和费用可能性。页面加载、能力查询、导入和项目重开不调用付费模型。WD 与 LLM 当前仍各用一个批次，不接受组合 executors。
