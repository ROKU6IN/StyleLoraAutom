后续更新：0.56.0 增加独立的显式网络诊断选项，见 [显式网络诊断验收](63-F11-显式网络诊断验收.md)。下文记录 0.55.0；不加网络选项时仍保持这里的离线行为。

版本：0.55.0。日期：2026-10-29。补充 F11 §9 和 0.42.0 doctor 的可选内容检查。

## 使用方式

```powershell
./scripts/run.ps1 doctor --verify-content --json
./scripts/run.ps1 doctor --project "E:\datasets\example.slproj" --verify-content --content-timeout 120 --json
```

`--verify-content` 显式启用模型与项目内容检查；没有 `--project` 时只核验已安装的内置审核模型，仍执行原有环境和配置诊断。没有安装模型是可选依赖缺失，不尝试下载，不视作内容验证成功。

`--content-timeout` 必须与内容检查同用，允许 5–600 整数秒，默认 120。每个模型、每个项目分别计时，不是整份报告的总时限。逐块文件读取及 SQLite 指令进度回调检查截止时间；一次操作系统读取或 SQLite 原生函数可能超过截止点，返回后停止后续工作，不承诺强制进程级截止。Ctrl+C 释放锁和文件句柄、退出 130，不打印完整成功报告。

不加选项的默认诊断保持 `scope=offline_metadata`，不打开项目 SQLite、不计算完整模型摘要。启用后为 `scope=offline_content`；所有模式仍返回单个 JSON、`network_probed=false`、`repairs_performed=false`。报告不携带项目名称、提示词、行内容、原始 SQL、绝对路径或凭据；失败只输出错误码及固定结构。

## 模型核验

仅使用包内已审核清单。`ready.json` 必须与清单完全一致，两个文件均须为预期大小；固定只读文件句柄后按 1 MiB 流式计算 SHA-256，核对读取总量、摘要和前后文件身份。Windows 句柄拒绝同时写入和删除；路径在规范化前后都检查链接及 reparse point，支持 Windows 应用目录映射。

成功为 `tagger:content_verified`，含 `content_verified=true`、`verified_files` 和 `verified_bytes`。相同大小的篡改、缺文件、坏清单、占用、截止时间均不能返回成功。无模型为 `tagger:not_installed`，`content_verified=false`。哈希只证明内容与已审核版本一致，不加载 ONNX/CSV、不运行张量校验或推理，不作为 CPU 性能与标签质量验收的替代。

## 项目核验

继续持有既有项目只读锁、目录、元数据和数据库文件句柄；项目被服务打开时退出 4，不抢锁。先核对格式版本和文件头，再检查以下恢复线索：`project.db-wal`、`project.db-shm`、`project.db-journal`、`.migration-state.json` 或非空 `images/.pending`。任何一项存在都返回 `doctor:project_requires_recovery`、退出 7，不打开 SQLite，不读取回执内容或清理文件。

只有稳定且无上述线索的主库才以编码后的 `mode=ro&immutable=1` URI 打开。限制数据库 8 GiB、SQLite 单值 16 MiB，开启 query_only、关闭 trusted_schema 与扩展加载，授权器只放行查询、固定诊断 PRAGMA 及内置约束必需的少量函数。

检查 `user_version` 与元数据/支持版本一致，表和索引定义与包内基准完全一致，拒绝额外视图、触发器及其他结构；随后执行 `integrity_check`、内置 CHECK 条件验证、`foreign_key_check`。当前 SQLite 3.53.1 在只读数据库加载时省略 CHECK 表达式，因此不能单靠只读 `integrity_check` 判定约束有效；实现显式执行从可信包内 DDL 提取的 CHECK 条件，不执行项目自带 SQL。[SQLite 3.53.1 官方源码](https://raw.githubusercontent.com/sqlite/sqlite/version-3.53.1/src/build.c)

成功为 `project:integrity_valid`，`sqlite_opened`、`schema_checked`、`integrity_checked`、`check_constraints_checked`、`foreign_keys_checked` 均为 true；`opened=false` 表示未经过项目服务打开，`image_content_checked=false` 明确不核验原图。检查结束前再次核对文件身份与恢复线索，关闭 SQLite 后释放句柄与锁。

本阶段不做项目业务记录间的全部不变量校验、原图逐文件哈希、历史回执对账、迁移、自动恢复或任何修复。遇到恢复线索可先按既有项目恢复流程处理并正常关闭，再重新诊断；不要为了让检查通过手工删除 WAL/回执。

## 错误和退出码

| 情况 | 典型错误码 | 退出码 |
| --- | --- | --- |
| 全部检查通过或可选模型未安装 | `project:integrity_valid` / `tagger:not_installed` | 0 |
| 选项组合或超时范围不合法 | 参数解析错误 | 2 |
| 项目或模型文件被占用 | `project:locked` / `image:file_busy` | 4 |
| 摘要、结构、约束、外键或数据库损坏 | `tagger:checksum_mismatch` / `doctor:schema_mismatch` / `doctor:database_corrupt` / `doctor:foreign_key_violation` | 5 |
| 原有平台能力缺失 | 沿用既有能力错误码 | 6 |
| 恢复线索、版本不一致、库过大、检查超时 | `doctor:project_requires_recovery` / `project:version_mismatch` / `doctor:database_too_large` / `doctor:content_timeout` | 7 |
| 用户中断 | 不输出完整成功 JSON | 130 |

多项问题仍按 5、4、7、6、0 汇总，每项保留独立结果。一次完整诊断可能因此返回其他配置或平台错误，即使内容项本身通过。
