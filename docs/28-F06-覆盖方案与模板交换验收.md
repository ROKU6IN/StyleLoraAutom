版本：0.21.0；日期：2026-10-26。依据 [F06/F07 设计](F06-F07-提示词生产设计.md) §4–5、§7 与 Q01 继续本地实现。未修改项目数据库 schema，未初始化、提交或上传 Git。

## 本地方案与采样

提示词生产增加“管理覆盖方案”入口。独立编辑页支持新建、编辑、校验、复制、保存，以及 JSON/YAML 文件导入导出。初始模板沿用 scene×lighting 六格、无人物至少 15%、远景至少 10%；模板中的 name 可编辑，plan 包含规则、目标数量和随机种子。校验只证明结构符合合同，不代表当前词典有足够候选，仍须走现有采样预览。

返回提示词生产后，选择本地方案并明确点击“载入并替换覆盖设置”，复制覆盖规则、数量和种子，启用格子配额并使旧采样预览失效。不会自动更改所选词典、精修开关、角色或围栏。创建任务继续冻结实际 Plan、词典和既有依赖，不记录 coverage_id；修改方案不改变旧任务，项目来源也不依赖方案文件。

方案编辑页接入现有草稿离页保护。切换方案、重新载入或离开时，可保存、放弃或继续编辑；版本冲突保留草稿。文件先完成解码和校验，再询问如何处理旧草稿；无效文件不会清空原内容。导出和复制只对已保存、没有未保存修改的版本开放。

浏览器编辑器把整个模板作为文本发送给后端，不先转为 JavaScript 数字。模板和 API 完整保留 uint64 种子；读取摘要的 random_seed 是字符串或 null。浏览器采样沿用安全整数范围 0–9007199254740991；更大的种子仍可编辑、保存、交换，但载入采样时明确报错，不做四舍五入。null 仍表示由服务端在任务冻结时生成种子。

## 持久化与 HTTP 合同

产品目录下 `coverage/<uuid>.json` 保存 JSON 运行数据，沿用 ProductFiles 的 UUID、路径/链接检查、摘要封装和原子替换。每项包含规范化模板、coverage_id、revision 与最小请求回执，不写 project.db，也不包含项目、来源或模型凭据。最多 2048 项；每项最多 4096 个保存回执。不自动删除历史回执。

更新使用 If-Match 校验 version。缺失返回 428，冲突返回 409。POST/PUT 要求 UUID Idempotency-Key；同一请求重放返回原回执，改正文或用创建键创建另一方案返回冲突。回执和正文一并原子提交，写盘失败保留旧文件；重启后仍能识别重复保存。未知保存结果的前端重试保留相同 ID 和请求键。损坏文件报错并保留，不当作新方案覆盖。

所有路由在 `/api/prompt-production` 下，使用既有会话鉴权、Origin 与传输边界：

| 方法与路径 | 行为 |
|---|---|
| GET `/coverage-plans` | 分页摘要，列表版本变化使旧游标失效；不返回整份模板 |
| GET `/coverage-plans/{id}` | coverage_id/revision/version、展示摘要与 UTF-8 JSON 模板文本 |
| POST `/coverage-plans/preview` | 校验 `{format, content}`；返回规范化模板和摘要，无落盘/任务/模型调用 |
| POST `/coverage-plans` | `{coverage_id, format, content}`，创建本地方案，201 |
| PUT `/coverage-plans/{id}` | `{format, content}`，CAS 更新，200 |
| GET `/coverage-plans/{id}/export?format=json\|yaml` | JSON 响应内的 filename/media_type/content，浏览器据此下载文件 |

保存可以直接提交合法模板，不要求临时预览 token。正文含模板原文，服务端在提交时重新校验；预览不承诺候选可用性或冻结词典。文件格式仅为 `json` 或 `yaml`，`.yml` 文件在 UI 映射为 yaml。

## 交换格式与输入界限

可移植模板只包含 `schema_version`、`name`、`plan`。导出不带 coverage_id、revision、version、存储摘要或幂等回执，导入生成新草稿/新 ID，不覆盖已有方案。示例（省略的 Plan 字段按同一 schema 补全）：

```yaml
schema_version: 1
name: 场景与光线覆盖
plan:
  schema_version: 1
  algorithm_version: coverage-v1
  primary_dimensions: [scene, lighting]
  cell_values:
    scene: [forest, beach, city street]
    lighting: [sunlight, night]
  cell_weights: {}
  exclude: []
  no_humans_excludes: [appearance, clothing, pose, expression]
  constraints:
    - dimension: count
      tag: no humans
      minimum_ratio: 0.15
    - dimension: view
      tag: wide shot
      minimum_ratio: 0.1
  target_count: 100
  random_seed: 42
```

UTF-8，可带 BOM；导入/导出文件上限 1 MiB，结构上限 32 层、100000 节点。JSON 与 YAML 使用同一严格 Template/Plan 校验，拒绝未知字段、非有限数、布尔冒充整数/比例、超限数量/种子，以及不存在的规范格子权重键。语义不可满足的合法约束仍由采样报告区分无解与搜索耗尽。

YAML 使用固定 [PyYAML 6.0.3](https://pypi.org/project/PyYAML/6.0.3/) 的 [SafeLoader](https://pyyaml.org/wiki/PyYAMLDocumentation)，加上构造前的深度/节点限制、锚点和别名拒绝、类型白名单和重复键检查。只接受 JSON 可表达的 map/seq/str/int/float/bool/null，不支持自定义对象、时间戳、二进制、set、合并键、多文档或非字符串 map 键。按 SafeLoader 规则会被识别为布尔/数值的标签文本应加引号；导出器会写出需要的引号。没有文件包含、表达式执行或网络取数。PyYAML 已加入 pyproject.toml，并安装到本机 CPU/GPU 两个虚拟环境。
