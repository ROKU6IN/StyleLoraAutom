## 本轮交付

| 范围 | 实际行为 |
|---|---|
| 导入/导出方案 | 项目内列表、创建、读取、编辑、删除；默认导入方案切换；严格配置校验、版本冲突、幂等写入 |
| 工作台 | 新增“导入导出方案”页，导入/导出页选择方案；编辑草稿导航保护；并发冲突保留草稿 |
| 词库解析 | `comma-v1` 保留原始片段和字符偏移，识别 canonical/alias/unknown/unverifiable；已验证别名折叠为规范标签 |
| 导入预检 | 全清单验证图片和 TXT，展示解析结果和错误；有阻断错误不能确认，不创建来源、不复制图片 |
| 恢复 | 来源冻结解析参数、方案快照、词库版本与文件哈希；产品目录保存版本归档，恢复使用原版本 |
| 触发词 | 普通单行标签校验、全部来源风格描述冲突、已有 canonical/alias 碰撞和无法验证状态 |
| 导出 | 来源/审核筛选、标签层与优先级、WD 阈值及空置信度策略、NL 选择、blocklist 模式、自定义命名和相对子目录、PNG 元数据 JSON、非空内容检查 |
| 发布产物 | 先固定数据快照，再在事务外写图片/TXT/JSON；完整文件对和完整目录发布；旧目录不覆盖 |

数据库仍为 F01 schema v1、8 张表，无结构迁移。配置通过已有 import_schemes/export_schemes 保存，不新增项目表，不将整份词库塞进项目。

## 使用

在仓库根目录运行 `./scripts/run.ps1 serve`。页面中先导入本地标签资料，再到“导入导出方案”创建配置。已有默认导入方案保留首行全部作为标签的兼容模式；新建方案默认词库识别。导入和导出页都可选择方案并调整少量当次选项，这些覆盖值不回写保存的方案。

标准 TXT：首行为逗号分隔内容，空行之后为描述。例如词库包含 blue_hair、smile，azure_hair 是 blue_hair 的别名：

```text
azure_hair, smile, 画面说明

原始段落。
```

词库方案解析成 original/tags 的 `blue hair, smile`，original/nl 的 `画面说明\n原始段落。`。未知片段只在明确有空行时归入 NL；没有空行时判为歧义。空 TXT 仍区别于缺失 TXT。词库缺失时拒绝使用词库方案，允许改选兼容模式。

权重、转义、跨逗号括号、BREAK/AND/管道控制符只识别，不求值、不剥除。已知消歧标签如 `name (series)` 可作为普通标签；无法验证的括号内容报错。原始 token 的 raw、normalized、lookup、syntax、weight、字符偏移保存在成功导入的原始标注参数中。权重识别出的数值不等于支持权重导入。

预检处理全部输入；最多显示 100 项，错误优先。每项展示的标签、描述和诊断片段有长度限制，节选不影响实际导入。第 101 项及后续项出错同样阻止导入。文件或方案在预览后变化时，开始任务会拒绝过期计划。

导出方案中的 `{stem}` 指项目 `images.filename` 主干，不是外部原文件路径。输出均置于新的版本目录中；子目录只能是安全相对路径。非空标签条件排除触发词本身。新格式方案的 JSON 是 `png_meta_json` 原值，无值写 JSON null；既有旧格式方案仍保持原来的包裹式 JSON 兼容输出，保存为新格式后使用新语义。

## API、并发与版本归档

项目接口前缀为 `/api/projects/{project_id}`：

- `GET/POST /import-schemes`、`GET/PUT/DELETE /import-schemes/{id}`。
- `POST /import-schemes/{id}/set-default`，请求 `{expected_versions:{"旧ID":"版本","新ID":"版本"}}`。
- 删除导入方案用 `X-Expected-Versions` JSON 请求头；删除默认项时加 `?replacement_default_id=...`，同时携带被删项和替代项版本。默认切换与删除为一个事务，错误不改变任何一项。
- `GET/POST /export-schemes`、`GET/PUT/DELETE /export-schemes/{id}`。PUT 与导出 DELETE 使用 If-Match，最后一个方案不能删除。
- 新写请求使用 UUID Idempotency-Key。PUT 即使内容相同也先核对版本。前端保留当前保存/确认操作的重试键，不自动重试不确定结果。
- `POST /imports/preview` 与 `POST /exports/preview` 接受 scheme_id，省略时使用默认导入方案/第一个导出方案。确认执行仍需 preview_id 和 digest。
- `POST /api/validation/trigger` 接受 `{trigger,project_id}` 或 `{trigger,style_prompts}`，返回状态、issues、digest、override_digest、can_override。正常诊断包括硬错误时返回 200；非法请求格式 422。正式导出拒绝硬错误。
- `GET /api/exchange/capabilities` 提供当前执行能力和严格默认配置；新增 `scheme.changed` 事件供 UI 刷新。

词库归档位于产品资料目录的 `catalog-versions/<revision>.json`，使用临时文件、fsync、原子替换，并检查内容摘要。来源只记录 revision；归档包含当时的规范词、别名、类别及翻译补充词条，不包含账户凭据。重载产品库后旧归档仍可读取。方案被删除或词库被替换，不影响暂停来源按已冻结内容恢复；原快照缺失或损坏时必须恢复快照，不静默改用新词库。不会自动清理可能仍被项目引用的旧版本。

导出预览绑定方案、图像/标注、项目触发词、来源风格和词库版本。确认前词库变化直接拒绝；数据或方案变化在执行快照校验时拒绝，输出目录尚未创建。开始写文件后使用任务已经固定的数据，不中途换配置。

## 触发词门禁与明确边界

已有标签或别名碰撞属于可确认警告。浏览器必须勾选确认，HTTP 必须发送该次预览返回的 `trigger_override_digest`；该摘要绑定规范化 trigger、词库版本和风格集合。旧的 HTTP `allow_existing_trigger` 布尔值不能绕过此门禁。导出报告保存确认摘要。来源 style_prompt 中包含触发词属于硬错误，无法强制通过。

Q05 的“词库缺失/无法验证是否严格阻止导出”仍是设计待决项。本轮保留既有兼容行为：无词库、非完整词库或无法判断的风格语法明确显示 unverifiable 警告，允许兼容导出，不声明通过全量唯一性校验。词库 complete 仍仅代表用户资料的声明，不代表程序验证了 Danbooru 全量覆盖。本轮没有下载词库或调用 Launcher 搜索来证明标签不存在。
