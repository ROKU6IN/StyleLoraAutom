## 命令和基本流程

先保持 `./scripts/run.ps1 serve --no-browser` 运行，用 project open 打开项目并由 project status 获取当前 project_id。命令仅附着已有实例，不自动启动服务或切换项目。

```powershell
./scripts/run.ps1 export --help
./scripts/run.ps1 project status
./scripts/run.ps1 api GET /api/projects/<project_id>/export-schemes
```

preview 可选 --scheme 编号，省略时使用项目默认方案。--options 接受严格 ExportOptionsInput JSON，包括 include_nl、include_unreviewed、include_json、source_ids、blocked_tags、blocklist_mode。可空开关保留 null 以继承方案；不支持任意路径、密钥或未知字段。例 options.json：

```json
{"include_nl": true, "include_json": true}
```

旧 allow_existing_trigger=true 布尔标志在 CLI 中拒绝，不能替代当前预览的警告摘要。服务预览仍可展示已有标签警告，不隐式授权实际导出。

```powershell
$lines = ./scripts/run.ps1 export preview --project-id <project_id> --options .\options.json
$previewExit = $LASTEXITCODE
if ($previewExit -notin @(0, 6)) { throw '预览失败，请查看返回错误' }
$text = $lines -join [Environment]::NewLine
[IO.File]::WriteAllText((Join-Path (Get-Location) 'export-plan.json'), $text, [Text.UTF8Encoding]::new($false))
$preview = $text | ConvertFrom-Json
$preview.plan.preview | ConvertTo-Json -Depth 30
$preview.confirmation_digest
```

preview 等待后台扫描完成，不生成导出目录或文件。审核 scheme、output_config、caption_config、trigger_validation、warnings、images 的 ready/skipped/failed 状态与原因，以及预览文本。存在逐图失败时退出 6，仍可明确审核计划并导出其它可用项；语法、风格词冲突等硬错误沿用服务失败语义，不产生可提交计划。目录资料不完整的 unverifiable 警告仍展示，不能把它解释成“触发词已验证无冲突”。

```powershell
./scripts/run.ps1 export run --preview .\export-plan.json --confirm-digest <confirmation_digest> --detach
./scripts/run.ps1 export status <export_id> --project-id <project_id> --wait
./scripts/run.ps1 export report <export_id> --project-id <project_id>
./scripts/run.ps1 export list --project-id <project_id> --limit 20
```

run 默认 --wait，直到该 export_id 不再 planned/running；--detach 返回 status=accepted 与 export_status（受理响应当时的真实状态）、export_id、operation_id 和 status_url，不宣称已导出。status 默认读一次，加 --wait 等待终态。run/status 的 finished 若 failed>0 返回 6；完整成功返回 0。拒绝、审核过滤、缺失等跳过项不被自动改成失败，skipped 与原因仍在报告中。

list 每次读取一页，可用 --cursor 继续；不自动翻页或合并不同时点。list 可省略 --project-id 查询当前项目，其它带导出身份的命令要求明确项目句柄。report 保留服务原始完整报告并附 cli 元数据，包括 counts、images、文件列表、标签频率、跳过/失败原因、方案、触发词与排序信息；报告有失败项时退出 6。

## 两类独立确认

计划 confirmation_digest 仅确认计划整体。若 trigger_validation.can_override=true，必须额外传它的 override_digest；只有已有标签警告允许此类确认，风格词/语法硬冲突没有强制入口。

```powershell
./scripts/run.ps1 export run --preview .\export-plan.json --confirm-digest <confirmation_digest> --accept-trigger-warning <override_digest>
```

方案采用 hardlink 时，必须额外传 preview.hardlink_ack_digest。它绑定该次内容计划，表示明确接受导出图像与项目图像共享文件内容。硬链接导出后修改任一链接的内容可能影响另一处；默认 copy 无此共享行为。CLI 不把确认摘要自动填入提交参数：

```powershell
./scripts/run.ps1 export run --preview .\export-plan.json --confirm-digest <confirmation_digest> --accept-hardlink <hardlink_ack_digest>
```

同时需要两类确认时，两个开关都要明确提供。缺少、错误、跨模式或不需要却提供的摘要在附着前拒绝；把确认值直接写进计划的 body 也拒绝，不能将预览文件当作隐式授权。参数有效后生成唯一规范请求体，保存到 cli.request。服务仍复验目录资料、内容计划、后端文件身份与硬链接条件；变化不会被 CLI 自动确认、切换为 copy 或重新预览。

## 计划与响应丢失

计划 schema_version=1 包含 instance_id、project_id、idempotency_key、ExportStart body 和完整 preview。body 固定 scheme_id、preview_id、digest，两类确认字段在保存计划中均为 null。整体 SHA-256 覆盖计划；run 校验严格结构、预览引用与模式一致性、整体摘要，再检查本次命令给出的独立确认。此摘要是本地一致性检查，不是服务签名。

options 与计划文件均为严格 UTF-8（允许 BOM），最大 16 MiB，拒绝重复键、非有限数字及错误类型。成功预览的完整格式化输出也受同一上限约束；过大返回 export:plan_too_large，不输出不可重读的成功计划。输出目录和报告 URL 仅接受当前项目的预期格式；CLI 自行构造 HTTP 路径，不跟随响应提供的任意地址。

提交前记录 cli.request 的 method/path/body/idempotency_key；受理后记录导出和操作身份。超时、重定向、无效身份或无效受理响应按结果未知退出 7，不自动重发。明确重复使用原计划、原确认参数和原实例时，服务使用相同请求键返回原导出，不再发布新目录。默认等待会再查询最新状态；--detach 的受理结果可能是会话缓存的历史状态，应另外 status 核对。

预览若已受理，可直接从原操作读取恢复计划，不再次扫描：

```powershell
./scripts/run.ps1 export preview --operation-id <operation_id> --project-id <project_id>
```

--operation-id 不能同时携带 scheme/options/请求键。该命令等待原 export.preview 操作，并从结果创建一份新的 CLI 运行计划；它不启动导出。恢复预览只应在准备新的明确提交时使用，已经保存并提交过的计划应继续使用原计划/导出身份核对，避免人为换新请求键创建另一份输出。

预览响应在返回 operation_id 前丢失时，可带相同输入与原请求键重放：

```powershell
./scripts/run.ps1 export preview --project-id <original_project_id> --instance-id <original_instance_id> --idempotency-key <original_key> --options .\original-options.json
```

预览恢复不延长服务原预览期限，run 的方案、图片、标注或目录资料校验失败时原样返回。后台失败会附 operation 错误诊断；等待模式会等失败操作完成诊断，避免因来源视图先更新而遗漏具体冲突原因。未识别的后台失败统一返回 5，保留 error.code；未知提交结果保持退出 7。

## 取消、重启和持久报告

```powershell
./scripts/run.ps1 export cancel <export_id> --project-id <project_id>
./scripts/run.ps1 export cancel <export_id> --project-id <project_id> --detach
```

cancel 默认读取当前版本、以 If-Match 提交一次取消，再等待实际终态。只有实际 canceled 才以退出 0 表示取消目标达到；如果发布抢先完成，保留 finished 并退出 7，不能声称已经取消。--detach 返回 cancel_requested=true 和真实 status，退出 0 只表示取消请求受理。已完成导出沿用服务的 export:already_finished 冲突；取消不删除已发布输出，也不自动清理临时目录。

显式重放取消要求原实例、版本与请求键，提交阶段不用新 GET 覆盖旧版本：

```powershell
./scripts/run.ps1 export cancel <export_id> --project-id <project_id> --instance-id <original_instance_id> --if-match <original_version> --idempotency-key <original_key>
```

run/status/cancel 等待中 Ctrl+C 退出 130，只停止本客户端等待，已受理导出继续；明确 cancel 才改变后台状态。输出保留已知 export_id、operation_id 或写请求身份，可据此核对。

服务重启后不能运行旧实例计划。重新打开原项目、取得新的 project_id 后，使用持久 export_id 查询 status/report/list。服务继续通过已有导出报告或 .export-state.json 恢复历史；恢复项的 operation_id 可为 null，不要求旧内存操作仍存在。中断项保留 interrupted 与暂存目录信息，不自动继续或接管未知目录。cleaned/cleanup_partial 也不会当作 finished 成功输出；report 仍只允许完成且可读的结果。

stdout 默认单个 JSON，--json 可省略；受理/中断进度写 stderr。输出不包含 Bearer token、原始异常或 spec 绝对路径；正常提示词、图像相对路径、项目元数据和导出报告内容沿用服务合同。

## 兼容性与退出码

旧 `export PROJECT [旧选项]` 保持原行为和退出码；`export preview/run/list/status/report/cancel` 与 `export --help` 进入新服务入口。旧相对项目目录恰好同名时，使用绝对路径或 `./preview` 等显式路径避免子命令歧义。导出期间仍遵守产品/项目锁，离线入口不能同时直接占用服务已打开的项目。

| 码 | 新入口含义 |
|---|---|
| 0 | 可用预览；导出完整完成；列表/完整报告读取成功；--detach 已受理；默认 cancel 实际达到 canceled |
| 2 | 参数、文件、计划、确认摘要不合法/缺失/过大 |
| 3 | 无运行实例或认证不可用 |
| 4 | 实例/项目/版本/状态/预览冲突；预览过期；报告尚不可用；后台已识别的版本冲突 |
| 5 | 依赖/I/O/读取失败、无效查询结果或后台失败（包括服务的硬阻断错误） |
| 6 | 预览含逐图失败；完成的导出/报告存在 failed 项 |
| 7 | 尚在运行、取消/中断/清理状态、结果未知，或取消未达到目标状态 |
| 130 | 客户端中断，已受理工作继续 |

预览展示已有标签/硬链接警告本身不等于失败；对应确认仍必须在 run 明确提供。无可导出项/全部跳过沿用服务报告和计数，不在 CLI 中伪造失败或改变筛选范围。
