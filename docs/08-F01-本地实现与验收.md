## 3. 实现约定

- 不增加第九张表或额外项目字段，保留原有历史；没有物理删除 images/annotations/items/jobs/log 的公开接口。
- 不使用 ORM，不为 F01 引入 FastAPI 或第三方测试依赖。后续 API 层桥接 Future 即可。
- 项目 source/job/规则配置拒绝产品端点、令牌和外部绝对路径。原始 PNG 元数据按原数据保留，不用于解析产品凭据。
- 只有对应 command 能写 original/manual/rule 或模型结果。手工/规则的 merge_meta 由服务生成，调用方不能自造证据 ID 或移除边界。
- RulePlan 的 changes 由后续 F09 计算；make_rule_plan 捕获完整读集并冻结范围，F01 不承担规则匹配算法。
- prepare_artifact 接受 F05 已验证的图像信息，核对并刷新文件指纹、写收据；F01 不实现图像解码或原始提示词解析。
- 没有收据、收据损坏或文件归属不确定时，保持 sent，报告 unresolved。仅明确 absent 证据可使 sent 变 failed；不发任何外部请求。
- 非空导出处理器链可保存，执行明确报 UnsupportedScheme。prompt_pyramid 没有适配器时明确报 UnsupportedSorter。
- NAI 生成源启动快照使用 schema_version、profile（model/sampler/steps/scale/quality_toggle/uc_preset）、sizes（三组 width/height）和 default_aspect。模型能力校验仍由 F02 负责。
- 导入源快照使用 schema_version、reader、params 和 import_manifest（seq/path）；path 为选定导入根内相对位置，不存外部根目录。

## 4. 本次验证边界

- 生产格式是初版 v1。没有已发布的旧格式，注册表不伪造 v0 升级；迁移引擎通过隔离的 v1→v2 测试迁移验证，测试补丁不会进入生产注册表。
- 崩溃测试通过可控故障点模拟提交窗口，使用真实 SQLite 文件、WAL、重开项目和子进程锁；不等于对实际断电、损坏硬盘或所有文件系统做过验证。
- 批量规则上限为 5000 图/16 MiB 预览预算。已经验证提前拒绝、分页与 SQL 变量上限；尚未完成真实大图库的容量基准。
- F02/F05 的真实 Launcher 调用、图像解码、WD/LLM 推理、前端、HTTP API、完整导入导出仍属后续模块；本次不消耗 Anlas 或模型额度。
