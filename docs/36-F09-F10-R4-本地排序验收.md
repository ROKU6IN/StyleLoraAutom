# F09–F10 / R4 本地标签排序实现与验收

日期：2026-10-26；版本：0.29.0。仅本地开发、测试与打包，未初始化、提交或上传 Git。

## 范围

落实 F09–F10 §8、C13、T16 和 05 §10.3 的 prompt_pyramid 适配。默认 layer_first 保持；用户在导出方案明确选择“本地金字塔排序”后生效，HTTP 与 CLI 使用相同方案。R4 不调用模型、不增加 jobs、不写原始标注/来源/规则操作记录，也不改变 F06 的 R1 生成或精修顺序。

内容顺序为主体 → 动作表情 → 服装 → 构图 → 场景 → 光照 → 未分类。组内保留原相对顺序，触发词由 F01 合并器去掉内容重复项后固定放最前。全局重排不推断多人物归属或构建人物块。

## 分类依据与边界

`caption/data/prompt_pyramid_v1.json` 含 142 个有限精确条目；配套 Markdown 是 Python 适配器的行为契约，不是发送给模型的提示词。两者随 wheel 发布。本实现依据本项目设计独立适配，没有原样搬入上游 TagCleaner 的删画师、解冲突、去重或另一套排序流程。

| 输入依据 | 分类行为 |
|---|---|
| 已冻结词库的别名 | 只用 canonical 查分类；输出保留输入标签本身，不归并 canonical 与 alias |
| `category=pyramid:subject/action_expression/clothing/composition/scene/lighting` | 采用用户明确提供的组别，优先于内置表 |
| `category=character` | 主体，不自行添加角色 |
| 缺少 category 或 category=general | 查询内置精确表 |
| artist、copyright、meta、未知 category，或表中不存在的 tag | 未分类，稳定放末尾并计数 |

可通过已有词库 JSON 导入提供明确分类，例如 `{"tag":"custom_lamp","category":"pyramid:lighting"}`。不自动改写词库原生 category；内置分类不覆盖 artist 等原有类别。此功能不是全量 Danbooru 分类器，也不从前后缀、括号或自然语言猜类别；例如 sunset、tree、shirt print 没有被无依据归类。已有 blocklist 仍独立运行，是否移除艺术家/风格标签由原方案决定；排序器自身不得移除它们。

## 合同与一致性

- `caption/sorters.py` 读取有界资源、拒绝重复 JSON 键、未知字段/版本、布尔 schema 版本、错组顺序、跨组重复标签和未规范化/带控制语法的条目。资源缺失或无效时能力不可用，执行在创建导出目录前报 sorter:unsupported，默认层顺序仍可使用。
- 每次导出 snapshot 载入规则，并复制词库 alias/category 到只读映射。metadata 保存 name、version、rules_sha256、skill_hash（本地契约摘要）、catalog_revision、catalog_sha256 和组顺序。它们参与 plan_digest；任何变更都需重做预览，不能复用旧的硬链接确认。
- 进入写文件阶段后只使用已冻结的标签和元数据；文件写入期间规则变化不会改变本次内容。下一次预览读取新规则。没有后台自动更新规则或网络下载。
- F01 排序入口检查输出必须是原标签字符串的精确排列；增删、改名、重复、错误类型返回 SorterContractViolation，HTTP 错误码 sorter:contract_violation / 422。缺少适配器仍报501。该校验与 WD 证据年龄、置信度、manual/rule removal 语义独立。
- NL 保持原内容与优先级，导出图片沿用 copy/hardlink 的校验与发布流程。排序与硬链接可组合，硬链接共享风险确认继续独立检查。

## 页面与报告

“导入导出方案 → 标签排序”默认按标注层顺序，增加本地金字塔选项；资源不可用时禁用该选项并标明原因。已保存但不可执行的方案仍可查看并切回默认排序。

预览显示选用的排序及顺序，每图显示 sorting_counts；未分类标签完整保留在当前 caption 末尾，页面提示数量。报告保留 sorter 元数据、逐图分类计数以及成功导出图片的未分类数量汇总（按图片出现次数计数，非去重标签数）。不向报告追加完整 caption；原有 caption 哈希和频次照常保存。重新打开页面读取既有报告，不重算旧结果。
