# F02–F05 串行调度与未知结果对账验收

日期：2026-10-28。版本：0.35.0。本阶段只在本地开发，所有生成、费用和设置证据来自合成适配器；未调用真实 Launcher/NAI，未上传 Git。

## 实现范围

`generation.runner.SerialDriver` 串起 F03 设置租约、F04 费用关口与 F05 图片登记。内部适配器通过代码注入；生产 Runtime 仍不注册 driver，真实兼容清单仍为空，工作台不能发起真实生成。`CycleAdapter` 是应用内部协议，不是声称 Launcher 已提供的 MCP 字段。

一张 Launcher 对应一个调度槽位，来源按 seq 顺序执行。dispatch 在返回 HTTP 之前保留项目引用，并启动单条后台线程；HTTP 不等待图片生成。重复启动仍复用已有完整投影与幂等规则，不再派发。另一个来源占用调度槽位时拒绝加入队列，不创建第二条生成线程。运行周期与控制串行校验，默认相邻 submit 起点至少一秒。

每周期重新校验能力、读取设置并取得 F03 租约。每张先 prepare，检查完整受控设置的实际值，再依据新估算和当前 cycle 通过 F04 关口。必须先保存估算凭据、mark_sent 提交成功，才允许唯一一次 submit；提交结果未知时没有派发许可。

## prepare 与未知写入屏障

新增项目辅助文件 `images/.operations/<item>/<attempt>.json`，不增加数据库表、列、jobs 或独立运行实体。它只存源/条目/attempt、随机操作关联键、设置 lease 标识、后端身份与请求/配置摘要、是否已结清，不存提示词、路径、凭据、准备令牌或余额。

文件在 prepare 前以原子替换持久保存；替换后报错只读回核对，不重新执行远端写操作。JSON 大小上限 8 KiB，严格字段/类型/摘要校验；损坏记录不能被当作不存在。`closed` 只表示该次准备/生成已得到终止证明，不代表图片可用或费用真实结算。费用暂停后取消已明确结清的 preparation，下一次用户确认才在同一尚未 sent 的 attempt 重新 prepare。

F03 的持久 inflight 屏障从 prepare 开始，覆盖准备、审批/提交与取消的未知结果。适配器的 generation_settled 必须证明这一完整操作及所有迟到效果都已结束；仅检查最近图片列表为空、文件不存在、连接断开或返回超时都不够。`verify_effective` 可带精确 preparation_key，在保持同一持久屏障时核验实际设置。

prepare、submit、cancel、设置操作和恢复查询默认使用 660 秒截止时间。适配器必须实现可取消、有限时的异步 I/O；超时只留下未知状态，没有生成重试、隐式改路径或 attempt 递增。读取异常也先暂停；本阶段没有自动重连或只读退避调度。

## 控制与费用

- 暂停/取消若发生于 mark_sent 之前，只取消 preparation；pending 不变、attempt 不增加。
- mark_sent 成功后，该一次已授权派发仍允许结清；暂停/取消不会启动下一张。取消来源收到迟到完整图片仍登记，但来源保持 canceled。
- ask 非零估算先暂停并取消 preparation。取消结清、设置恢复完成后，现有 HTTP 周期确认可开启新周期，重新 prepare 并使用新的估算。deny 没有确认路径，零估算不被称为免费。
- 运行中修改策略使旧 cycle 失效。旧 preparation 结清后来源暂停，必须显式继续，不留下无人执行的 running 来源。
- 明确拒绝须有同一操作的无产物、无扣费终止证据，sent 才变 failed；本地已有文件与拒绝证据矛盾时保持未知。失败没有自动重试，沿用 F01 手动授权新 attempt。
- 所有条目终态且设置恢复完成后才将 running/paused 变 done；恢复冲突保留用户修改并阻塞后续周期。

## 产物归属及恢复

结果必须同时匹配 operation、instance、contract、item/attempt 对应的请求/配置摘要、费用 grant 和终止证据。完整图片还需适配器证明其确切 caller 归属及内容 SHA-256。F05 在写可恢复收据之前校验这个 SHA-256，随后由原有完整解码、尺寸、Comment 检查与 complete_item 原子登记流程接管。

画风缺失/新增质量词继续登记为 reject，完整图片不会因为元数据检查而自动重生成。哈希不符不会创建能在下次打开时冒认图片的完成收据；损坏图片、身份不符、提交丢响应均保留 sent 并暂停。

内部 `reconcile(context, item_id)` 只调用远端 probe、结清证明及设置读取，可以本地补登记或确认拒绝，绝不 prepare、submit、cancel 或恢复设置。`restore(context, item_id)` 是后续独立内部动作，只有操作已结清才允许执行 F03 的有条件恢复。重复核查不重复入库；登记 COMMIT 后回执丢失时核对原 image_id/哈希，再补记费用与结清。

关闭项目先关闭调度入口，再等待保留的项目引用释放。已授权的在途结果仍可完成登记/恢复，之后关闭数据库；未知操作留下持久屏障供重新打开后核查。重开项目不恢复费用同意或自动发图。界面与 HTTP 暂未开放强制清除、未知操作处置或恢复写入按钮。
