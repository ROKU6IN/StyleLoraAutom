# F06/F07 精修与词典回写验收

版本：0.18.0；日期：2026-10-26。依据 [F06/F07 设计](F06-F07-提示词生产设计.md) §6–7，在 0.17.0 的词典、抽样、HTTP 和冻结 JSON 上继续开发。仅本地修改与构建，不初始化、提交或上传 Git。

## 本阶段交付

- 可选 R1 SFW 精修、R5 未知评级判断，复用已有三协议 LlmService、Windows 密钥存储、全局两路并发和有限传输重试。预览不发模型请求；创建时冻结角色、端点配置摘要、模板全文/哈希、词典、标签库和 D1。
- 每个候选独立请求，两条并发；派发前与阶段完成后写入持久任务。UI 展示处理计数、原值、精修结果与原因，冻结结果按候选优先序排序，与异步完成顺序无关。
- R1 严格 JSON/schema、首位人数标签、tag_range、NL 开关、图幅提示、added/dropped/out_of_frame 一致性及泄漏检查。内容门禁覆盖字面禁用项、artist 分类、权重、负面、图幅措辞与物体属性例外；已识别的语义不确定模式标为 review_required，不能追加或作为 seed。没有声称规则能证明任意自然语言完全合规。
- 精修之后重新检查 D1 下界、围栏、覆盖格子、规范标签集合去重和全局比例。初始一轮加最多两轮补位，候选不重复派发；不足时 done 但 ready=false，不导出可启动 seeds。
- 最终报告单列输入池是否枚举完整及尚未处理的候选数量。补位预算用完但还有未精修候选时报告 search_exhausted，不把部分输出池不足说成已证明整体无解。
- 新任务的未精修原值也通过 `r1-v1` 内容门禁。旧 0.17.0 已完成结果保持可读；旧本地任务恢复保持其原有本地算法分支。新快照记录门禁版本，避免把规则变化伪装为同一版本重放。
- 手动选取合格结果、预览合并后追加；创建时也可指定目标词典，预先授权任务就绪后只自动追加成功优化的最终选中结果。角色为空或禁用精修时保留的原值不会自动追加。

## 评级与调用边界

组合采用最高已知评级；混合未知项仍未验证。部分 D1 命中只建立下界，不能把剩余未知项全部改成 verified。启用 R5 时，未知 fallback 候选先得到评级机会；仍未知才按 fallback/围栏决定。R5 无法降低已知高等级。

questionable/explicit 走 NSFW 路由，不因用户关闭围栏改走 SFW。C08 的 NSFW 模板尚未提供，保持 `nsfw_contract_missing`，仅保留通过检查且未被围栏拦截的原值，不调用 SFW 模板替代。R1 refused_nsfw 至少升级为 questionable 并复验围栏；invalid_input 为单项语义终态，不重复原请求。

R5/R1 共用一次格式或契约修复预算；无 NSFW 重路由调用时，每候选正常执行最多三次语义调用，每次传输最多尝试三次。300 秒请求时限、两次传输重试由已有服务负责，任务层不再叠加网络重试。未知超时记 failed/llm_outcome_unknown，不自动重发。真实供应商的内容质量、收费、限流参数仍未验收；本轮全部使用 MockTransport。

认证或冻结绑定不可用暂停整批。端点/模型改变时不自动换模型，恢复原配置后可继续；令牌轮换不改变被冻结的配置摘要。若冻结时评级角色为空，应配置角色后新建任务，不向旧快照注入新的模型。

## 持久化与追加

新远端任务使用产品文件 schema_version=2，保留 v1 本地任务读取与恢复。v2 增加 execution 和 appends；输入快照内保存 composer 依赖。文件不含密钥、端点 URL、项目路径或生成源 ID，不写 project.db 的 jobs/images/annotations。未知字段和损坏文件拒绝，不自动覆盖。

暂停停止新派发，接收本代次的在途结果；在途尚未结束时恢复返回 inflight_busy，避免旧代次与新代次同时执行。取消丢弃迟到结果，阻止自动追加。重启把运行任务转为 paused，未落结果的 running 项变为 llm_outcome_unknown，已完成项不会重发；人工重试未知项需新建任务。

写入失败后，进程内暂存已返回结果或已完成的 R5 检查点，恢复先提交缓存，再继续未派发阶段。崩溃会丢失内存缓存，磁盘仍为 running 的远端项只能报告未知；没有宣称外部请求恰好执行或计费一次。原有 32 MiB 输入、64 MiB 任务文件等容量限制继续生效，超限暂停而不删除用户数据。

词典追加使用 task_id、目标和选中内容摘要导出稳定 UUID，先读取词典持久凭据再检查 CAS。词典凭据先落盘、任务标记后落盘；在两文件之间失败，重放核销已有凭据，不重复写条目。目标 revision 冲突保留任务与 seeds，用户重新预览后追加。导入与词典自身的幂等机制继续沿用。

## HTTP 与界面

既有 `/api/prompt-production/coverage/preview` 返回 refinement 预算与冻结角色摘要。`POST /tasks` 接受 optimize、fence.use_rating_model、append_target_id；能力端点相应开放。浏览器通过明确费用确认才能提交模型任务，选择变化或重新预览都会取消旧确认。API 的显式任务请求本身构成调用授权。

新增 `POST /tasks/{id}/append-preview`：target_id、唯一 indices → 预计新增/重复数、任务 revision、目标 version、内容摘要。新增 `POST /tasks/{id}/append`：上述选择及 expected_revision、target_version → 原子 AppendResult。追加仅限完成任务中通过检查的条目。请求响应错误仍走已有脱敏 DTO；事件只发 ID、状态与计数摘要。

结果表按冻结候选索引显示，所以索引可能不连续；导出 seeds 的 seq 始终连续 1..N。手动追加表展示前 100 条供逐项选择，“选择全部合格结果”会读取完整分页结果。支持原值与精修结果对照；尚无对待审核结果直接编辑后复验的界面。
