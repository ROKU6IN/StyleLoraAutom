## 本轮设计裁决与可信来源

原 §5 要求权重和标签表均有发布者 SHA-256。实际官方标签表为普通 Git 对象，官方 API 提供 Git blob SHA-1，没有独立公布的 CSV SHA-256。2026-10-25 用户明确选择“接受官方 Git 摘要验证后固定 SHA-256”。已将这条规则并入 [F12 设计 §5](F08-F12-视觉与执行器设计.md)，没有把本地计算值标成发布者摘要。

审核顺序：先从官方固定 commit 文件树取得 CSV 对象标识和长度；下载 CSV 后核对 `SHA1("blob " + length + NUL + bytes)`；通过后再计算 SHA-256 并固定进内置清单。权重直接使用官方 Git LFS SHA-256。安装/重新校验同时检查文件长度、固定 SHA-256、CSV Git 对象身份、CSV 结构及 ONNX 张量合同。可信依据是固定官方仓库对象与开发审核，不是发布者数字签名。浏览器仍不能登记清单或自行提供可信摘要。

## 实现与使用

新增 `tagging/reviewed_wd.py` 保存固定模型事实和来源说明，`manifests.py` 构造严格不可变清单；`provenance.py` 核对 Git blob 身份；`models.py` 在既有安装与全量校验中执行此核对。`services/tagger.py` 返回审核日期、许可证和摘要来源，前端在“文件与校验信息”中展示。未更改数据库 schema、任务模式、缓存规则或模型下载授权入口。

本机已经从已验收的本地文件安装到 `%LOCALAPPDATA%/StyleLoraAutom/models/wd/wd-eva02-large-tagger-v3/<revision>`；应用启动后按既有设计显示“待校验”。运行 `./scripts/run.ps1 serve`，进入“WD 模型管理”点击“重新校验文件”，然后到“WD 标注任务”选择模型、阈值与范围即可执行。新机器需要显式点击“下载并安装”，不会启动时下载。模型校验通过不自动创建任务。

同一版本存在时只重新校验，不覆盖已发布文件。普通运行不读取测试参考图片、参考源码或 golden；这些都属于开发验收输入。

## 真实 CPU 验收方法

`scripts/accept_wd_cpu.py` 完全离线，必须显式传入已安装模型目录、参考资料目录和新的输出目录。它先核对参考源码与示例图片的固定 SHA-256，才从 AST 中提取发布者的 `Predictor.prepare_image` 方法；不运行下载源码的顶层代码、下载函数或 Gradio 应用。原始 EXIF 图先按本项目图片合同纠正方向，再传入发布者要求的 RGBA 输入。

参考实现固定为 [SmilingWolf/wd-tagger](https://huggingface.co/spaces/SmilingWolf/wd-tagger/blob/fbd35b187d6e8cb8a00c529d52999f82d6b5193b/app.py)，revision `fbd35b187d6e8cb8a00c529d52999f82d6b5193b`。源码 SHA-256 `a6526595fe9582d4307732ac1b3778df8a89a0a69d690e17f91813bf4b0063f7`。示例 `power.jpg` SHA-256 `6fbc5cdb614aaa882067e80abbcc2773c284fdeabccd0ee269364504e9fc0995`，作者归属按发布者演示页标注的 [ほし☆☆☆](https://www.pixiv.net/en/users/43565085)。图片和参考源码仅保存在本地验收目录，不加入发行包。

验收输入是一张真实公开示例和五种确定性变体，共六例：原始 JPEG、竖幅 PNG、横幅、半透明 RGBA、EXIF 旋转、缩小 PNG。它们用于检验预处理和格式兼容，不是六张独立内容样本。每例分别验证：

1. 产品预处理数组与发布者预处理数组逐元素完全相等。
2. 产品 CPU 会话使用 ORT_DISABLE_ALL；参考 CPU 会话使用 ORT 默认图优化，均单线程。所有 10,861 个输出概率满足 `atol=1e-5, rtol=1e-4`，非有限值/数量或范围异常直接失败。
3. 以通用 0.35、角色 0.85 验证最终标签及顺序；参考过滤器独立实现本项目 `>=`、规范化和去重约定，不调用产品 decoder。示例输出中最高分包含 `power (chainsaw man)`、红色角、领带等，人工检查与样例内容相符。
4. 首轮参考输出冻结为 `tests/fixtures/wd-v3/reference-scores.npz`，附 JSON 记录模型清单、参考源码/图片/变体摘要和 NPZ 摘要。后续显式 `--golden` 验收同时核对来源和数值；不自动替换既有 golden。NPZ 使用 `allow_pickle=False`。
5. 同一真实模型经 ASGI TestClient 调用真实 API handler/worker/DAL：导入 6 张、标注 6 张、第二任务 6 次当前缓存命中、不新增标注版本、人工编辑、审核、导出 6 份 TXT、关闭并重开项目后任务记录保留。此处是 ASGI 协议测试，不声称使用独立 TCP 服务。
6. 最终验收补测真实 CPU 调用在途暂停/恢复/取消：只观察推理入口、不伪造概率或延迟；暂停允许当前一图提交，恢复余下图片不重做；取消后的迟到结果不改变 WD 标注版本。损坏文件、提交未知和库忙仍由普通可控回归覆盖。

本机 Intel Core i9-14900K、32 逻辑 CPU，Python 3.12、Pillow 12.3.0、ORT 1.31.0。前两轮测得单图约 5.09 秒，首轮最大概率偏差 `9.5367431640625e-7`；第二轮对固定 golden 最大偏差为 0。进程峰值工作集约 3.77 GiB，包括产品会话、参考会话及 HTTP 验收整个生命周期，不能当作单张图的显存需求。六次推理的时延仅为本机小样本观察，不是吞吐保证。

本验收证明真实模型接入、实现一致性和产品闭环，不证明独立数据集上的准确率、所有角色识别效果或真实 GPU 性能。CPU 单线程基线已可用，GPU 显存档案、动态批调度、Launcher 反推和 F15 仍待实现。

## 复现

根目录 PowerShell，已有本机安装和参考资料时直接运行离线验收；输出目录必须不存在：

```powershell
$env:PYTHONPATH='src'
.venv/Scripts/python.exe scripts/accept_wd_cpu.py `
  --model-dir "$env:LOCALAPPDATA/StyleLoraAutom/models/wd" `
  --reference-dir .test-tmp/wd-real-evidence `
  --golden tests/fixtures/wd-v3/reference-scores.npz `
  --output .test-tmp/wd-cpu-my-check
```

新环境显式下载参考资料和模型（约 1.26 GB）；该命令只从固定官方版本读取，不使用账户凭据或代理环境：

```powershell
.venv/Scripts/python.exe scripts/prepare_wd_cpu.py --download `
  --model-dir .test-tmp/wd-real-models `
  --reference-dir .test-tmp/wd-real-evidence
```

`--local-bundle <目录>` 可替代 `--download`，目录应包含 model.onnx、selected_tags.csv、reference-app.py、reference-power.jpg；复制后仍执行正式 ModelStore 的全部校验，不是导入任意信任模型的接口。参考下载有固定摘要、大小、HTTPS 主机、重定向和总时限限制；已有参考文件不匹配时失败，不覆盖。

本轮单流连接较慢，模型最初通过本地验收辅助脚本从相同官方端点进行 8 路有界 Range 读取；逐段检查 Content-Range/长度，完整权重校验发布者 SHA-256 后，才经正式 ModelStore 本地流安装。产品下载器未改为分段下载，30 分钟总时限仍保留；慢速网络可使用上述本地 bundle 路径。
