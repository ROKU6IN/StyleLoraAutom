## 本轮范围

接续 0.43.0 项目管理 CLI，实现 F11 §9 标注任务命令组。连接已运行的本地 serve 和当前项目，调用现有 jobs/preview、jobs/batches、job/batch control、状态与分页结果接口。创建单阶段或 WD→视觉组合批次，复用持久冻结、模型依赖、缓存和生命周期管理；CLI 不直接运行模型、访问项目 SQLite 或写标注。

本轮细化原设计中 job run 的参数入口：执行器、mode、ids/filter 和 config 先交给 `job preview`，再以保存的完整预览 JSON 和确认摘要运行。这让预览和提交之间的配置变化可被检测，也提前保留批次编号与请求键，便于响应丢失后核对。`all`、大范围和任务重叠都采用同样的显式计划确认，不存在隐式 yes-to-all。

## 使用流程

先运行 `./scripts/run.ps1 serve --no-browser`，并通过 project open 或工作台打开项目。WD 需事先安装模型；视觉任务需事先配置相应 LLM 角色。命令不安装模型、不写密钥、不自动启动服务或切换项目。

WD 的 `wd.json` 使用已安装模型的真实 manifest_id，例如以下结构（摘要占位符需要替换）：

```json
{
  "manifest_id": "<installed_manifest_sha256>",
  "general_threshold": 0.35,
  "character_threshold": 0.85,
  "provider": "cpu",
  "batch_size": 1
}
```

先预览、保存并查看。以下写法明确保存为 UTF-8，兼容旧 PowerShell 默认重定向编码不同的情况：

```powershell
$previewLines = ./scripts/run.ps1 job preview --executor wd --config .\wd.json
if ($LASTEXITCODE -ne 0) { throw '预览失败，请检查命令返回的错误码' }
$previewText = $previewLines -join [Environment]::NewLine
$planFile = Join-Path (Get-Location) 'job-preview.json'
[IO.File]::WriteAllText($planFile, $previewText, [Text.UTF8Encoding]::new($false))
$preview = $previewText | ConvertFrom-Json
$preview.plan | ConvertTo-Json -Depth 20
$preview.confirmation_digest
```

检查范围、配置、覆盖估算和重叠任务后，使用显示的确认摘要：

```powershell
./scripts/run.ps1 job run --preview .\job-preview.json --confirm-digest <confirmation_digest> --detach
./scripts/run.ps1 job list --limit 20
./scripts/run.ps1 job status --batch-id <batch_id> --project-id <project_id> --wait
./scripts/run.ps1 job pause --batch-id <batch_id> --project-id <project_id>
./scripts/run.ps1 job resume --batch-id <batch_id> --project-id <project_id>
./scripts/run.ps1 job cancel --batch-id <batch_id> --project-id <project_id>
# 单阶段操作：JOB_ID 是数字，不是 Operation UUID
./scripts/run.ps1 job status <job_id> --project-id <project_id>
./scripts/run.ps1 job outcomes <job_id> --project-id <project_id> --kind failed --limit 50
```

省略 run 的 --detach 时默认等待整个批次完成；组合任务不会在 WD 完成时提前报告整批成功。resume 默认等待，--detach 只返回控制后的状态。status 默认读取一次，--wait 等待活动任务；遇暂停、取消、失败、依赖阻塞或 pending 的诊断原因则退出并保留状态，不循环自动恢复。

## 参数与计划合同

| 命令/参数 | 语义 |
|---|---|
| preview --executor | wd、llm_vision、wd,llm_vision；逆序输入会规范为 WD→视觉，不允许重复或未知执行器 |
| --mode uncovered | 默认：当前非 reject 图片，允许 --filter FILE；空滤镜由服务执行既有默认范围 |
| --mode selected --ids ... | 明确的 1–5000 个互异正整数 image_id；只能和 selected 搭配，不能并用 filter |
| --mode all | 对筛选范围强制执行；仍须先保存预览，再明确确认计划 |
| --filter FILE | 严格 JobFilter JSON：source_ids、review_statuses、include_missing、rating、file_missing、q；未知字段拒绝 |
| --config FILE | WD 必填；单执行器传对应配置对象，组合传 `{"wd": {...}, "llm_vision": {...}}`；纯视觉可省略，使用现有默认 VisionConfig |
| run --preview FILE --confirm-digest DIGEST | 只接受 preview 输出中的严格计划，使用其中既定项目、实例、批次编号、请求键和 body；不重新预览，不分配新批次，不接受运行时范围/配置覆盖 |
| list | 当前项目批次分页；limit 1–200，cursor 按 URL 参数编码；不自动翻页、不扫描图片 |
| status/pause/resume/cancel | 数字 JOB_ID 或 --batch-id UUID 二选一；必须明确 --project-id，避免同一个数字在另一项目中对应不同任务；--instance-id 可再限定原会话 |
| outcomes | 单 job 逐图结果分页，kind 可为 done/failed/skipped；只读，不重新推理 |

config、filter、plan 文件最多 1 MiB，严格 UTF-8（可带 BOM）；拒绝重复键、非有限数字、错误类型与秘密/未知配置字段。复用现有 HTTP Pydantic DTO 规范默认值；校验错误只输出安全错误码，不打印原文件、异常正文或秘密。JSON stdout 始终为单个对象，--json 可省略；进度写 stderr。

计划包含 schema_version=1、instance_id、project_id、idempotency_key、body（含预分配 batch_id 和 preview_scope_digest）、preview（估算和重叠任务）。confirmation_digest 是整个计划规范 JSON 的 SHA-256；文件内容变化或传入错误摘要在附着前拒绝。摘要是客户端一致性检查，不能充当服务器签名、费用授权或防篡改权限系统。

预览不推理、不调用视觉服务、不建 job。它只表示当时的范围与覆盖估算，不冻结未来的缓存状态、角色绑定、模型环境、标注证据或费用。服务在建批时重新校验范围摘要并冻结其任务快照；范围成员变化返回 job:preview_stale，CLI 不自动生成新预览继续执行。配置/角色/模型依赖变化沿用既有服务校验。视觉执行会使用当前已配置的服务，估算数不等同实际费用。

## 控制、等待与恢复

pause/cancel 先读取目标当前版本，再携带 If-Match 和请求键提交；版本变化即冲突，不更新版本自动重试。单阶段控制只影响该 job，整批控制保持既有 WD→视觉依赖。暂停允许已经接受的在途结果结清，返回 paused 不等于底层线程已排空；取消丢弃未提交及迟到结果并保留已提交内容。终态任务不能通过 resume 重新执行，需要新的预览/批次。

run 在 POST 前保存 `cli.batch_id/status_url/request`，request 含完整 body 和 key。无效受理内容、重定向、响应丢失、超时都不触发自动重发；也不跟随任意返回 URL。Ctrl+C 退出 130，保留可用请求/批次身份，不发 cancel/pause 请求，服务中已受理的工作继续。

未知创建结果先使用 batch_id 查询；同一实例与项目句柄下，可明确再次使用原 plan 和摘要执行 run，保持原 batch_id 和请求键。服务器按现有请求收据/持久批次规则返回原批次，避免重复建批。即使原任务暂停或取消，重放创建也不会自动 resume。想创建另一轮必须重新 preview 并确认新计划。

未知控制结果先查询目标。需要重放时使用输出中的原始 request.if_match、idempotency_key 和 instance_id，保持同一个项目、job/batch 和 action，例如：

```powershell
./scripts/run.ps1 job pause --batch-id <original_batch_id> --project-id <original_project_id> --if-match <original_version> --instance-id <original_instance_id> --idempotency-key <original_key>
```

显式提供请求键时必须同时提供原版本和实例；重放不会重新捕获版本。实例或项目句柄已变化时停止，不把旧计划重绑到新项目。关闭/重启后批次仍持久存在，可先明确打开原项目，再用**新 project_id 和原 batch_id/job_id**只读查询、核对状态；不会自动重发旧计划或继续暂停任务。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 预览/读取成功；run 已完成，或 --detach 明确受理；pause/cancel 请求已达到目标状态；resume --detach 已恢复活动状态 |
| 2 | 参数、文件、计划、配置、路径或目标不合法 |
| 3 | 无运行实例、认证/授权不可用 |
| 4 | 项目/会话/状态/版本冲突，预览已过期 |
| 5 | 依赖、I/O、轮询、任务级失败或无效查询响应 |
| 6 | 批次/job 已 done，但存在逐图 failed_count；保留成功、失败、跳过计数 |
| 7 | 活动任务的一次状态查询、暂停、取消、依赖阻塞、待处理诊断或写入结果未知 |
| 130 | 客户端中断，未隐式取消后台任务 |

pause/cancel 的成功码表示该控制请求成功，status 观察到 paused/canceled 则返回 7。list/outcomes 的 0 只说明该页读取成功，不代表其成员任务全部完成。轮询失败返回 5 时仍可能有后台任务运行，应保留输出中的身份继续查询。
