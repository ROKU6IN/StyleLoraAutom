日期：2026-10-27；版本：0.32.0。依据 F02–F05 §6、T14–T17、C07 与 F01 §5.5。本轮仅本地实现、测试和打包，未初始化、提交或上传 Git。

## 已实现范围

新增 `generation/metadata.py` 与 `generation/artifacts.py`，完成已派发条目的本地产物检查、原始标注解析、F01 完整收据准备、原子图片登记与项目重开恢复。入口为内部服务 `inspect_and_prepare` / `register_artifact`，不增加任意文件路径 HTTP 导入接口，不启用真实生成。已有图片查询、人工审核与导出 HTTP 流程可消费登记结果。

只处理 NAI 已锁源的 sent 条目和指定 attempt；caller 路径须恰为项目 `images/.pending/<item>/<attempt>/out.png`，拒绝相对路径、穿越、其它名称和项目路径重解析点。不会扫描、移动或删除 Launcher 外部画廊。检查与登记持有既有项目文件操作保护，关闭项目必须等待；关闭后的句柄不能创建检查收据。

这里的路径检查不能证明外部生成请求归属。未来 driver 仍须先验证可信 resourceId/caller 响应与请求的关联；同名文件、相似 prompt、时间相近或单条 recent 记录不能作为重新提交、补救导出或直接恢复的授权。本轮未实现 intent 收据、未知网络发送对账、外部资源下载或完整生成 runner。

## PNG 与元数据检查

文件最多 100 MiB，像素上限 100 MP，保留 Pillow 自身的解压防护。先有界读取不可变字节快照，检查 PNG 签名、全部 chunk 边界和 CRC、完整 IEND 且无尾随字节，拒绝 APNG；再调用 Pillow verify 与重新打开后的完整 load。有效 CRC 但损坏像素压缩流也拒绝。实际宽高必须等于已保存配置按条目 aspect（或来源默认 aspect）投影的宽高，不能从 PNG 反向更新来源参数。

SHA-256、文件大小、宽高及可选 phash64-v1 来自同一字节快照。准备 F01 完整收据时再次校验哈希/大小；两步之间文件变化不创建完整收据，收据之后变化也不能登记或自动恢复。损坏/尺寸不符保持 sent，交给未来调度层暂停核查，不擅自 failed 或生成重试。

Comment 支持普通/压缩 PNG 文本，解码后最多 1 MiB。重复 Comment、重复 JSON 键、非对象、非有限数值、非法 Unicode 和非法 JSON 都判无法核验；原 PNG 保留，不能伪造提示词。合法 JSON 原样放入 `png_meta_json = {schema_version:1, comment:<原对象>}`，包括 seed、steps、scale、sampler、uc、v4_prompt、v4_negative_prompt 及未知字段，仅作档案，不修改 caption、配置或费用。

可核对的正向字段为 Comment.prompt 或 v4_prompt.caption.base_caption；两者同时存在须在完整 tag 集合上相符，否则 ambiguous_prompt。非空角色 caption 属当前不支持结构，保持 unverifiable。该解析行为使用合成合同测试，不构成真实 Launcher 响应格式已验收的结论。

复用 comma-v1 tokenizer：大小写、下划线/空格、连续空白归一后比较完整 tag，art 不匹配 artist。不删括号来假装支持权重；未知权重、转义和控制语法使本次检查无法核验。只检查新增的 very aesthetic / masterpiece / no text；sent 本来就有的不误报，负向 uc 不参与正向标签检查。

| 检查结论 | 初始审核状态 | 行为 |
|---|---|---|
| pass | unreviewed | 画风 tag 全部存在，未新增受检查的质量词 |
| mismatch | reject | 确定缺画风 tag 或新增质量词；图片仍完成登记，原文件保留，用户可人工复核 |
| unverifiable | unreviewed | Comment 缺失/非法、正向字段缺失/矛盾、不支持结构/语法；不自动重新生成 |

metadata_stripped=true 且 caller 文件有合法 Comment 时仍核验；没有 Comment 才记 meta:stripped，不能误报 style_tag_missing。metadata_stripped 为 false/未知且无 Comment 时记 meta:missing。

## 原始标注与 C07

original 只解析 source_items.prompt 内容段，不从 PNG 正向字段或来源 style_prompt 反推。有本地标签库时按 §8.2 分离已知 tag 与自然语言；标签库缺失或内容存在不支持语法时，把完整内容保留为 nl 并记录警告，避免丢词或把画风注入训练标注。检查摘要、tokenizer 和词库修订保存在 original.params_json.generation_validation / 同级解析字段。

C07 在本阶段按推荐落地：ImageArtifact 增加可选 registration_check，结构为 schema_version、review_status 和 versioned summary；仅允许初始 unreviewed/reject，不能自动 keep，检查对象最多 64 KiB。准备完整收据前先写 `images/.checks/<item>/<attempt>.json`，含 item/attempt、图片 SHA-256、检查对象与摘要，使用原子 JSON 写入。摘要含来源编号、请求/配置哈希、结果与原因，不保存完整请求、端点凭据或外部绝对路径。已有检查不同不覆盖；没有 original 也保留检查档案。

完整收据将检查对象纳入原有摘要。complete_item 校验收据和独立检查档案后，在同一 SQLite 事务登记图片、original、初始审核状态和 item done。不会出现已提交图片短暂显示 unreviewed 后再改 reject 的窗口。失败回滚或改名后崩溃由既有恢复流程重试登记，不能重新生成；检查档案缺失/损坏保持 unresolved。完成后普通收据可清理，检查档案保留；重复登记、提交后故障恢复均不覆盖用户之后的 keep/reject 决定。已派发的合法迟到产物允许结清 canceled 来源中的条目，来源保持 canceled。

没有 registration_check 的旧调用保持默认 unreviewed，序列化时省略该字段，因此旧 v1 完整收据字节合同和摘要不变，新版本能恢复旧项目。新带检查的收据须由支持本扩展的版本恢复；不承诺旧二进制能恢复新收据。没有增加表/列、item 状态或项目数据库版本。检查档案属于项目 images 内的辅助证据，随项目搬迁保留，不应手工删除。
