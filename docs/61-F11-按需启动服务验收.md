## 使用方式

增加三个显式入口。没有运行服务时后台启动，已有服务时直接验证并附着；不加选项仍保持原来的附着行为。

```powershell
./scripts/run.ps1 ui --start-service
./scripts/run.ps1 project init "E:\datasets\new.slproj" --name "样例" --trigger "example_style" --start-service
./scripts/run.ps1 project open "E:\datasets\example.slproj" --start-service
./scripts/run.ps1 project open "E:\datasets\example.slproj" --start-service --detach
```

可附加 `--startup-timeout 30`，允许 5–120 整数秒，必须与 `--start-service` 同用。此值限制启动确认阶段，不改变项目后台任务的等待方式。既有管道连接/响应有独立 3 秒/6 秒上限，因此已经开始的一次管道读取可能使总等待超出所设截止时间最多约 9 秒；超时后不会开始新的握手或再启动子进程。

创建/打开项目默认等待完成；`--detach` 只改变项目任务等待。CLI 退出后服务和已打开项目继续存在，不自动退出服务或继续已暂停的生成任务。可通过 `ui` 打开同一服务；关闭终端或浏览器不等于停止服务。需要关闭时，读取 `/api/session` 的 version 后显式提交 `/api/session/shutdown`：

```powershell
$localSession = ./scripts/run.ps1 api GET /api/session | ConvertFrom-Json
./scripts/run.ps1 api POST /api/session/shutdown --if-match $localSession.version
```

关闭返回受理结果，服务继续按现有 draining/排空协议退出。不要用结束任意 Python 进程的方式替代服务关闭。

后台服务使用当前 Python/虚拟环境，继承当前进程环境与默认产品目录，执行 `python -m stylelora serve --no-browser`。需要自定义产品目录、端口或开发 Origin 时，先用原 `serve` 命令启动，再附着；这些配置不会由按需启动覆盖。

## 启动和认证

1. 先读取当前用户 ACL 管道的 hello，验证协议、回环地址、端口、PID 和实例编号。
2. 仅第一次读取明确返回 `instance:not_running` 时启动一个后台子进程。认证异常、错误响应或管道请求结果未知均不会触发启动。Windows 隐藏窗口、脱离控制台，标准输入/输出/错误流不继承客户端管道；凭据不写参数、日志或项目。
3. 通过带会话认证的 `GET /api/session` 验证 HTTP 已就绪、实例与版本一致且未处于 draining；不使用定位文件、PID 文件或“子进程已创建”替代就绪确认。禁用代理与重定向，只重试只读握手。
4. 并发 CLI 可各自发起一次启动尝试，由既有产品互斥锁保证一个服务实例。落败子进程正常退出后继续等待胜出实例；不杀掉已有服务，不再次派生子进程。
5. 就绪后才执行原有项目 grant + HTTP 创建/打开流程。`ui` 的 bootstrap 请求绑定刚核实的 instance_id；期间服务重启则拒绝，不能把引导请求发给另一个会话。

项目命令 stdout 仍为单个 JSON；启动提示和进度在 stderr。`cli.service_start` 记录 checking/starting/ready/failed/unconfirmed 状态，以及可用的 spawned_pid、server_pid、instance_id，不含 API Token。Windows 虚拟环境启动器或并发竞争可能导致 spawned_pid 与 server_pid 不同；ready 只表示验证完成，不宣称本客户端独占该服务。

`ui` 正常打开浏览器；只有显式 `--print-link` 才把短时一次性链接写 stdout。后台服务自身不会自动打开浏览器。

## 失败与重放边界

`--start-service` 不能与 `--standalone`、`--instance-id`、`--grant-id`、`--idempotency-key` 混用。已有请求对账必须保持原会话与请求标识，不能通过拉起新会话重放。`project status/close`、doctor、source/job/import/export 等命令没有隐式启动行为。

- 参数或组合不合法：退出 2，解析阶段结束，未启动服务。
- 身份/协议/就绪响应无效，或已有服务仍未就绪：退出 3；实例发生变化为 4。draining 返回 `process:draining`，沿用 ui 的实例不可用退出 3、项目命令的 503 依赖失败退出 5。
- 子进程无法创建或明确非零退出：`process:start_failed`，退出 5。需要详细诊断时在终端显式运行 `serve --no-browser`；不回显后台异常中的本地路径或敏感内容。
- 已派生进程但就绪超时：`process:start_timeout`、outcome=unknown、退出 7。保留启动 PID，先查询项目状态；不终止可能正被其他客户端使用的服务。
- Ctrl+C：退出 130，只停止等待。服务可能继续启动，已受理的项目操作继续，未发送的项目操作不会补发。
- 就绪之后 grant、bootstrap 或 HTTP 写入响应未知：沿用现有未知结果与原请求核对流程，不自动重发。
