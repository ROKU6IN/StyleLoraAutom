## 2. 分层模型

| 层 | 职责 | 数据位置 |
|---|---|---|
| 项目层 | 项目名、画风触发词（Anima LoRA 用） | `project.json` |
| 提示词生产层 | 特征字典组合 → 可选 LLM 优化 → 存入提示词词典 | 词典在产品层；项目不记录字典引用 |
| 数据源层 | 外部导入 / NAI 生成 / 其它接口（预留） | `sources`、`source_items`、`import_schemes` |
| 图集层 | 图片 + 分层标注（原始提示词解析 / WD tagger / LLM 视觉反推 / 手工 / 规则） | `images`、`annotations`、`images/` |
| 导出层 | 可配置导出方案，默认「图片 + 同名 txt」，其余只做扩展规划 | `export_schemes`、`exports/` |
| 产品层（项目外） | LLM 端点与密钥、模型角色分配、MCP 配置、标签翻译库、WD tagger 模型、字典库、尺寸预设 | 用户级目录，见第 4 章 |

层间依赖规则：

- 依赖方向：导出层 → 图集层 → 数据源层；提示词生产层仅为 NAI 等生成类数据源提供输入。
- 每张图片必属于一个数据源（`images.source_id` 必填，外部导入也归入 `import` 类型数据源，见 5.4）。
- 项目层与产品层之间只通过「角色名」一种引用耦合，不存配置内容；尺寸预设在数据源启动时把实际像素值写入 `config_json`，之后与产品层预设脱钩（见 4.5）。

## 3. 项目目录结构与规则

项目 = 一个目录：

```
MyStyle.slproj/
├── project.json     # 格式版本、名称、触发词、创建时间
├── project.db       # SQLite，全部业务数据
├── images/          # 以 image_id 命名
├── cache/           # 缩略图，可重建可删
└── exports/
```

| 目录/文件 | 内容 | 可删 |
|---|---|---|
| `project.json` | `format_version`、`name`、`trigger_word`、`created_at` | 否 |
| `project.db` | 全部业务数据 | 否 |
| `images/` | 图片文件，文件名 = `image_id` + 小写原扩展名；`.pending/<item_id>/<attempts>/` 为落盘暂存与收据，不能当缓存清理 | 否 |
| `cache/` | 缩略图等派生文件 | 是，可重建 |
| `exports/` | 导出产物，`<scheme_id>/<UTC时间>-<随机短码>/`，重复导出新建目录 | 是，可重新导出 |

规则：

| # | 规则 |
|---|---|
| 1 | 项目内只用相对路径，整个目录可搬迁、可压缩分发 |
| 2 | 项目**不存**产品级配置：只存角色名（如 `vision`），不存端点地址和密钥 |
| 3 | 每条执行结果记录**实际使用的模型名和参数**，溯源不依赖产品配置还原 |
| 4 | `project.json.format_version` 与 `PRAGMA user_version` 一一对应；任一高于当前程序支持时拒绝打开，不降级写入；双文件迁移恢复协议见 F01 §8 |
| 5 | 外部导入的图片**复制进项目** `images/`，不引用原位置 |
| 6 | 项目不存字典内容，也不记录字典引用（见 4.4） |
| 7 | 各项目数据物理独立成块，删除整个 `.slproj/` 目录即彻底清理该项目，不留外部残留 |

### 3.5 存储占用扫描与清理

决议：剔除的图片只打标记不删文件，磁盘会持续增长，因此产品要主动把占用情况摆在用户面前，由用户决定清理。

产品提供两级视图：

| 级别 | 内容 |
|---|---|
| 项目内 | `images/` 总量、`cache/` 总量、`exports/` 总量、`project.db` 大小；`images/` 再按 `review_status` 拆成 保留 / 未审 / **剔除** 三块，以及按数据源拆分 |
| 跨项目 | 已知项目列表（最近打开记录）各自的总占用，按大小排序 |

规则：

- 扫描是**只读统计**，不自动删任何东西。
- 超过阈值时在界面提示（默认单项目 20 GB、全部项目合计 100 GB `[待确认阈值]`），提示里直接给出可回收的量：`cache/` 全部可删、`exports/` 全部可重新导出、`reject` 图片可删。
- 提供三个清理动作，均需二次确认：清空缩略图缓存、清空导出产物、**删除 `reject` 图片文件**。
- 删除 `reject` 图片文件后，`images` 行保留，置 `images.file_missing=1`（见 5.4），标注和历史不丢，界面显示占位图。这样统计口径和撤销记录仍然成立，只是图片本身不可恢复。
- `file_missing=1` 的图片不能切回 `keep` / `unreviewed`（核验文件恢复后才解除）；执行器和导出一律跳过。外部丢失的 keep 图只置 missing，不伪造原审图决定。
- 跨项目视图只依赖最近打开记录，不扫描整个磁盘。

### 4.2 LLM 配置

端点列表，每个端点包含：

| 属性 | 说明 |

| 项 | 设计 |

| 角色 | 用途 | 状态 | 空值行为 |

| `clean` | 数据清洗 | **预留，不实现** | - |
| `clean_nsfw` | NSFW 数据清洗 | **预留，不实现** | - |

### 4.3 密钥存储

- 沿用 TagCleaner 方案：`%LOCALAPPDATA%` 下 DPAPI 加密的 `secrets.json`。
- 环境变量优先于 `secrets.json`。
- 本地 API 不返回明文密钥。
- 密钥不进入项目目录，因此项目可安全分发。

### 4.4 字典库

字典**只存在产品层**。

| 字典类型 | 说明 |
|---|---|
| 特征字典 | 提示词生产的原料，可导入；也可由「特征生成源」（如 NAI Launcher 的随机提示词词库）现场生成 |
| 提示词词典 | 自定义，保存可直接用于出图的内容段提示词；可导入导出，LLM 优化结果可追加条目 |

项目与字典的关系：

- 项目**不记录字典引用**，也不存字典内容。字典变化不影响已有项目，打开项目时不做字典比对。
- 数据源启动时，抽取结果直接写入 `source_items`（提示词本体，见 5.3），之后与字典脱钩。
- 生成源不做溯源：`source_items` 只存提示词本身，不记录构造该提示词所用的字典、LLM 模型或参数（已定）。

提示词词典条目格式：

| 字段 | 类型 | 说明 |
|---|---|---|
| `tags` | 字符串数组 | 内容段 tag，不含画风串 |
| `natural_language` | 字符串 | 自然语言段，可空 |
| `aspect` | 枚举 | `landscape` / `portrait` / `square`，可空 = 用数据源默认 aspect |
| `rating` | 枚举 | Danbooru 四级之一，可空。与 NSFW 围栏、路由的具体衔接方式 [待确认，见第 13 章] |

- `aspect` 由 LLM 做自然语言优化时一起输出（见 6.3），也可手工编辑。
- 词典条目其余字段（来源、创建时间等）[待确认]。

### 4.5 尺寸预设 generation_presets

产品层配置，供 NAI 等生成类数据源选择出图尺寸。

实现补充（0.31.0）：已实现产品级自定义预设 CRUD、内置预设只读及生成源草稿选择器，见 [F24 验收](38-F24-自定义尺寸预设验收.md)。宽高采用与生成源相同的严格整数范围 64–16384，且须为 64 的倍数；横向宽大于高、竖向高大于宽、方形宽高相等。选择时复制三组像素，连已保存但尚未启动的来源也不会随预设变化。配置单文件原子保存，不增加项目表。

| 项 | 设计 |
|---|---|
| 结构 | 每个预设含 `landscape`（横）/ `portrait`（竖）/ `square`（方）三组像素，宽高均为 **64 的倍数** |
| 默认 | 内置「小」 |
| 用户自建 | 允许；保存时校验 64 倍数 |

内置预设：

| 预设 | 横 | 竖 | 方 |
|---|---|---|---|
| 大 | 1536×1024 | 1024×1536 | 1472×1472 |
| 小（默认） | 768×512 | 512×768 | 640×640 |

使用规则：

- 数据源配置时选择预设，`sources.config_json` 记录所选预设的**实际像素值**（三组），不只记预设名。
- 数据源启动后参数锁定；之后产品层预设被修改或删除，不影响已启动的数据源。
- 生成时按 `source_items.aspect` 取对应像素；`aspect` 为空则用 `config_json` 中的默认 aspect（见 5.2、5.3）。
- 内置预设不可删除，不可覆盖修改 [推断，见第 13 章]。

## 5. project.db 表设计

### 5.1 总览与约定

| 表 | 用途 | 字段数 |
|---|---|---|
| `sources` | 数据源 | 13 |
| `source_items` | 生成索引，核查与断点续跑 | 10 |
| `images` | 图片登记（含分级结果缓存） | 16 |
| `annotations` | 分层标注 | 12 |
| `jobs` | 执行器批次进度 | 17 |
| `operation_log` | 批量规则操作记录，可撤销 | 9 |
| `export_schemes` | 导出方案 | 9 |
| `import_schemes` | 导入方案（与 `export_schemes` 对称） | 7 |

共 8 张表、93 个字段。项目不记录字典引用，没有字典相关表。完整 DDL、17 条二级索引及约束见 `F01-project-db-设计.md`。

约定：

- 主键均为 `INTEGER PRIMARY KEY`（自增）。`image_id` 同时用作 `images/` 下的文件名主干。
- 时间字段为 `TEXT`，UTC ISO 8601。
- `*_json` 字段为 `TEXT`，存 JSON。
- 外键启用；图片行不做物理删除（见 5.4 `review_status`），因此本版无级联删除场景。用户在 3.5 删除 `reject` 图片时只删文件、保留行并置 `file_missing=1`。
- 迁移：`project.json.format_version` 与 `PRAGMA user_version` 一一对应，初版均为 1；任一高版本拒绝，旧版本按连续迁移链升级。仅可信迁移标记允许修复 DB 已提交而 JSON 未发布的中间态，细节见 F01 §8。

### 5.2 sources

| 字段 | 类型 | 说明 |
|---|---|---|
| `source_id` | INTEGER | 主键 |
| `type` | TEXT | `import` / `nai` / 预留其它接口 |
| `name` | TEXT | 显示名 |
| `config_json` | TEXT | 数据源配置。NAI：生成参数（模型、步数、cfg 等）、所选尺寸预设的**实际像素值**（横/竖/方）、默认 aspect；import：所用导入方案的 reader 与参数快照（见 5.9） |
| `cost_policy` | TEXT | NOT NULL，默认 `ask`，CHECK `deny` / `ask` / `allow`；独立运行策略，不在参数锁定范围，可随时改，下一张生效；import 保留但不使用 |
| `style_prompt` | TEXT | 画风正面词，用户输入。仅用于 NAI 出图，不进训练 caption。import 为空 |
| `negative_prompt` | TEXT | 画风负面词，用户输入。同上 |
| `target_count` | INTEGER | 目标数量。import 可为空 |
| `status` | TEXT | `draft` / `running` / `paused` / `done` / `canceled` |
| `locked` | INTEGER | 0/1。启动后置 1，参数锁定 |
| `created_at` | TEXT | 创建时间 |
| `started_at` | TEXT | 首次启动时间，同时是锁定时间 |
| `finished_at` | TEXT | 结束时间 |

状态机：

```
draft ──启动──▶ running ◀──继续── paused
                  │  └──暂停──▶ ─┘
                  ├──全部 item 终态──▶ done
                  └──取消──▶ canceled
```

- 锁定规则：`draft → running` 时 `locked=1`；之后 config_json、style_prompt、negative_prompt、target_count 及 type 不可改；name 与独立 cost_policy 可改。生成参数要改则新建源，运行费用策略变化不影响生成参数一致性。
- `done` 判定：所有 source_items 均为 done/failed/skipped；failed 不阻塞结束。补充合法迁移：draft/paused→canceled、paused→done；用户明确重试 failed 时同事务 done→paused、failed→pending、attempts+1、清空 finished_at；canceled 不重开。
- `import` 类型：启动即开始复制文件，文件级进度同样落在 `source_items`（见下）。外部导入的每一批图片都归入一个 `import` 类型数据源，因此 `images.source_id` 必填（见 5.4）。
- config_json.import_manifest 仅存 seq 到所选根内相对文件位置的清单；原绝对目录仅会话展示，不持久化，续跑未复制项需重新选择根目录。
- 费用策略（NAI）：每张非零估算按 cost_policy 决定暂停/确认/放行，见 7.3；不要求先观察到零估算。
- 画风提示词的拼接：发给 NAI 的完整串 = `style_prompt` + `source_items.prompt`；`quality_toggle` 固定关闭，`uc_preset` 必须为 None（见 7.3）。

### 5.3 source_items

| 字段 | 类型 | 说明 |
|---|---|---|
| `item_id` | INTEGER | 主键 |
| `source_id` | INTEGER | 外键 → `sources` |
| `seq` | INTEGER | 数据源内序号，与 `source_id` 联合唯一 |
| `prompt` | TEXT | 内容段提示词（不含画风串）。import 类型存原文件名。只存提示词本身，不记录构造它的字典、LLM 模型或参数（生成源不做溯源，已定） |
| `aspect` | TEXT | 图幅：`landscape` / `portrait` / `square`，可空。生成时确定；空 = 用 `sources.config_json` 的默认 aspect。import 类型为空 |
| `status` | TEXT | `pending` / `sent` / `done` / `failed` / `skipped`；skipped 仅 import 查重跳过 |
| `image_id` | INTEGER | 产出图片，可空，外键 → `images` |
| `attempts` | INTEGER | 尝试序号，初值 0；首次 sent 置 1，failed→pending 授权重试加 1，重试发送不再加 |
| `error` | TEXT | 最近失败原因；skipped 固定 `duplicate_sha256`，image_id=NULL |
| `updated_at` | TEXT | 最近状态变更时间 |

状态机：

| 转移 | 条件 |
|---|---|
| `pending → sent` | 请求已发出（先落库再发请求） |
| `pending / sent → skipped` | import 已核验 sha256 命中；不回填已有 image_id，结束后统一汇总；pending 直接跳过不加 attempts |
| `sent → done` | 结果收到，图片已入库，`image_id` 已回填（同一事务） |
| `sent → failed` | 明确失败，或崩溃恢复核查后确认未落盘 |
| `failed → pending` | 用户手动重试，`attempts` +1 |

幂等策略：

- 数据源启动时一次性生成全部 `source_items`（`seq`、`prompt`、`aspect` 固定），续跑不重新抽取提示词。
- 续跑只处理 pending；done/skipped 永不重做；源结束统计包含 skipped。
- 崩溃恢复：sent 不自动重放；采用 `images/.pending/<item_id>/<attempts>/` 收据核验归属/哈希/完整性，确认完整则同事务补登记为 done，核查结束确认无产物则 failed，未知仍 sent 且源 paused。running 源重启先 paused。协议已定，Launcher save_path 行为已实测（F01 §5.5）；改名与 DB 提交之间的恢复窗口见 F01 §5.5。
- 一个 `image_id` 至多被一个 `source_items` 引用。

### 5.4 images

| 字段 | 类型 | 说明 |
|---|---|---|
| `image_id` | INTEGER | 主键，同时是 `images/` 下的文件名主干 |
| `filename` | TEXT | `images/` 下的相对文件名 |
| `width` | INTEGER | 像素宽 |
| `height` | INTEGER | 像素高 |
| `phash` | TEXT | 感知哈希，用于近似去重 |
| `sha256` | TEXT | 文件内容哈希，用于导入去重和缓存失效（图片指纹） |
| `file_size` | INTEGER | 字节数，视觉请求判定「≥10MB 也缩放」用 |
| `source_id` | INTEGER | 外键 → `sources`，**NOT NULL 必填**；外部导入也归入 `import` 类型数据源（用途见下） |
| `file_missing` | INTEGER | 0/1，默认 0。删除 `reject` 图片文件后置 1（见 3.5） |
| `review_status` | TEXT | `unreviewed` / `keep` / `reject`，默认 `unreviewed` |
| `rating` | TEXT | Danbooru 四级 `general` / `sensitive` / `questionable` / `explicit`，可空（未判定） |
| `rating_source` | TEXT | 判定来源：`keyword`（词库命中）/ `model`（分级模型）/ `fallback`（nsfwfallback 策略）/ `refusal`（LLM 短路回传 `refused_nsfw` 后升级）/ `manual`（用户手改）/ `detector`（本地检测器，**预留值，本版不写入**，见 9.1） |
| `rating_verified` | INTEGER | 0/1。0 表示未经可靠判定，请求体需带 `rating_verified: false`（见第 9 章） |
| `rated_at` | TEXT | 判定时间，可空 |
| `png_meta_json` | TEXT | 入库时解析一次的 PNG 元数据；原图不动。非 PNG 或无元数据为空 |
| `created_at` | TEXT | 入库时间 |

`review_status` 只有三档：

| 值 | 含义 | 导出 |
|---|---|---|
| `unreviewed` | 未审 | 由导出方案过滤条件决定 |
| `keep` | 保留 | 导出 |
| `reject` | 剔除 | **跳过** |

- 三档之间可任意互转，无单向限制。
- **剔除只打标记，不删文件、不删行**，可随时恢复。导出跳过，但文件仍占磁盘，清理靠 3.5 的存储占用扫描。
- `parent_id`（图片血缘）属预留，不在本表正式字段内（见 12.1）。

`source_id` 必填，用途：

- 关联数据源配置与锁定参数（`sources.config_json`、画风串等）。
- 按源分组统计、筛选，以及 3.5 存储占用按数据源拆分。
- 查看某一批生成的全部图片。
- 续跑时与 `source_items` 对应（`source_items.image_id` 反向指回本表）。
- **不用于定位原始文件**：项目内文件一律按 `image_id` 命名放在 `images/`，原始路径不参与运行。

`rating` 四个字段是**分级结果缓存**（决议：图片需要缓存）。NSFW 路由每次执行 LLM 步骤前先读本表，已有 `rating` 且 `rating_verified=1` 就直接用，不重复调用分级模型，避免同一张图反复付费判定。

- 写入时机：导入/入库时跑一遍关键词词库；词库无结论且配置了分级模型时调用模型并回写；用户在界面手改写入 `rating_source=manual` 且 `rating_verified=1`。
- `rating=NULL` 或 `rating_verified=0` 时按第 9 章兜底，走普通线路并在请求体标注 `rating_verified: false`。
- LLM 短路返回 `refused_nsfw` 时，把 `rating` 升为 `questionable`、`rating_source=refusal`、`rating_verified=1`，并改走 nsfw 线路。这是一条真实判定，所以要落库，下次不再重试普通线路。
- 词库或分级模型配置变更后不自动重算；界面提供「重新分级」动作，按范围清空 `rating_source IN ('keyword','model','fallback')` 的记录后重跑，`manual` 不动。
- 幂等：导入按 sha256 查重，命中写 source_items.skipped、error=duplicate_sha256、image_id=NULL，导入后汇总，不逐张询问、不合并图片归属。sha256 不设唯一约束，因为 NAI 与导入可能出现相同内容。

### 5.5 annotations

分层存储，**互不覆盖**。不预先合并写回，最终 caption 由导出方案在导出时组合。

| 字段 | 类型 | 说明 |
|---|---|---|
| `annotation_id` | INTEGER | 主键 |
| `image_id` | INTEGER | 外键 → `images` |
| `source` | TEXT | 来源层：`original` / `wd` / `llm` / `manual` / `rule` |
| `type` | TEXT | `tags` / `nl`（自然语言） |
| `content` | TEXT | `tags`：JSON 数组，元素为 `{tag, conf}`，`conf` 可空；`nl`：纯文本 |
| `confidence` | REAL | 整条置信度，可空；逐 tag 置信度放 `content` 内 |
| `model_name` | TEXT | 实际使用的模型名；`original` / `manual` / `rule` 为空 |
| `params_json` | TEXT | 实际参数：角色名、温度、阈值、缩放档位、NSFW 路由/rating_verified；rule/manual tags 另存 merge_meta 的显式移除集与 tag 原始证据（见 10.3） |
| `job_id` | INTEGER | 外键 → `jobs`，可空（手工和原始解析无 job） |
| `cache_key` | TEXT | 缓存键，由配置、模型、Skill 内容哈希、图片指纹组合而来（见 8.8） |
| `created_at` | TEXT | 写入时间 |
| `is_current` | INTEGER | 0/1，该层当前采用的版本 |

各层含义：

| `source` | 产生方式 | 典型 `type` |
|---|---|---|
| `original` | 原始提示词自动解析（标签段 / 自然语言段，见 8.2） | `tags`、`nl` |
| `wd` | 本地 WD tagger | `tags` |
| `llm` | LLM 视觉反推 | `tags`、`nl` |
| `manual` | 界面手工编辑 | `tags`、`nl` |
| `rule` | 批量规则操作结果（见 8.4） | `tags` |

规则：

- 同一 `(image_id, source, type)` 至多一条 `is_current=1`。重新执行不覆盖旧行，而是新增一行并把旧行置 0，历史保留。
- original 只在入库时写入；用户修改写 manual，不改 original。manual 编辑以用户读到的有效合并视图及 read_set 为基准，差集形成显式移除，复制 tag 保留原版本证据。
- 「原始 + LLM 视觉改进后两份自然语言并存」靠 `source` 区分，无需额外字段。
- 幂等：执行器写入前按 `(image_id, source, type, cache_key)` 查当前行，命中则跳过（见 8.3）。
- `is_current` 只表示该层的当前版本；导出时取哪些层、按什么优先级，由导出方案决定（见第 10 章）。

### 5.6 jobs

执行器批次进度。**启动时冻结配置快照**，运行期间产品层配置变化不影响本批次。

| 字段 | 类型 | 说明 |
|---|---|---|
| `job_id` | INTEGER | 主键 |
| `executor` | TEXT | 执行器：`wd` / `llm_vision`，预留其它。**单值** |
| `batch_id` | TEXT | 同一次界面提交生成的多个 job 共享的分组 id，可空 |
| `mode` | TEXT | `selected`（执行选中）/ `uncovered`（执行未覆盖）/ `all`（执行所有） |
| `scope_json` | TEXT | 范围：`selected` 存 image_id 列表；其余存筛选条件（如数据源、审图状态） |
| `config_snapshot_json` | TEXT | 冻结的配置快照：角色名、实际模型名、协议格式、采样参数、阈值、缩放档位、并发/超时/重试参数、Skill 内容哈希。**不含端点地址和密钥** |
| `progress_json` | TEXT | NOT NULL JSON 对象，默认 `{"schema_version":1,"image_ids":[],"outcomes":{}}`；启动物化冻结有序 image_ids，outcomes 按 image_id 字符串键存 kind/reason/annotation_ids/cache_keys；与标注/计数同事务 |
| `status` | TEXT | `pending` / `running` / `paused` / `done` / `failed` / `canceled` |
| `total` | INTEGER | 启动时计算出的待处理张数 |
| `done_count` | INTEGER | 成功张数 |
| `failed_count` | INTEGER | 失败张数 |
| `skipped_count` | INTEGER | 因缓存命中或 NSFW 角色为空等原因跳过的张数 |
| `error` | TEXT | 批次级错误（如角色未配置） |
| `created_at` | TEXT | 创建时间 |
| `started_at` | TEXT | 启动时间，即快照冻结时间 |
| `finished_at` | TEXT | 结束时间 |
| `updated_at` | TEXT | 最近进度更新时间 |

状态机：

```
pending ──启动(冻结快照)──▶ running ◀──继续── paused
                              │  └──暂停──▶ ─┘
                              ├──处理完毕──▶ done
                              ├──批次级错误──▶ failed
                              └──取消──▶ canceled
```

**执行器多选 = 拆成多个 job**（决议）。界面上勾选「WD 打标 + LLM 自然语言」后，产品生成两个 job，各自独立的快照、进度、状态，共享同一个 `batch_id` 供界面聚合显示进度。理由：两个执行器的失败原因、重试策略、并发限制都不同，合在一条记录里无法表达「WD 全成功、LLM 失败一半」。执行顺序按 `job_id` 递增串行，WD 排在 LLM 之前（LLM 清洗阶段可能需要 WD 结果作证据）。

幂等与续跑：

- 没有 job 子表；progress_json 保存逐图终态凭据。total=len(image_ids)，三类计数从 outcomes 重算，相同 outcome 重交不增计数，不同终态报冲突。启动后筛选属性改变/新增图片不漂移范围；已落 outcome 的图恢复不重做。
- all 新 job 首轮忽略其它 job 缓存，恢复仅承认本 job 已提交证据；其余模式未有 outcome 的图可用当前相同 cache_key 覆盖，记 skipped。LLM tags/nl 同事务完成才计一图；失败/跳过同样持久化。外部调用已返回但未落库不保证不再次付费。
- 「执行未覆盖」的覆盖判定 = 该 `(image_id, source, type)` 存在 `is_current=1` 且 `cache_key` 与当前快照计算结果一致。
- running job 重启转 paused，由用户继续。补充合法边：pending/paused→canceled、pending→failed（可无 started_at）、paused→done/failed；终态 job 重做创建新 job。
- 并发上限 2、退避重试、超时等参数来自快照，不读运行时配置。

### 5.7 operation_log

批量规则操作记录，可撤销。规则语义见 8.4。

| 字段 | 类型 | 说明 |
|---|---|---|
| `op_id` | INTEGER | 主键 |
| `rule_json` | TEXT | 规则全文：删除/写入/条件三组 tag 及各自「全量」「任意」模式 |
| `scope_json` | TEXT | 作用范围，同 `jobs.scope_json` |
| `affected_count` | INTEGER | 实际发生变更的图片数 |
| `changes_json` | TEXT | 逐图变更清单：`image_id`、新增的 `annotation_id`、被置为非当前的 `annotation_id` |
| `status` | TEXT | `applied` / `undone` |
| `created_at` | TEXT | 执行时间 |
| `undone_at` | TEXT | 撤销时间 |
| `note` | TEXT | 用户备注 |

- 规则**由用户手动触发**，只作用于触发时作用对象**已有的**标注，结果以**快照**形式写入 `annotations`（`source=rule`，`type=tags`），不改动其它层。
- 之后 WD / LLM 新产出的标注**不会被自动替换**，需用户再次触发规则（见 8.4）。
- 撤销 = 按 `changes_json` 把新增行置 `is_current=0`，并恢复被置 0 的旧行。因为标注分层不覆盖，撤销无需存全量副本。
- 撤销仅允许全局最近 applied；逐图检查 current 新行身份及后续标注依赖，冲突整批拒绝。A/B 先撤 B 再撤 A，已 undone 的 B 新 rule 行不误算为冲突；其它层后续变更仍拦截。移除集/来源随 current 版本一起回退，不从操作时间猜测。
- 幂等：比较完整 tags 与 merge_meta；都一致才不新增、不计数。规则输出完整有效合并快照，同时继承仍有效的移除与原证据；本次实际删除更新该 tag 的移除边界，无关编辑不刷新旧边界。详见 10.3。

### 5.8 export_schemes

| 字段 | 类型 | 说明 |
|---|---|---|
| `scheme_id` | INTEGER | 主键 |
| `name` | TEXT | 方案名 |
| `exporter` | TEXT | 导出器类型。默认 `image_txt`（图片 + 同名 txt），其余预留 |
| `filter_json` | TEXT | 图片过滤：`review_status` 范围（`reject` 恒跳过）、数据源范围 |

### 5.9 import_schemes

与 `export_schemes` 对称的结构预留：导入时「怎么读提示词」与导出时「怎么写提示词」使用同一套标准格式（规则见 10.5）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `scheme_id` | INTEGER | 主键 |
| `name` | TEXT | 方案名 |
| `reader` | TEXT | 读取器类型。本版仅实现 `txt_sidecar`（标准同名 txt）；其余预留（如 PNG 元数据、WebUI parameters） |
| `params_json` | TEXT | 读取器参数：编码、tags 段分隔符、空行分段规则等 |
| `is_default` | INTEGER | 0/1，至多一条为 1 |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 更新时间 |

- 项目创建时自动建一条默认方案（`txt_sidecar`，`is_default=1`）。
- 启动 `import` 数据源时，把所用方案的 `reader` 与 `params_json` 快照写入 `sources.config_json`，之后与本表脱钩（与数据源参数锁定一致）。
- 导入是单向读取：不改被导入的原文件。

### 5.10 一致性约定

| 项 | 约定 |
|---|---|
| 事务边界 | `source_items → done` 与 `images` 入库、`annotations` 的新增/置非当前，各自在同一事务内完成 |
| 外键 | 开启；`images.source_id` 为 NOT NULL，`source_items.image_id`、`annotations.job_id` 允许空 |
| 索引 | `annotations(image_id, source, type, is_current)`、`source_items(source_id, status)`、`images(review_status)`、`images(sha256)`、`images(phash)` [待确认：以实际查询为准] |
| 并发 | SQLite WAL 模式，单进程单写连接；执行器并发 2 仅指对外 API 请求并发，写库串行 |
| 迁移 | 见 5.1 |

## 6. 提示词生产机制

提示词生产层为生成类数据源（NAI 等）提供内容段提示词。import 数据源不经过本层。

### 6.1 流程

```
特征字典 / 特征生成源
        │  按过滤规则随机组合（受围栏开关约束）
        ▼
   特征组合
        │  可选：LLM 优化（角色 prompt / prompt_nsfw）
        ▼
   提示词词典（产品层，可追加条目）
        │  随机抽取（词典多选 + 现场生成开关 + 数量）
        ▼
   source_items.prompt（启动数据源时一次性固定）
```

### 6.2 方向：随机 + 字典混合

- 字典约束主维度，保证覆盖；随机填充其余维度，保证多样性。
- 具体维度与配比**延后设计**（沿用 docs/04 §6 方向）。本文档只写机制预留：维度、配比、约束均为配置内容，不进代码常量。

### 6.3 机制预留点

| 机制 | 设计 |
|---|---|
| 特征字典导入 | 可导入外部特征字典，存产品层字典库（项目不记录字典引用，见 4.4） |
| 特征生成源 | 可接入「特征生成源」，如 NAI Launcher 的随机提示词词库；现场生成特征，不落字典 |
| 围栏开关 | 首个围栏为 **NSFW 围栏**（开：组合时排除 NSFW 特征）。围栏以开关列表形式组织，预留扩展位，其它围栏本版不定义 |
| 过滤规则 | 按规则筛选特征后再随机组合；规则语法 [待确认] |
| LLM 优化（可选） | 把特征组合交给 `prompt` 角色优化；NSFW 内容走 `prompt_nsfw`，该角色为空则不做 LLM 清洗（见第 9 章）。运行时 Skill 见 docs/06 R1 |
| LLM 输出 aspect | 做自然语言优化时，LLM **一并输出 `aspect`**（`landscape` / `portrait` / `square`）；随条目写入提示词词典。docs/06 R1 与 prompt-composer SKILL.md 输出契约已同步（输入 `aspect_hint`，输出 `aspect`）。优先级：词条已有 aspect > LLM 输出 > 数据源默认 aspect |
| 存入提示词词典 | 优化结果存入用户指定的自定义提示词词典（条目格式见 4.4）；LLM 优化结果可直接追加条目 |
| 词典导入导出 | 提示词词典可导入导出 |
| 随机抽取 | 抽取时可选来源：提示词词典（多选）+「特征词典现场生成」开关；并指定数量 |

### 6.4 与项目的衔接

- 抽取结果在数据源启动时写入 `source_items.prompt` 与 `source_items.aspect` 并固定，续跑不重新抽取（见 5.3）。词条 `aspect` 为空时 `source_items.aspect` 留空，生成时用数据源默认 aspect。
- 生成源不做溯源（已定）：项目不记录字典引用，`source_items` 只存提示词本身，不记录构造它的 LLM 模型或参数。
- 提示词内容段**不含画风串**；画风串在 NAI 出图时由数据源拼接（见 7.3）。

## 7. 数据源机制

### 7.1 通用规则

| 项 | 规则 |
|---|---|
| 平行关系 | `import`、`nai`、其它接口数据源地位平行，共用 `sources` / `source_items` 结构 |
| 参数锁定 | 数据源启动后参数锁定，不允许更改（状态机见 5.2） |
| 目标数量 | `sources.target_count`；NAI 为生成张数，import 可空 |
| 产出 | 每张产出图片登记 `images`，并回填 `source_items.image_id` |
| 来源归属 | `images.source_id` 必填：每张图都属于一个数据源，外部导入归入 `import` 类型数据源（用途见 5.4） |
| 生成参数粒度 | 生成参数在数据源级（`config_json`），**不以图片为单位保存**，不影响后续处理和训练 |
| 参考图字段 | 生图请求结构从一开始带可选的参考图字段（本版不填，见 12.2） |

### 7.2 外部导入（import）

- 选择文件或目录，创建一个 `import` 类型数据源，逐文件**复制进项目** `images/`，不引用原位置。
- 复制后计算宽高、`phash`、`sha256`、`file_size`，登记 `images`（`source_id` 指向该数据源）。
- PNG 元数据入库时解析一次写入 `images.png_meta_json`，原图不动。
- 提示词读取按导入方案（`import_schemes`，见 5.9）。本版只实现 `txt_sidecar`：读同名 txt，规则见 10.5。读到的内容按 8.2 解析后写入 `annotations`（`source=original`）。
- PNG 元数据里的提示词（如 NAI 的 `prompt` 字段）、WebUI parameters 等其它读取方式属于预留 reader，本版不实现。
- 无同名 txt 的图片：不写 `original` 层（见 8.4 的退化规则）。
- 重复文件按 `sha256` 处理，见 5.4。

### 7.3 NAI 数据源

通过 Aaalice NAI Launcher 的 MCP 接口生图。连接方式、生成链路、工具分级、稳定性处理均见 docs/02，本文不重复。

| 项 | 设计 |
|---|---|
| 生成参数 | 模型、步数、cfg 等由前端配置，存 `sources.config_json`；默认 V5 标准版 `nai-diffusion-5-full` |
| 图幅与尺寸 | 数据源选一个尺寸预设（见 4.5），`config_json` 记录所选预设的**实际像素值**与默认 aspect。每张生成时按 `source_items.aspect` 取对应像素，`aspect` 为空用默认 aspect |
| 表单来源 | 前端不硬编码参数项，向后端能力自描述接口取 schema 后动态渲染（沿用 docs/04 §2.1） |
| `quality_toggle` | **固定关闭**，不暴露给前端 |
| `uc_preset` | **必须设 None**，否则用户负面词会被预设顶掉 |
| 画风正/负面词 | 不内置，由用户在前端输入，存 `sources.style_prompt` / `negative_prompt`；调用时与内容段拼接：完整正面串 = `style_prompt` + `source_items.prompt` |
| 画风提示词用途 | **只用于 NAI 出图**，不进训练 caption |
| 训练 caption 的画风处理 | 不是「剔除画风词」，而是「只取内容段 + 前挂触发词」；触发词来自 `project.json.trigger_word` |
| 生成参数粒度 | 不以图片为单位保存；`png_meta_json` 虽含逐图 seed/steps 等，但只作留档，**不参与任何后续处理** |
| PNG 元数据 | 入库时解析一次写入 `images.png_meta_json`；原图不动；导出方案可选输出配套 json |
| 账号状态 | 预留只读展示口子（额度等）；不参与任何决策；字段全部可选（沿用 docs/04 §2.1） |

执行约束（引用 docs/02，不展开）：

- 写操作串行、不重放未完成写操作；崩溃恢复处理见 5.3。

费用策略（已定，取代原先仅检测 0→非0 的提醒方案）：

- 产品层 cost_policy 默认 ask；建源复制到独立 sources.cost_policy，值为 deny/ask/allow。它是运行策略，不受生成参数锁定，可随时改，下一张生效；不重复存进锁定 config_json。
- 每张 prepare 后、sent 前读取 estimated_anlas。零值继续；任何非零值（含首张）执行策略，不要求先观察到 0。
- deny：暂停源并说明原因，不提供“本周期同意”按钮；用户可改策略后继续。
- ask：暂停并询问；用户同意执行 paused→running，同时授权新工作周期；该周期后续非零不再询问。
- allow：不提示直接提交；**Launcher 自身的付费确认仍可能弹出**，本产品不绕过它。
- 工作周期是一次 running，从启动/继续到暂停、停止、完成或应用退出。任何周期结束都清除确认；下次 running 首遇非零重新询问。ask 同意导致的新 running 周期带本次授权，普通继续不带授权。
- 确认只在内存以 cycle_id/ack 保存，过期确认拒绝；修改策略也清除 ack，切回 ask 要重新确认。无需 sources.runtime_json，pause_reason 为会话事件，重启统一显示中断暂停。
- 暂停时当前 item 保持 pending、不加 attempts、不转 failed；已 sent 不撤回。estimated_anlas 不作计费统计，账号余额展示仍预留。

### 7.4 其它接口（预留）

- 以图像后端接口抽象（沿用 docs/04 §2.1 的 `ImageBackend` 思路）：能力自描述、`prepare` / `submit`、可选 `apply_profile` / `restore`。
- 本版不实现。新增后端只需新增 `sources.type` 取值与对应适配器，表结构不变。

## 8. 数据清洗工作台

从 TagCleaner 迁移的能力。工作台是产品主界面，数据源只是图片的入口。

### 8.1 数据集视图与图片详情

数据集视图展示**所有数据源的所有图片**及打标状态。

| 列/信息 | 来源 |
|---|---|
| 缩略图 | `cache/`，可重建 |
| 数据源 | `images.source_id`（必填） |
| 审图状态 | `images.review_status` |
| 各层打标状态 | `annotations` 中各 `source` 是否存在 `is_current=1` |

选中图片后展示：

| 区块 | 内容 |
|---|---|
| 标签列表 | 当前标签 + 中文翻译（标签翻译库，产品层） |
| WD 对照 | WD 完成后展示反推结果与原始标签的重合情况，及每个 tag 的置信度。无 `original` 层时退到 WD 层自身，并标注「无原始标签」（见 8.4） |
| 自然语言 | 原始（`original`）与 LLM 视觉改进后（`llm`）**两份并存**展示 |
| 审图操作 | 切换 `unreviewed` / `keep` / `reject` |

### 8.2 原始提示词解析

- 入库时把原始提示词**自动解析为标签段和自然语言段**，写入 `annotations`（`source=original`，`type=tags` / `nl`）。
- 解析规则：按逗号分段；能在标签库查到的算 tag，查不到的算自然语言。
- 界面可手改解析结果；手改写入 `manual` 层，不覆盖 `original`（见 5.5）。
- 「标签库」即产品层标签翻译库 [待确认：是否另有独立的 Danbooru tag 表]。
- tag 合并比较统一小写、下划线转空格、去首尾空白（见 10.3）；原始提示词权重语法的解析仍 `[待确认]`，不改原始 prompt。

### 8.3 执行器与执行模式

执行器列表（可多选）：

| 执行器 | 写入层 | 依赖 |
|---|---|---|
| WD 打标 | `wd` / `tags` | 本地 WD tagger（见 8.7） |
| LLM 视觉反推 | `llm` / `tags`、`nl` | 角色 `vision`（NSFW 时 `vision_nsfw`），模型需标记「支持图像」 |

三种模式：

| 模式 | 范围 | 对应 `jobs.mode` |
|---|---|---|
| 执行选中 | 当前选中的图片 | `selected` |
| 执行未覆盖 | 目标层尚无有效结果的图片 | `uncovered` |
| 执行所有 | 全部图片，已有结果也重跑 | `all` |

- 「未覆盖」判定：目标 `(image_id, source, type)` 存在 `is_current=1` 且 `cache_key` 与当前快照一致（见 5.6、8.8）。
- 启动时冻结配置快照到 `jobs.config_snapshot_json`；多选执行器时**拆成多个 job**，共享 `batch_id`，WD 先于 LLM 串行执行（见 5.6）。
- reject 默认不参与执行器，用户可明确选入；file_missing 始终跳过并记逐图 skipped 原因。
- 每条结果记录实际模型名与参数（`annotations.model_name`、`params_json`），不依赖产品配置还原。

### 8.4 批量规则替换

规则由三组多 tag 列表组成，每组各有「全量」「任意」两种模式。

| 组 | 全量 | 任意 |
|---|---|---|
| 删除 | 列表**全部存在**才执行，删除全部 | **任一存在**即执行，只移除命中项 |
| 写入 | 列表**全部不存在**才执行，写入全部 | **有缺失**就执行，只补缺失项 |
| 条件 | 全部存在才满足 | 任一存在即满足；未设置条件组时无此限制 |

规则：

- **条件用原始 tags 判断**（`original` 层，不受其它层影响）。
- **无 original 层时退化**：条件判断退到 wd tags，界面标注无原始标签；wd 也无时条件不满足，不执行该图。
- 删除与写入同时存在时，**删除成功才判断写入**；删除未执行（条件不满足或无命中）则写入不执行。
- 只有写入组时，直接按写入组模式判断。
- 条件组未满足时整条规则对该图不执行。

触发与作用范围（已定）：

- 规则**由用户手动触发**，不自动运行。
- 只作用于触发时已有标注的有效全层合并视图（应用历史显式移除，不应用导出 WD 阈值）；条件仍只查 original/退化 wd。
- 结果以**快照**形式写入 `annotations`（`source=rule`，`type=tags`），内容为规则应用后的完整 tags，不是增量。
- 触发之后 WD / LLM 新产出的标注**不会被自动替换**；需要对新标注生效时，用户再次触发规则。
- 同时记 `operation_log`，可撤销（见 5.7）。
- 必须预览命中数与示例后执行，提交校验所有读取层的 current ID（包括缺失层）；变更则重新预览。rule/manual 显式移除与复制证据语义见 10.3。

### 8.5 并发、重试与超时

| 项 | 设计 |
|---|---|
| 并发上限 | 2（对外 API 请求并发） |
| 重试 | 退避重试；429 先切换令牌（见 4.2） |
| 单次 API 超时 | 默认 300s，来自 job 快照 |
| 限流与服务端错误 | 不触发图片压缩降档（见 8.6） |

### 8.6 视觉请求的图片处理

视觉请求对图片缩放为**内存 JPEG 副本**，**原图不改**，不落盘。

| 项 | 设计 |
|---|---|
| 默认档 | 2MP |
| 大文件 | 原图 ≥ 10MB 也缩放 |
| 超时降档 | 超时后降到 1.6MP / 1MP，JPEG 质量 88 / 84 |
| 不触发降档 | 限流（429）和服务端错误 |
| 溯源 | 实际使用的缩放档位记入 `annotations.params_json` |

默认档的 JPEG 质量 [待确认：未给定]；1.6MP 对应质量 88、1MP 对应质量 84 为按顺序对应的推断 [待确认]。

- 走画风 LoRA 线时**默认不开启**。

### 8.8 缓存与失效

执行结果缓存键 `annotations.cache_key` 由以下四项组合：

| 要素 | 说明 |
|---|---|
| 配置 | job 快照中的相关参数 |
| 模型 | 实际模型名 |
| Skill 内容哈希 | 运行时 Skill 文本哈希（见 docs/06） |
| 图片指纹 | `images.sha256` |

四项**任一变化即失效**，失效后「未覆盖」判定将该图视为未覆盖。旧结果不删，按分层规则保留为历史行。

## 9. NSFW 路由

分级结果**缓存在 `images` 表**的 `rating` / `rating_source` / `rating_verified` / `rated_at` 四个字段（决议：图片需要缓存，见 5.4）。路由每次执行前先读缓存，只在无缓存时才判定，避免同一张图反复调用分级模型。实际走的线路另记入对应 `annotations.params_json`（见 9.4）。

### 9.1 判定优先级

| 优先级 | 判定方式 | 写入 `rating_source` | 说明 |
|---|---|---|---|
| 0 | **读缓存** | — | `images.rating` 非空且 `rating_verified=1` 直接采用，不再往下判定 |
| 1 | 关键词词库匹配 | `keyword` | 产品层 NSFW 关键词表，格式 `tag<TAB>等级`；图片/提示词的 tag 命中即得出结论 |
| 2 | 本地检测器（**预留，本版不实现**） | `detector` | YOLO 类 NSFW 区域检测，超阈值即判 nsfw。本版该级不存在，判定直接跳到下一级；仅在结构上预留位置和 `rating_source` 取值 |
| 3 | 分级模型 | `model` | 用户可配置角色 `rating`；**手动指定时**才用它分析 |
| 4 | `nsfwfallback` 策略 | `fallback` | 用户可把策略指定为 nsfwfallback：所有不确定内容全部走 nsfw 线路 |
| 兜底 | 走普通处理 | 不写 | 以上都没配置，或都没结论时走普通线路，并在发给 LLM 的请求体里标注 `rating_verified: false` |

- 判定自上而下，前一项有结论即停止。
- 1、2、3 得出的结论**回写 `images`** 并置 `rating_verified=1`（2 本版不会出现）。
- 4 得出的结论也回写，但 `rating_verified=0`：它是策略兜底而非对图片内容的真实判定，所以不能让它永久钉住结果；配置改了之后「重新分级」会覆盖它。
- 检测器启用后的阈值、模型来源、`rating` 取值映射（检测器只能判 nsfw，不分四级）[待确认，见第 13 章]。
- 兜底分支不回写任何字段，下次仍走同一流程。
- 用户手改写 `rating_source=manual`、`rating_verified=1`，「重新分级」不覆盖。

### 9.2 两条线路

| 线路 | 提示词生产 | 视觉反推 |
|---|---|---|
| 普通 | `prompt` | `vision` |
| nsfw | `prompt_nsfw` | `vision_nsfw` |

nsfw 线路对应角色为空时：**跳过该 LLM 步骤，保留原值**（不报错，计入 `jobs.skipped_count`）。

### 9.3 `refused_nsfw` 短路

- 普通线路下，若请求带 `rating_verified: false`，LLM 发现明确 NSFW 内容时**立即短路返回** `refused_nsfw`，不做任何处理或净化改写（Skill 侧规则见 docs/06 R0）。
- 产品收到 `refused_nsfw` 后**回写 `images`**：`rating=questionable`、`rating_source=refusal`、`rating_verified=1`、`rated_at=now`。这是一条来自多模态模型的真实判定，必须落库，否则下次执行又会先撞一次普通线路、白付一次费用。
- 回写后改走 nsfw 线路重新请求；若 nsfw 角色为空，按 9.2 跳过该步骤、保留原值。
- 同一图片同一步骤至多重路由一次，避免循环。
- 这条与 docs/06 R0 的「把该图 rating 升为 `questionable`」已对齐，字段在 5.4 存在。

### 9.4 溯源记录

写入 `annotations.params_json` 的路由信息：

| 键 | 含义 |
|---|---|
| `route` | `normal` / `nsfw` |
| `route_reason` | `keyword` / `detector`（预留） / `rating_model` / `nsfwfallback` / `refused_nsfw` / `default` |
| `rating_verified` | 布尔 |

- 路由配置冻结在 job 快照；关键词表只存内容哈希，内容仍在产品层/当前执行内存。哈希纳入结果缓存键，变化使相关标注覆盖失效，但不自动清 images.rating；重新分级仍由用户触发。重启无法取得原哈希版本则暂停，要求恢复版本或新建 job。
- 降档 params 同时记录 requested/actual；实际档位进入 cache_key，覆盖检查枚举冻结策略允许的档位键，不用原档键冒充降档结果。

## 10. 导出机制

### 10.1 原则

- 导出方案存 `export_schemes`，可配置；默认方案为「图片 + 同名 txt」。
- 其余格式（如 kohya 目录结构）只做扩展规划，导出器抽成接口（见 12.3）。
- **最终 caption 在导出时组合**，不预先合并写回 `annotations`。
- 导出只读，不改 `images`、`annotations`。
- 导出后处理器链 `export_schemes.pipeline_json`：图片与 txt 写出后依次执行的处理器（规划「元数据抹除」「本地超分放大」）。**本版不实现**，默认空链，空链时行为与不存在该字段一致（见 12.4）。

### 10.2 默认方案 `image_txt`

| 步骤 | 规则 |
|---|---|
| 图片过滤 | 排除 `reject`；其余按方案 `filter_json`（如仅 `keep`，或 `keep` + `unreviewed`） |
| 图片输出 | 默认复制 `images/` 中的原图到 `exports/` 下方案目录，原图不改。v0.28.0 可显式选择同卷硬链接（必须空处理链），每次执行确认共享内容风险；修改硬链接导出图也会影响原图，失败不自动回退复制 |
| caption 组合 | 按 caption_config_json 取参与层 current tags 全部合并，应用有版本边界的显式移除、WD 阈值，再按优先级去重排序，见 10.3 |
| 触发词 | 取 `project.json.trigger_word`，固定排在 caption 第一位 |
| 画风部分 | 只取内容段，前挂触发词；**不含任何 `style_prompt` 内容** |
| 自然语言 | 默认关闭；开启后取 manual > llm > original 的最高非空 current nl，一段输出，不合并拼接 |
| 文件名 | 同名 txt，主干与图片一致 |
| 可选输出 | 配套 json（来自 `images.png_meta_json`）；统计报告 [待确认] |

### 10.3 caption 组合可配置项

| 配置 | 说明 |
|---|---|
| 参与层 tag_layers | 默认 original/wd/llm/manual/rule 全部，可配置子集；关闭某操作层也关闭其移除作用 |
| 层优先级 layer_priority | 默认 manual > rule > llm > wd > original；所有参与层合并，优先级只影响首次出现位置 |
| 合并策略 | 规范化键并集、显式移除的版本边界、WD 置信度过滤；不取最高单层 |
| tag_sort | 默认 layer_first 按层优先级及层内首次出现排序；v0.29.0 支持 prompt_pyramid 本地纯排序，内容按主体/动作表情/服装/构图/场景/光照分组，同类稳定；未知项稳定放末尾并报告。不增删改名，触发词恒第一 |
| wd_min_confidence | 默认 0.0，范围 [0,1]；conf=NULL 默认排除，可设 wd_null_confidence=include；快照内来自 WD 的复制证据同样过滤 |
| 受保护 tag / 黑名单 | 内容段混入画风词时剔除并记日志（沿用 docs/04 §2.2 blocklist 作为保险） [待确认] |
| 分隔符 | 逗号 + 空格 |

以上全部配置放既有 `export_schemes.caption_config_json`，不新增 params_json 列；默认仅导出 keep，自然语言关闭，pipeline=[]。prompt_pyramid 排序适配器由 F09 提供，不可用时明确报错，不静默替换策略。

合并键为 tag 小写、下划线转空格、去首尾空白；保留层内首次位置，导出写规范化 tag，不改原始 prompt。rule/manual 的 annotations.params_json.merge_meta 存 schema_version、tag_origins、removals：

- tag_origins 为每个规范化 tag 的原始证据列表 `{layer, annotation_id, conf}`；普通 original/wd/llm 用自身 annotation_id。快照复制已有 tag 保留原证据，只有用户显式新增/重新加入才用本次新版本 ID，防止旧内容被快照“刷新”为新产出。
- removals 为 `{tag, cutoff_annotation_id, removed_at}` 列表。每次实际删除记本次新 annotation_id；继承旧移除保留原边界，无关保存不刷新。created_at/removed_at 用于展示，annotation_id 的单写全序用于判先后，避免同一时间戳歧义。
- 仅 current 且参与的 rule/manual 提供移除；同 tag 取最大 cutoff。候选有通过 WD 阈值且 origin.annotation_id>cutoff 的证据才能保留；无移除则正常并集。手动全量编辑按读到的有效视图差集记删除，未触及 tag 不刷新证据。
- 示例：original#10 有 A，rule#20 把 A 换 B（A cutoff=20），导出 B；后来 wd#30 有 A，因 30>20，导出 B、A；再触发 rule#40 删除 A 才重新只剩 B。无关规则编辑不能刷新 A 的旧移除边界。
- rule 新快照携带累计有效移除及原证据；内容相同但 merge_meta 不同也是变更。撤销随 current 回退恢复整套元数据，已撤销行不参与合并。DAL 验证引用同图且存在，细节与测试见 F01 §7.4/§9。

### 10.4 导出前检查

- 触发词必填，且不得出现在任何 `style_prompt` 中；是否与 Danbooru 已有 tag 冲突，警告但允许强制通过（沿用 docs/04 §5 决议 8）。
- 导出时跳过 `reject` 与 `file_missing=1` 的图片。
- 有 `unreviewed` 图片且方案要求仅 `keep` 时，导出前提示数量。

### 10.5 导入方案（与导出对称）

导入读提示词的规则与导出写提示词的规则对称：同一套标准格式，一读一写。方案存 `import_schemes`（见 5.9），与 `export_schemes` 结构对称。

标准「同名 txt」格式（本版唯一实现的读写格式）：

| 位置 | 内容 |
|---|---|
| 第 1 行 | tags，逗号分隔，单行 |
| 空行 | 分隔符 |
| 空行之后 | 一段自然语言，可无 |

读取（`import_schemes.reader = txt_sidecar`）：

- 按图片文件名主干找同目录同名 `.txt`。
- 第 1 行作为 tags 段，空行之后的文本作为自然语言段；之后按 8.2 的解析规则落入 `annotations`（`source=original`）。
- 无空行、无第二段时，只有 tags 段，不产生 `nl` 记录。
- 找不到同名 txt：该图不写 `original` 层（8.4 的退化规则适用）。

写出（导出方案 `image_txt`）：

- 第 1 行写 tags（触发词排第一位），自然语言按方案选项追加到空行之后，与读取格式一致，导出结果可被本产品再次导入而不丢段。
- 若方案不带自然语言，则只有 1 行。

边界：

- 其它 reader（PNG 元数据、WebUI parameters、JSON sidecar 等）和其它 writer（kohya 目录结构等）均只预留（见 12.4）。
- 导入过程不修改原 txt；txt 的编码按 `params_json` 配置，默认严格 UTF-8（兼容 BOM）。v0.27.0 支持显式选择 `auto`：无 BOM 时先严格 UTF-8，失败才尝试严格 GBK；带 BOM 的非法 UTF-8 不回退。回退提示、实际编码和请求编码保存在原始标注参数中，预览与导入报告可查；不使用替换字符或宣称统计探测可靠。

## 11. 技术栈与进程结构

### 11.1 技术栈

| 部分 | 选型 |
|---|---|
| 后端 | FastAPI；绑 `127.0.0.1`，**启动时生成随机 token**，前端请求带 token |
| 前端 | React + Vite + TypeScript |
| 存储 | SQLite（`project.db`），WAL 模式 |
| 桌面外壳 | Tauri，**后期**再做 |
| 已否决 | Svelte、Gradio / Streamlit、Flutter |

### 11.2 进程结构

```
┌ 前端 (React + Vite + TS) ─────────────────────────┐
│ 项目管理 │ 数据集视图 │ 详情/审图 │ 数据源 │ 设置 │
└───────────────┬────────────────────────────────────┘
                │ HTTP, 127.0.0.1 + 随机 token
┌───────────────▼────────────────────────────────────┐
│ FastAPI 后端（单进程）                              │
│  项目服务 │ 数据源服务 │ 执行器/Job │ 导出服务      │
│  适配器：LLM 协议(插件) │ ImageBackend │ WD tagger   │
└───┬───────────────┬──────────────────┬─────────────┘
    │               │                  │
 项目目录         产品层配置          外部服务
 (project.db     (端点/角色/字典/    (LLM 端点、
  images/…)       secrets.json…)      NAI Launcher MCP)
```

### 11.3 安全要点

- 后端无登录体系，仅靠 127.0.0.1 绑定与随机 token 做访问控制；不得绑定 0.0.0.0。
- 本地 API 不返回密钥明文（见 4.3）。
- token 每次启动重新生成，不落盘 [待确认：前端如何获得 token，如启动参数传递或由外壳注入]。
- 本版一次只打开一个项目；项目目录进程间独占锁，切换先安全关闭当前项目，崩溃由操作系统释放锁。
